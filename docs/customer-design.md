# A-CUT Customer Mobile Design

- 최종 `/delivered` 화면은 흰 카드·라이트 배경·주황 다운로드 CTA를 사용한다. 격자와 모서리 장식, 고정 푸터를 제거하고 다운로드 장수·용량·기한을 첫 화면에서 제공한다. 다운로드 모달도 같은 라이트 팔레트를 상속한다. 완료는 수령 상태이며 기기 저장 완료를 뜻하지 않는다.

## 갤러리 리디자인 (2026-09-13)

이 절은 아래 기존 갤러리 배치 수치보다 우선한다. 셀렉·보정본 목록은 `--customer-gallery-max-width: 1440px`, PC 전환 768px, PC 헤더 높이 64px를 공유한다. 상세 뷰어는 다크를 유지한다.

- 셀렉 PC는 전체/선택됨, 유사컷, 별점·찜·품질·정렬·검색·처음/마지막 이동을 상시 노출한다. `.gld-inline-tools`는 가용 폭에 따라 그룹 단위로 줄바꿈한다. 적용 조건은 해제 가능한 칩으로 표시하고 실제 헤더 높이를 측정해 사진 첫 행이 가려지지 않게 한다.
- PC 셀렉 카드는 `/review`와 같은 `GRID_MIN_CELL = 180`의 정사각형과 4px 모서리를 사용한다. 1440px에서 약 190px의 7열이며, 별 다섯 개와 최대 참가자 컬러칩 다섯 개가 한 줄에서 겹치지 않는다. 가상 스크롤 행 높이도 정사각형 기준으로 계산한다. 모바일 2열은 가로 4:3과 다섯 별을 유지하며, 작은 모바일 3·4열은 `★ 4` 형태의 결과 요약을 표시하고 상세에서 수정한다. 모바일 축소 헤더는 현재 전체/선택됨 범위를 유지한다. 날짜는 본문과 같은 Pretendard를 사용하며, 도구 버튼은 테두리 없이 활성 배경으로 구분한다. D-day 공통 배지는 유지한다.
- 보정본은 모바일 기본 2열·3열 전환을 제공한다. 필터 순서는 전체/미검토/확정/재보정 요청이다. 미검토도 공통 Badge로 표시하며, 셀렉 카드와 같은 4px 모서리를 사용한다.
- 미검토가 남으면 하단 버튼으로 첫 미검토 상세에 진입한다. 전부 검토한 뒤에만 기존 최종 전달 확인창을 열며, 판단 결과가 있으나 제출 전이면 하단에 미전달 안내를 표시한다. 수령 모드에는 미검토 이동과 미전달 안내를 적용하지 않는다.
- 공통 제출 풋터의 모바일 375px 폭 제한을 제거하고 두 갤러리에 같은 진행선/버튼 배치를 적용한다.

## 1. 문서 역할과 Source of Truth

이 문서는 고객 모바일 UI를 Figma 기준으로 점진 이행하기 위한 Golden Reference다. 아직 적용하지 않은 화면은 proposal로, 코드와 브라우저에서 검증한 화면만 implemented/verified로 구분한다.

Source of Truth 우선순위:

1. 실제 동작과 인증·데이터 흐름은 현재 구현 코드
2. 적용 완료 화면의 브라우저 computed style과 동작 검증
3. Figma `#56108`, `#55882`, `#55883`, `#56109`의 geometry, typography, asset, 문구
4. 기존 `design-system.md`의 공통 접근성·상태 원칙

`design-system-light.md`는 Photographer Light App 전용이므로 고객 화면의 수치와 조합을 그 문서에 합치지 않는다.

## 3. Mobile frame contract

- 기준 프레임: `375 × 812px`.
- 앱 콘텐츠 최대 폭: `375px`; 모바일에서는 `width:100%`, PC 임시 대응은 중앙 정렬.
- 브라우저가 소유하는 iOS 상태바를 그리지 않는다. 상단은 `env(safe-area-inset-top)`으로 대응한다.
- 본문 좌우 여백 `24px`, 고정 action 좌우 여백 `20px`.
- CTA와 키패드는 `env(safe-area-inset-bottom)`을 포함한다.
- 의미 있는 touch target은 최소 44px. 숫자 키는 `60px` 높이를 기본으로 한다.

## 5. Shared components

### SystemLoadingScreen light variant

- `/c/[token]` 아래 고객 플로우는 `variant="light"`를 사용한다.
- 고객용 light variant는 시스템 로그·시계·격자·코너 장식을 사용하지 않는다.
- 흰 캔버스 중앙에 `48px` 주황색 brand mark, 짧은 한국어 안내와 `112×3px` indeterminate progress만 배치한다.
- `prefers-reduced-motion`에서는 mark/progress animation을 멈춘 정적 상태로 표시한다.
- 강제 새로고침에서도 root dark fallback이 먼저 보이지 않도록 `app/c/loading.tsx`가 token layout의 서버 준비 구간을, `app/c/[token]/loading.tsx`가 내부 page streaming 구간을 light variant로 감싼다.
- 루트·작가용 기본 dark variant는 유지한다.

### CustomerEntryShell

- 파일: `src/components/customer/CustomerEntryShell.tsx`.
- 기본 variant는 잘못된 링크용 375px white canvas를 관리하고, PIN은 auth variant로 모바일 전체 폭과 PC 최대 440px 인증 카드를 사용하며, responsive 초대 인트로 variant는 기기 viewport 전체 폭을 사용한다.
- `CustomerEntryHeader`는 Figma logo geometry와 safe area를 관리한다.
- 고객 진입 화면만 사용하며 갤러리·뷰어의 photo workspace chrome을 대체하지 않는다.
- `CustomerInviteIntro`가 이 shell 위에서 셀렉과 보정본 검토 인트로의 대표 사진·작가 정보·본문·CTA 영역을 공통 구성한다.
- 초대 인트로는 모바일 전체 폭을 사용하며 사진 높이는 `clamp(220px, 40dvh, 340px)`로 제한한다. 본문과 CTA는 콘텐츠 높이를 확보하고, 작은 화면이나 큰 글자에서는 문서 스크롤을 허용한다.
- PC는 사진/안내 양쪽 분할을 유지하며 대표 사진은 viewport 높이로 sticky 배치한다. 안내와 CTA를 하나의 그룹으로 묶는다.
- preparing도 공통 라이트 초대 레이아웃으로 표시한다. 선택 CTA 없이 준비 중임을 안내한다. selecting과 reviewing의 CTA 및 상태별 리다이렉트는 유지한다.
- 대표 사진은 URL 사전 로드가 끝날 때까지 light brand placeholder를 표시한다. 사전 로드에 성공한 URL만 실제 `<img>`에 연결하고 오류가 나면 placeholder를 유지해 브라우저의 깨진 이미지 아이콘을 노출하지 않는다.

## 6. PIN contract

- 숫자 1–9, reset, 0, backspace의 3×4 grid.
- reset은 전체 입력을 지우고, backspace는 마지막 한 자리를 지운다.
- 입력 위치는 SVG dot `16 × 16px`과 네 개의 입력 상자로 표시한다.
- 기존 회귀 동작을 보존하기 위해 네 번째 숫자 입력 시 자동 제출한다. 중복 확인 CTA는 제거하고 자동 확인 안내와 작가 문의 안내를 표시한다.
- 오답이면 네 칸을 비우고 line을 Error 색으로 바꾸며 `비밀번호가 올바르지 않습니다`를 표시한다.
- 1분 5회 제한, countdown, 네트워크 오류, 성공 후 full-page navigation은 기존 API 계약을 유지한다.
- 물리 키보드 숫자, Backspace, Escape(reset), Enter를 지원한다.

- 제목과 설명은 Figma 문구를 사용한다.

대표 사진은 `projects.cover_photo_id`를 우선 사용하고, 미지정 또는 사진 삭제 시 첫 사진으로 폴백한다. 고객 초대 인트로에서는 가로·세로 모두 중앙인 `object-position: 50% 50%`로 표시한다.
PC 셀렉 인트로는 대표 사진을 왼쪽 전체 높이로 확장하고, 오른쪽에 고객 인사말·선택 안내·마감일·Primary/Secondary CTA를 배치한다. 모바일의 정보 순서, Orange Accent, dark Primary/neutral Secondary 위계는 바꾸지 않는다.
마감일 앞에는 `lucide-react`의 `CalendarDays`를 `20px`, `stroke-width: 1.6`, Secondary 색상으로 표시한다.
작가명은 실제 이름이 있으면 `이름 작가`, 없으면 `담당 작가`로 표시해 접미사 중복을 막는다. D-day는 초대·갤러리·보정본 검토·원본 다운로드에서 모두 `customerDDay()`와 공통 `Badge(theme="customerLight")`를 사용한다. 3일 초과는 중립, 1~3일은 Warning, 당일과 초과는 Critical이며 초과 기한은 `D+N`으로 표시한다.
PC에서는 제목·설명·마감일·CTA를 하나의 그룹으로 보고 화면 중심보다 조금 위에 배치한다. 마감 초과는 `D+N` 대신 `N일 지남`으로 표시한다.
원본 다운로드 진입점은 투명 text action 대신 `#DDE1E4` 테두리와 `#F7F7F6` 배경의 secondary CTA로 표시해 클릭 가능성을 높이되, dark-fill Primary CTA보다 낮은 위계를 유지한다.

## 10. Gallery contract (`#55882`)

- 모바일 기본은 2열이며, 갤러리 좌우 `20px` 안쪽에서 2/3/4열을 각각 `10/8/6px` 간격으로 표시한다.
- 밀도는 "한 번에 몇 장을 보나"만 정한다. 2·3열은 사진 위에 별점/코멘트/색 메타를 얹고, 4열은 선택·유사컷 상태를 우선하는 image-only 밀도다. 파일명은 어느 밀도에도 없다(상세보기 전용).
- 모바일 툴바의 그리드 아이콘을 누르면 `2 → 3 → 4 → 2열` 순서로 전환한다. 아이콘은 현재 열 수를 도형으로 표시하고 스크린 리더에는 현재·다음 열 수를 안내한다. 전환 전 화면 중앙 사진을 앵커로 유지하며 선택한 밀도는 토큰별 `sessionStorage`에 저장한다.
- 유사컷 보기 CTA는 `SimilarityToggleButton`을 사용한다. 고객 모바일 툴바와 작가 모바일 원본 갤러리는 `compact`, 작가 PC 원본 갤러리는 `default` 크기를 사용하며 아이콘·문구·그룹 수·활성 색과 접근성 레이블은 동일한 컴포넌트가 관리한다.
- 탭을 닫으면 저장한 밀도가 사라지고 다음 세션은 기본 2열로 시작한다.
- 가상화는 밀도별 실제 카드 비율과 간격으로 행 높이를 다시 계산하고 `measure()`한다. 썸네일 URL·진행 중 요청·로드 완료 queue는 `[token]` 공통 레이아웃의 `CustomerImageCacheProvider`가 보유해 상세 화면을 다녀와도 유지한다. 최초 화면은 즉시 presign하고, 이후 빠른 스크롤만 debounce하며, 화면 근처 썸네일은 최대 12개를 동시에 로드한다. 필터/그룹 데이터 흐름은 변경하지 않는다.
- 상단은 `사진 셀렉`, `yy.MM.dd`, D-day, 전체/선택 수, 필터, 파일명 검색으로 구성한다. `전체/선택됨`은 scope dropdown, 필터 버튼은 bottom sheet를 각각 연다.
- 하단은 선택 수/필수 수, 6px progress, 56px CTA로 구성하며 safe-area inset을 포함한다. 완료 전에는 남은 장수를 안내하고 완료 시에만 확정 modal을 연다.
- 체크 UI의 시각 크기는 밀도에 따라 작아지지만 실제 버튼 영역은 `44px`로 유지한다.

### PC composition

> 2026-09-09 PC 검수: selecting 인트로·갤러리·상세 viewer를 Chromium `1024/1280/1440/1920px`에서 확인했다. 문서 가로 넘침은 없었으며 Intro/Gallery Light와 Viewer Dark 경계를 확인했다. Gallery fixture의 썸네일 presign 완결성, PIN/완료/보정 검토 전체 상태와 모바일은 이번 검수 완료 범위가 아니다. [검수 결과](desktop-design-audit-2026-09-09.md) 참고.

- 브레이크포인트는 `768px`(앱 전역 `MOBILE_MAX_W` 관례와 동일)이며, 768px 미만에서는 이 절이 적용되지 않고 위 모바일 계약을 그대로 따른다.
- 상단 헤더는 모바일 bottom sheet로 여닫던 필터·정렬·검색을 하나의 상시 노출 툴바로 구성한다: 브랜드 마크·프로젝트명·마감일/D-day(좌), 담당 작가·선택 수(우) 상단 행 + 전체/선택됨 scope 탭·별점 `≥N`·유사컷 묶어보기·흔들림/눈감음 토글(좌), 색상 다중 선택·필터 초기화·정렬·처음/마지막 이동·파일명 검색(우) 하단 필터 행. 기능 계약은 모바일과 동일하고 배치만 상시 노출로 바뀐다.
- 색상 토큰은 `design-system-light.md`(Photographer 전용)를 참조하지 않고, 이 문서 §4 Customer entry tokens를 `.customer-app-shell` 스코프 CSS 변수(`--customer-canvas`, `--customer-ink`, `--customer-ink-secondary`, `--customer-control`, `--customer-divider`)로 선언해 사용한다. Brand accent는 `src/app/globals.css`의 전역 `--accent: #ff4d00`을 그대로 재사용한다(2026-09-09 PC computed 확인). 작가 Light route의 `#ff5712`는 고객 shell에 적용되지 않는다.
- 그리드 컬럼 수는 밀도 선택 UI 없이 뷰포트 폭에 따라 자동 계산된다(최소 셀 `148px`, 간격 `12px`, `max-width: 1800px` 컨테이너). 핀치 밀도 시스템은 PC에서 개입하지 않는다.
- 결과 0건 empty state는 모바일과 동일한 문구·분기(필터 조건 없음 vs 선택한 사진 없음)를 라이트 톤으로 확대 배치한다.
- 하단 확정바는 모바일과 같은 라이트 톤(Control `#26282C` CTA, Brand accent 진행바)을 폭에 상관없이 유지하고, 폭만 헤더/그리드와 동일한 `max-width: 1800px` 컨테이너에 맞춘다.
- 상세보기(`/c/[token]/viewer/[photoId]`) PC 구성은 §11에서 별도로 다룬다 — 갤러리와 달리 라이트로 바꾸지 않고 다크 사진 워크스페이스 톤을 유지한다. 완료 목록의 PC 구성은 이번 범위 밖이며 기존 Dark Photo Workspace 구성을 그대로 유지한다(§12 참조). 여러 화면이 공유하는 하단 확정바(`SelectionConfirmFooter`) 컴포넌트는 갤러리에서만 opt-in 라이트 variant(`theme="customerLight"`)를 쓰고 기본값(다크)은 그대로라 다른 호출부의 기본 동작에 영향이 없다.

### Selection and filter states (`#55883`)

- `전체/선택됨` trigger는 별도의 scope dropdown을 열며 각각 전체 사진 수와 현재 선택 수를 표시한다. 별점·색상 조건과 독립적으로 동작한다.
- AI 유사컷 그룹이 있으면 모바일 toolbar의 필터 왼쪽에 `Layers + 유사컷 + 그룹 수` 보기 모드 버튼을 표시한다. OFF는 neutral outline, ON은 orange outline과 pale-orange background를 사용하며 필터 활성 개수에는 포함하지 않는다. 최초 1회 `비슷한 사진을 묶어서 볼 수 있어요` 안내를 표시하고 상태는 기존 `grouped=1` URL 계약으로 상세 화면까지 전달한다.
- 우측 `SlidersHorizontal` 버튼은 높이 `297px` 수준의 bottom sheet를 연다. 배경 dim을 누르거나 `Escape`를 누르면 닫힌다.
- 별점은 기존 필터 계약대로 선택한 점수 이상(`rating >= starFilter`)의 단일 조건이고, 색상(=참가자) 필터는 복수 선택 조건이다. 같은 옵션을 다시 누르면 해제된다.
- 색은 참가자 슬롯이므로(§11) 필터 섹션 제목은 `찜`이고, **프로젝트에서 실제로 쓰인 색만 노출**한다(안 쓰인 색은 눌러도 0장이라 감춘다). 라벨은 내 색이면 `내 찜`, 나머지는 `빨강 찜`처럼 색 이름을 붙인다. 아무도 찜하지 않았으면 `아직 찜한 사람이 없어요`를 표시한다. PC 툴바에서는 내 색 dot에 흰 링을 둘러 구분한다.
- 색을 **2개 이상** 고르면 `한 명이라도 찜`(OR, 기본)과 `모두 찜`(AND) 중 하나를 고를 수 있다. 색이 사람인 이상 "둘 중 누구라도 좋다고 한 사진"과 "둘 다 좋다고 한 사진"은 전혀 다른 질문이고, 후자가 합의된 컷을 추리는 실제 용도이기 때문이다.
  - 모드는 `GalleryFilterState.colorFilterMode`(`"any" | "all"`)에 담기고 URL `color_mode=all`로 직렬화된다. 색이 1개 이하면 두 모드의 결과가 같으므로 쿼리에 쓰지 않는다.
  - 필터링은 공유 `getFilteredPhotos`에서만 갈라지므로(`every` vs `some`) 뷰어의 이전/다음 목록도 자동으로 같은 조건을 따른다.
  - UI는 색이 2개 이상일 때만 나타난다 — PC 툴바는 색 dot 옆 `모두 찜` 토글 pill, 모바일은 필터 시트 `찜` 섹션의 2분할 라디오이며 적용 중이면 상단 칩 줄에 `모두 찜` 칩으로도 보여 한 번에 되돌릴 수 있다.
- **밀도(2·3·4열)는 "한 번에 몇 장을 보나"만 정한다 — 카드 구조나 기능을 바꾸지 않는다.**
  - 예전에는 2열만 다른 카드였다: 회색 액자(`#f1f3f6`) + 패딩 + **가로 1.46:1 사진** + 사진 아래 검은 파일명. 3·4열은 패딩 없는 타일에 파일명이 아예 없었다. 같은 화면에서 밀도만 바꿨는데 카드가 다른 컴포넌트로 보였고, 형제 화면(검토 목록 1.027:1, 잠금 갤러리 1:1)과도 어긋났다.
  - **모든 밀도에서 카드 = 사진 1:1**, 흰 배경 + `--customer-divider` 1px. 기본값 `var(--surface)`는 다크 토큰(`#15161a`)이라 라이트 갤러리에서 로딩 전/실패 시 검은 사각형이 뜬다.
  - 2열의 1.46:1은 **사진을 가장 크게 보는 밀도에서 가장 많이 잘리는** 구조였다(세로 사진은 위아래가 통째로 날아갔다).
  - **2열만 사진이 가로 4:3이다.** 1:1로 두면 한 장이 168px까지 커져 한 화면에 두 줄밖에 안 들어온다 — 2열은 "크게 보며 고르는" 밀도지 한 장을 감상하는 화면이 아니다. 대신 세로 사진은 위아래가 잘린다(원본 확인은 상세보기의 몫).
  - **§파일명 규칙 — 격자에는 파일명을 그리지 않는다. 파일명은 상세보기 한 곳에서만 말한다.** (고객 화면 전체에 적용: 셀렉 갤러리 · 검토 목록 · 잠금/결과 갤러리)
    - 고르는 동안, 훑어보는 동안 고객이 읽는 것은 사진이지 `IMG_8060.jpeg`가 아니다. 그런데 파일명은 화면·밀도마다 자리가 달랐다(2열=사진 밖 / 3열=사진 위 / 4열=숨김 / PC=사진 위 / 검토 목록=사진 위 / 잠금 갤러리=사진 아래). 같은 정보가 화면을 옮길 때마다 다른 컴포넌트처럼 보이는 것이 통일감을 해치는 원인이었다.
    - 파일명이 필요한 순간은 **작가에게 "이 사진"이라고 짚어 말할 때**다. 그건 한 장을 보고 있는 상세보기에서 일어나므로, 표기도 거기 한 곳에만 둔다(셀렉 뷰어 앱바/헤더 보조 줄 · 검토 상세 `.rvx-frame-name` · `LockedPhotoViewer` 헤더).
    - **되살리는 예외는 둘뿐이다.**
      1. **파일명 검색이 켜진 동안** — 그때는 파일명이 곧 작업의 대상이라, 안 보이면 무엇이 왜 걸렸는지 확인할 방법이 없다.
      2. **그 화면에서 상세보기를 열 수 없을 때** — 규칙은 "상세보기가 있다"는 전제 위에 선다. 열 수 없으면 격자가 이름이 나올 유일한 자리다. 잠금 갤러리의 검토 결과 카드(`PhotoCard` — `div`라 애초에 클릭 대상이 아니다)와 `canViewOriginals === false` 상태(`SimplePhotoCard`/`UnselectedPhotoCard`의 `onOpen` 없음, 모바일 격자의 `canOpenDetail` false)가 여기 해당한다.
    - ⚠️ 새 격자를 만들 때는 **상세보기가 있는지 먼저 확인한다.** 없는데 파일명을 빼면 고객이 재보정 요청한 사진을 작가와 이야기할 방법이 사라진다.
    - 셀렉 갤러리에서 예외 1을 거는 자리는 `filenameContextActive` → `GalleryPhotoCard`의 `showFilename`이다(예외 2는 해당 없음 — 이 격자는 늘 상세보기로 이어진다).
      - 자리는 **사진 위**다(사진 밖이 아니라). 사진 밖에 두면 카드 높이가 검색 상태에 따라 바뀌고 가상 스크롤 행 높이(`MOBILE_LAYOUT[n].info`)까지 함께 흔들린다 — 사진 위면 행 높이가 고정이다(실측: 검색 전후 모두 136px).
      - 4열에서는 켜도 감춘다 — 8px 글자가 뭉개지는 데다 그 밀도에는 스크림 그라데이션도 없어 사진에 그대로 묻힌다.
      - ⚠️ **파일명 정렬은 조건에 넣지 않는다.** `filename`이 기본 정렬값이라(`toSearchParams`가 이 값만 URL에서 생략한다) "정렬이 파일명"은 사용자가 고른 특별한 상태가 아니다 — 넣으면 사실상 항상 참이 되어 파일명을 걷어낸 의미가 사라진다(구현 중 실제로 24장 전부에 파일명이 뜨는 것으로 드러났다).
    - 파일명을 걷어내면서 **카드 상자(`.gl-card-shell`)도 함께 없앴다.** 상자는 사진과 파일명 줄을 한 덩어리로 묶으려고 둔 것이라 파일명이 사라지면 사진만 남는다. 그래서 선택 표시도 3·4열·검토 목록·잠금 갤러리와 같은 **사진 안쪽 주황 링**으로 돌아간다 — 2열만 상자 테두리로 알리면 밀도를 바꿀 때 선택 표시가 다른 것으로 바뀌어 보인다.
  - **별점·코멘트·색은 사진 안에 남는다.** 사진마다 붙는 판단 표시라 사진에서 떨어지면 어느 사진 것인지 한 번 더 짚어야 한다. 밀도가 바꾸는 것은 정보의 **자리**이지 정보의 **유무**가 아니다(4열만 예외 — 별 하나가 8px 밑이라 누를 수도 읽을 수도 없다).
  - 빈 별은 **사진 위 그라데이션에 얹힌다** — 어두운 회색으로 두면 사진에 묻혀 "별점을 줄 수 있다"는 것 자체가 보이지 않는다. `rgba(255,255,255,.72)` + `text-shadow`로 어떤 사진 위에서도 읽히게 한다.
  - **코멘트 표식은 중립 흰색이다.** 주황은 "선택/제출 + 별점"의 색이라(§색 규칙) 코멘트까지 주황이면 한 카드에 주황이 네 군데(선택 링·체크박스·별점·코멘트) 겹쳐 "골랐다"와 "코멘트가 있다"가 같은 무게로 읽힌다. 사진 위에 얹히므로 `drop-shadow`로 대비를 준다.
  - 코멘트 표식(13px)과 찜 dot(7px)은 나란히 서므로 **무게를 맞춘다** — 예전에는 14px 외곽선 아이콘 옆에 5px 채운 원이라 2.8배 차이가 났다.
  - **선택 표시는 모든 밀도에서 사진 안쪽 주황 링**(`PhotoThumbnailFrame active`)이다. 한때 2열만 카드 상자 테두리로 알렸는데(`inset 2px` 링과 체크박스가 겹쳐 주황이 두 겹이고, 링이 사진 가장자리를 2px 덮어 선택된 사진만 좁아 보이는 문제 때문), 상자 자체가 없어지면서 3·4열·검토 목록·잠금 갤러리와 같은 링으로 통일했다. 한 화면 안에서 밀도만 바꿨는데 선택 표시가 다른 것으로 바뀌는 쪽이 더 나쁘다.
  - **코멘트 표시는 밀도로 막지 않는다.** 예전에는 JS의 `density === 2` 조건과 CSS의 `.gl-comment-indicator { display: none }` **두 겹**으로 막혀 있어, 3열은 물론 **PC에서도 코멘트가 있는 사진을 알 수 없었다**(찜 색 dot은 보이는데 코멘트만 안 보여 더 헷갈렸다). 둘 다 걷어내야 실제로 보인다 — JS 조건만 풀면 DOM에는 있고 화면에는 없다. 4열은 오버레이 자체가 숨겨지므로 별도 조건이 필요 없다.
  - **별점·코멘트·색은 3열까지 유지한다**(`density <= 3`). 예전에는 2열에서만 보여, 3열로 바꾸면 별점을 보지도 주지도 못했다 — 밀도는 보기 방식이지 기능 스위치가 아니다. 4열은 별 하나가 8px 밑이라 그때만 감춘다. PC는 열 수가 3을 넘으므로 기존대로 hover 전에는 채워진 별만 보인다.
  - 별을 사진 위에 얹으면서 **빈 별 색을 흰색 계열(`rgba(255,255,255,.72)` + 그림자)로** 바꿨다. 기존 어두운 회색은 사진에 묻혀 "별점을 줄 수 있다"는 것 자체가 보이지 않았다.
  - 선택 테두리도 카드 = 사진이 되면서 밀도와 무관하게 같은 자리에 걸린다(예전 2열은 액자 안쪽 사진에만 걸렸다).
- 별점 아이콘은 카드·필터·상세 화면에서 동일하게 표시한다. 선택된 별만 `#FF4D00`으로 채우고, hover/touch preview는 `rgba(255, 77, 0, .7)`, 비선택 별은 기존 회색을 유지한다. 숫자와 옵션 배경에는 accent를 확장하지 않는다.
- 활성 조건은 filter 버튼의 orange count badge와 상단 29px removable chip으로 표시한다. chip을 누르면 해당 조건만 제거한다.
- `필터 초기화`는 별점·색상과 검색/품질 조건을 함께 초기화하지만 `전체/선택됨` scope는 유지한다.
- 결과가 0장이면 모바일 전용 empty state에서 `조건에 맞는 사진이 없어요`와 `검색 · 필터 지우기`를 표시한다. 선택 scope 자체가 비어 있으면 `선택한 사진이 없어요`와 `전체 사진 보기`를 표시한다.
- 선택 장수가 필수 장수와 정확히 같으면 하단 CTA는 `셀렉 확정하기`로 활성화되고 기존 confirm modal/API 흐름을 실행한다.
- 필수 장수를 채운 상태에서 미선택 사진을 누르면 선택 상태는 바꾸지 않는다. 갤러리·상세 화면은 `N장을 모두 선택했어요` snackbar와 `선택한 사진 보기` action을 표시하고, 선택 진행 영역을 짧게 orange pulse한다. 지원 브라우저에서는 `[18, 40, 18]ms` 거절 진동을 제공한다. action은 `선택됨` scope로 이동하며 snackbar는 5초 후 또는 닫기 버튼으로 사라진다.
- 모바일 헤더는 스크롤 방향에 따라 2단계로 동작한다. `72px` 아래에서 누적 `12px` 이상 아래로 스크롤하면 제목·마감일 행을 접어 `99px → 56px`로 축소하고, 선택 진행률(`Y / N`)과 필터·검색은 유지한다. 위로 `12px` 이상 이동하거나 최상단 `16px` 이내로 돌아오면 다시 펼친다.
- 헤더 축소/확장 시 본문 상단 여백과 가상화 `scrollMargin`을 함께 다시 계산하며, `prefers-reduced-motion` 환경에서는 전환 애니메이션을 제거한다.

## 11. Detail viewer contract (`#56109`)

- 사진이 화면의 대부분을 차지하도록 이미지 영역을 항상 풀블리드(`100dvh` 전체)로 깔고, 앱바·컨트롤 바·필름스트립은 별도 검은 띠가 아니라 사진 위/아래에 얹는 반투명 그라디언트 오버레이로 띄운다.
- **집중 보기는 고객 뷰어 3곳이 같은 컴포넌트를 쓴다**(`PhotoFocusOverlay`) — 셀렉 상세·보정본 검토·잠금 뷰어. 사진을 탭(모바일, 더블 탭 확대와 구분해 `320ms` 대기 후 확정)하거나 클릭(PC)하면 **검은 전체화면에 사진만** 남고, 다시 탭/클릭하거나 `ESC`로 닫는다.
  - 화면마다 자기 챙을 숨기는 방식으로 만들면 챙 구조가 다른 만큼 동작이 갈린다(실제로 예전에는 셀렉 뷰어 **모바일에만** 있었다). 사진 위에 검은 판을 덮는 방식이라 어떤 화면에 붙여도 결과가 같다.
  - 집중 중에도 좌우 스와이프·`← →`로 이동이 유지된다 — 훑어보는 것이 집중 보기의 목적이라 한 장만 보고 나가야 하면 쓸모가 준다. 확대 중에는 스와이프를 넘기지 않는다.
  - 단축키는 capture 단계에서 먼저 받아 아래 화면의 단축키(`Y`/`R`/별점 등)와 겹치지 않게 한다.
- 상단은 safe area 다음 `56px` 앱바 한 줄이다. 좌측 뒤로가기 + **`Y / N장 선택`(17px SemiBold, 선택 수만 Orange)** + 우측 **신원 칩**(`.fv-identity`)으로 구성한다.
  - **신원 칩이 앱바에 있는 이유**: 이름·색은 사진마다 바뀌는 값이 아니라 "이 세션에서 나는 누구"라는 세션 단위 정보다. 사진별 컨트롤 행에 두면 그 행의 절반을 상시 차지하면서 찜 토글과 한 덩어리로 묶여 "이름 vs 찜함" 택1로 오독됐다. 파일명·진행 바를 걷어낸 자리라 새 공간을 쓰지도 않는다. PC 헤더에도 같은 자리·같은 규칙으로 둔다.
  - **파일명은 카운터 아래 보조 줄**(`.fv-filename`, `11px 'Space Mono'` / `rgba(255,255,255,.62)`)로 둔다 — PC 헤더와 같은 구성이다(§PC composition).
    - 한때 앱바에서 완전히 걷어냈었다. `IMG_8090.jpeg`는 고객이 사진을 **고를 때** 쓰는 단서가 아닌데 상단 두 줄 중 하나를 상시 점유했기 때문이다. 그때는 갤러리 격자가 파일명을 보여주고 있었다.
    - 격자에서 파일명을 없애면서(§셀렉 갤러리 밀도) **앱 전체에 파일명이 남는 곳이 없어져** 되살렸다 — 작가에게 "이 사진"이라고 짚어 말할 때 쓰는 유일한 번호다. 대신 카운터와 경쟁하지 않도록 **위계를 낮춰** 보조 줄로 내렸다.
    - 두 줄을 합쳐도 35px라 앱바 `56px`(`--fv-appbar-h`)는 그대로다 — 이 값이 바뀌면 `--fv-top-chrome`을 타고 사진 크기까지 바뀐다.
  - **진행 바도 두지 않는다** — 바로 옆 카운터와 같은 사실을 한 번 더 말하는 데다, 미디어 뷰어에서 그 위치의 가로 바는 "전체 중 몇 번째 사진"(스크러버)으로 오독된다. 현재 위치는 하단의 얇은 위치 인디케이터가 알려준다.
- **별점·유사컷·코멘트·찜은 모두 하단 오버레이 한 행에 모은다**(`.fv-controls`, `60px` — 별점/유사컷·코멘트·찜 순서로 한 줄). 한 손 조작 시 엄지 도달 범위를 벗어나는 상단에 조작계를 두지 않기 위한 것이고, 동시에 상단 오버레이 그라디언트의 옅은 끝자락에 컨트롤이 놓여 사진 비율에 따라 가독성이 들쭉날쭉해지던 문제도 함께 해결한다. 하단 그라디언트는 컨트롤이 놓이는 구간까지 스크림이 남도록 `rgba(0,0,0,.9) → .78(45%) → .45(78%) → 투명` 단계로 깐다.
- 선택 액션은 사진(실제 렌더된 이미지 bounds 기준, 레터박스 여백이 아니라 사진 콘텐츠 **좌측 상단**)에 겹치는 체크박스로 제공하며, 모바일·PC가 같은 위치를 쓴다.
  - **좌측 "상단"인 이유**: 갤러리 그리드 카드의 체크박스와 같은 자리라 "선택 마커는 좌상단"이라는 관용구가 화면 사이에서 끊기지 않는다. 한때 엄지 도달성(모바일에서 y≈153 = 화면 상단 18%로 한 손 조작 영역 밖)을 근거로 하단으로 내렸으나, 위치 일관성을 우선하기로 하고 되돌렸다 — 도달성 손해는 감수하는 선택이다.
  - 다른 참가자의 찜 마크는 사진 **우측 상단**이라 같은 줄이지만 반대쪽 끝이고, 마크 컨테이너는 `pointer-events: none`이라 탭이 겹치지 않는다.
  - 다른 참가자의 찜 마크는 반대쪽(우측 상단)에 두어 서로 겹치지 않는다. 이 좌표는 이미지가 디코딩된 뒤에야 알 수 있으므로, **측정이 끝난 src에 대해서만 배지를 렌더링한다**(측정 전 컨테이너 모서리에 임시 배치하면 사진 이동 직후 배지가 화면 위쪽에서 제자리로 튀어 보인다). 탭 영역은 `44 × 44px`, 시각적 박스는 `34 × 34px`(둥근 모서리 `8px`)로 갤러리 그리드 카드 체크박스보다 크게 잡아 항상 눈에 띄게 한다. 미선택은 갤러리 카드 체크박스와 같은 **흰 채움**(`rgba(255,255,255,.92)`), 선택됨은 orange fill + white check로 표시하며, 두 상태 모두 테두리 바깥에 어두운 링(`box-shadow`)을 한 겹 더 둬서 밝은 사진 위에서도 묻히지 않게 한다. 선택 상태와 API 계약은 `SelectionContext`를 그대로 사용한다. 체크박스는 사진의 pinch/pan 제스처 영역 위에 있지만 자체 터치 이벤트를 전파 차단해 확대/이중탭 제스처, 그리고 탭-투-숨기기 토글과 충돌하지 않는다(체크박스를 눌러도 집중 모드로 전환되지 않는다). **집중 모드에서는 체크박스·참가자 마크·선택 테두리가 모두 함께 사라진다**(`showBadge={mobileChromeVisible}`) — 사진 위에 아무것도 남기지 않는 것이 집중 모드의 목적이다. 한때 "집중 모드에서도 선택 액션은 항상 노출"로 두었으나, 사진만 보고 싶을 때 배지가 남는 것이 목적과 어긋나 되돌렸다. 모바일에서 실제 선택/해제가 반영될 때는 지원 브라우저에 한해 `10ms` 진동 피드백을 제공하며, 진동 API 미지원·차단 환경에서는 시각적 상태 변경만 유지한다.
- **강조색 역할 분리**: 주황(`#ff4d00`)은 **선택**(작가에게 전달되는 결과물 — 사진 테두리·체크박스·상단 카운트)과 별점에만 쓴다. **찜은 그 참가자의 색**(초록/파랑 등)으로 칠한다 — 색이 곧 사람이라 의미가 맞고, 주황과 겹치면 "선택"과 구분이 되지 않기 때문이다. 코멘트 유무 같은 메타는 중립 흰색으로 표시한다.
  - **참가자 색 위의 글자색은 계산해서 정한다**(`getReadableInk`). 흰 글자는 노랑(`#f59e0b`) 위 2.15:1, 초록(`#22c55e`) 위 2.27:1로 WCAG AA(4.5:1)에 크게 미달한다. 상대 휘도를 재서 대비가 큰 쪽을 고르며, 현재 팔레트 5색은 모두 어두운 잉크(`#1a1a1a`)가 유리하다(4.32~8.52:1).
  - 참가자 색은 `--fv-my-color` / `--fv-my-ink` / `--fv-my-tint` / `--fv-my-line` CSS 변수로 내려보낸다. 틴트는 `color-mix()`가 아니라 **JS에서 hex → rgba로 계산**한다(`color-mix`는 iOS Safari 16.2+ 전용이라 미지원 브라우저에서 선언이 통째로 무효가 되어 "찜 켜짐"이 꺼짐과 똑같이 보인다).
- **다른 참가자의 찜 마크는 사진 우측 상단**에 얹는다(`MobileViewerPinchPhoto`의 `marks` prop, 체크박스와 같은 `imageBounds` 측정값 사용). 하단 컨트롤 행에 두면 폭 경쟁에서 잘려 반원만 남아 렌더링 오류처럼 보였고, "누가 이 사진을 찜했나"는 사진에 붙는 정보다.
- 하단 챙은 **컨트롤 행 하나(`.fv-controls`, 76px)**이고, 그 아래에 `14px + safe-area` 여백을 둔다(바가 화면 끝에 딱 붙으면 답답하다). 이 값은 `--fv-bottom-chrome` 계산에도 함께 들어가 사진 stage 정렬이 어긋나지 않는다. 위치 트랙(`20px`)을 그 행의 **윗변으로 흡수**하고 아래 `56px`에 알약 세 개를 둔다 — 별도 행으로 떨어져 있으면 위 컨트롤과 아무 관계 없는 요소로 읽혔다. 트랙의 탭/드래그 영역은 위쪽 `20px`이라 알약 타깃과 겹치지 않는다.
  - 유사컷 그룹을 펼치면 멤버를 골라야 해서 **필름스트립(`68px`)이 컨트롤 바 "위"에 추가 행으로 붙고**(아래에 붙이면 바가 화면 끝에서 밀려 올라가 위치가 흔들린다 — 위로 열리면 바는 그대로 있고 사진 쪽으로 펼쳐진다), 그동안 위치 트랙은 감춘다(필름스트립이 위치를 대신 알려주므로 두 지표가 경쟁하지 않는다). 컨트롤 행은 `56px`로 줄어든다. 높이 전환은 `.fv-mobile`의 `fv-group-expanded` modifier가 `--fv-controls-h`/`--fv-strip-h`를 덮어써서 만들고, stage의 기존 `top`/`bottom` transition을 그대로 탄다(집중 모드 전환과 같은 메커니즘).
  - **위치 인디케이터**(`.fv-position`)는 필름스트립이 하던 두 역할(위치 파악 + 점프) 중 위치 파악을 얇은 트랙 + 이동식 thumb 세그먼트로, 점프를 탭/드래그 seek(`seekToRatio`)로 대체한다. thumb 폭은 `max(100/전체장수, 6%)`, 위치는 스크롤바와 같은 수학(`(순번-1)/(전체-1) × (100-thumb폭)`)으로 계산해 첫 장은 왼쪽 끝, 마지막 장은 오른쪽 끝에 닿는다. 오른쪽에 `N/M` 텍스트를 곁들인다. `touch-action: none`으로 브라우저 기본 스크롤과 경합하지 않는다.
  - 썸네일 행이 필요 없어진 만큼 화면의 약 8%(36px)가 사진에 돌아간다.
  - **컨트롤은 알약 하나(`.fv-bar`) 안에 담고 내부 항목은 무테로 둔다.** 별점·유사컷·코멘트·찜을 각각 알약으로 감쌌더니 **둥근 1px 테두리가 4겹**으로 반복되고 찜 안쪽 dot까지 더해져 동심원이 됐다 — 껍데기는 바 하나만 갖는다(둥근 테두리 5개 → 1개). 내부 항목(`.fv-pill`)은 높이 `44px`·정렬만 공유하고 테두리·배경을 갖지 않는다.
  - 그 이전 단계에서는 별점(테두리 없는 글리프)·코멘트(반경 22px·2px 테두리)·찜(반경 999px·1px 테두리 + 내부 분할선)이 한 행에서 서로 다른 세 가지 디자인 규칙을 쓰고 있었다. 규칙을 통일하는 것과 껍데기를 반복하는 것은 다른 문제였다.
  - **찜 켜짐은 테두리가 아니라 내 색으로 "채운" 면**(`--fv-my-tint-strong`, alpha `.34`)으로 알린다. 바 안에서 테두리를 또 그리면 동심원이 되고, 안쪽 dot도 같은 이유로 없앴다 — 내 색이 무엇인지는 앱바 신원 칩이 상시 보여주므로 여기서 색을 또 보일 필요가 없다.
  - 유사컷 항목도 `44px`로 맞춘다(혼자 `23px`이라 통일했다던 시각 언어가 깨져 있었다). 펼침 상태는 주황이 아니라 옅은 흰 채움(`rgba(255,255,255,.14)`)으로 표시한다.
  - 별점은 탭 정확도를 위해 `28px` 폭 + `4px` 간격(피치 32px)을 유지한다. 폭을 아끼려 24px/간격 0(피치 24px)까지 줄였다가 인접 별 오탭이 늘어 되돌렸다 — 폭은 마크를 사진으로 옮기고 코멘트 미리보기를 없애서 확보한다.
- **레터박스와 사진 크기의 관계**: 세로 화면에서 사진은 가로(390px)가 먼저 꽉 차므로, 상·하 챙을 줄여도 **사진 자체는 커지지 않고 레터박스 여백만 줄어든다**(가로 4:3 → 390×293, 세로 3:4 → 390×520로 챙 높이와 무관하게 동일). 챙 축소의 이득은 "사진 확대"가 아니라 "죽은 여백 감소"로 이해할 것.
- 평가는 별점 5개와 찜 표시를 한 행에 배치한다. 별은 갤러리와 동일하게 선택 `#FF4D00`, hover/touch `rgba(255, 77, 0, .7)`, 미선택 회색 규칙을 적용한다.
- **색(`ColorTag`)은 의미 태그가 아니라 "참가자 슬롯"이다.** 고객 링크는 여러 사람(신랑·신부 등)이 함께 쓰는데 서버가 요청자를 구분하지 못하므로, 색을 사람 식별자로 재해석해 "누가 찜했는지"를 표현한다. 사진 태그의 `color`가 이미 배열이라 여러 사람의 찜이 한 사진에 공존한다.
  - **찜(개인) ≠ 선택(공동)**: 찜은 "나는 이거 좋아"라는 개인 표시, 좌측 상단 체크박스의 선택은 작가에게 전달되는 공동 확정 N장이다. 두 단계가 서로 다른 층위임을 UI에서 구분한다.
  - 컨트롤은 5색 토글이 아니라 **내 색 하나만 토글**하고, 다른 참가자의 찜은 읽기 전용 원으로 함께 보여준다. 남의 색을 대신 찍을 수 있으면 식별자로서 의미가 깨지므로 PC 키보드 단축키도 색별(`Q W E R T`)이 아니라 `F`(내 찜) 하나만 둔다.
  - **누가 참여 중인지**는 별도로 저장하지 않고 **사진 태그에서 실제로 쓰인 색을 역산**한다(`getUsedColors`). "이 기기가 그중 누구인지"만 `localStorage(ps:c-participant:v1:{token})`에 남긴다.
  - 첫 찜 시점에 "누구세요?" 시트(`ParticipantSheet`)를 띄워 색과 이니셜(1~2자)을 받는다. 이미 쓰이는 색은 `사용 중`으로 표시하되, 기기를 바꿨을 때 되찾을 수 있도록 선택 자체는 막지 않는다.
  - 찜은 **순수 토글 하나**다(`.fv-mark-toggle`). 한때 `[내 표시 | 찜]` 두 구획으로 나눠 왼쪽에서 신원을 고치게 했지만, 두 구획이 같은 톤으로 나란히 서면서 **"이름 vs 찜함" 중 택1하는 세그먼트 라디오로 읽혔다** — 참가자 색을 입히자 양쪽이 같은 색조가 되어 오히려 더 심해졌다. 신원 편집은 앱바 신원 칩으로 옮기고 여기는 토글만 남겼다.
  - 켜짐 상태의 틴트는 `background`가 아니라 **`inset box-shadow`로 얹는다** — `background`로 덮으면 `.fv-pill`의 어두운 바탕이 지워져 그 알약만 떠 보인다. 안쪽 dot은 테두리를 흰색으로 고정하고 채움만 참가자 색으로 바꿔(빈 링 → 채워진 점) 어떤 참가자 색에서도 경계가 살아남게 한다.
  - 시트를 연 이유는 `participantSheetIntent`로 구분한다 — `mark`(찜하려다 열림)일 때만 확정 후 그 찜을 이어서 적용하고, `edit`일 때는 사진 상태를 건드리지 않는다.
  - 색을 옮기면 지금까지의 찜은 옛 색에 남아 남의 것처럼 보인다. 1단계에서는 이관하지 않고 시트에서 경고만 띄운다(`색을 바꾸면 지금까지 찜한 표시는 이전 색(초록)에 그대로 남아요`).
  - 마크는 이름이 붙으면 원이 아니라 **알약으로 늘어난다**(`:empty`면 기존 원 유지). `신랑`/`신부`처럼 첫 글자가 같은 쌍이 흔해 한 글자로 줄이면 구분이 되지 않기 때문이다.
  - **이름이 없는 마크는 `?` + 점선 테두리로 "미등록"임을 드러낸다.** 색만 있고 이름이 없으면 "누군가 찜했다"는 정보 가치가 절반이라, 빈 원으로 얼버무리는 대신 명시적으로 표시한다. 다른 참가자에게 이름 입력을 대신 시킬 수는 없으므로(그 기기의 본인만 가능) 할 수 있는 선에서 상태를 정직하게 보여주는 선택이다.
  - **내 마크도 이름이 없으면 같은 점선 + `?`로 보인다** — 다른 사람 눈에 내가 어떻게 보이는지를 내 화면에도 그대로 비춰서, 탭하면 열리는 `내 표시 바꾸기` 진입점(`editMyIdentity`)으로 자연스럽게 이어지도록 한다. `aria-label`도 이름이 없을 때 "이름 등록하기 — 다른 참가자에게 색으로만 보여요"로 바뀐다.
  - **표시 이름(이니셜)만 서버에 공유 저장**한다 — `project_participants(project_id, color, nickname)` 테이블과 `/api/c/participants`(GET 명단 / POST 내 색 이름 upsert). 이름이 있으면 다른 참가자의 마크 안에도 그 글자가 찍히고, 갤러리 필터 라벨도 `빨강 찜` 대신 `민 찜`이 된다.
  - 이 테이블은 **표시용 라벨일 뿐 본인 확인 수단이 아니다**(링크를 공유한 사이라는 전제). 그래서 색 슬롯은 누구나 되찾을 수 있고, 시트에서 이미 이름이 있는 색을 고르면 그 이름을 미리 채워 되찾기를 돕는다.
  - 명단 조회는 실패해도 조용히 빈 명단으로 떨어진다(`fetchRoster`). 마이그레이션 적용 전이나 오프라인에서도 색만으로 기존과 동일하게 동작한다.
  - 색 팔레트는 `lib/gallery-filter.ts`의 `COLOR_OPTIONS` 하나만 쓴다 — 같은 사람이 갤러리와 뷰어에서 다른 색으로 보이면 안 되기 때문이다.
- 사진 비율이 화면과 달라 생기는 레터박스 여백은 **순검정(`#000`)**으로 둔다. 한때 같은 사진의 흐린 확대본(`blur(20px)`)으로 메웠으나, 사진 경계가 뭉개져 오히려 사진이 작아 보이고 어두운 사진에서는 상·하가 흙탕물 덩어리처럼 읽혀 제거했다. 검은 여백은 사진 모서리와 선택 테두리를 또렷하게 만든다.
- 실제 사진은 뷰포트 전체가 아니라 **챙 사이 "stage" 영역**(`top: 상단 챙 높이`, `bottom: 하단 챙 높이`)에 중앙 정렬한다. 컨트롤이 사진을 덮지 않게 하고, 사진과 하단 컨트롤이 시각적으로 분리돼 보이던 문제를 없애기 위한 것이다. 집중 모드로 챙을 숨기면 stage가 `inset: 0`으로 `220ms` 확장되며 사진이 자연스럽게 커진다(`prefers-reduced-motion`에서는 전환 없음). 챙 높이는 `.fv-mobile`의 `--fv-appbar-h`/`--fv-controls-h`/`--fv-strip-h` 변수로 정의하고 각 행과 stage offset이 모두 이 값을 참조한다 — 행 높이를 바꿔도 사진 정렬이 어긋나지 않게 하기 위한 단일 출처다.
- 사진이 챙 뒤로 깔리지 않으므로 하단 그라디언트는 흐린 배경 위에서 컨트롤이 읽힐 정도(`rgba(0,0,0,.82) → .5(55%) → 투명`)만 유지하고, 대비는 요소별로 보강한다: 별 `text-shadow: 0 1px 3px rgba(0,0,0,.85)`, 참가자 마크 `box-shadow`에 어두운 1px 링, 상단 카운터에도 동일한 그림자.
- 본 이미지는 presigned preview 캐시와 기존 pinch/double-tap 확대를 유지한다. 확대 중이 아닐 때 이미지 영역 수평 swipe로 이전·다음 사진을 탐색하며 별도의 화면 위 화살표는 표시하지 않는다.
- **위로 쓸어올리면 코멘트 시트가 열린다**(`openCommentEditor`, 하단 코멘트 아이콘과 동일 동작). 한때 아래로 당기기를 갤러리 복귀에 배정했으나, 브라우저 스크롤·키보드 닫기 동작과 헷갈려 제거했다 — 복귀는 좌상단 뒤로가기만 쓴다.
  - 판정은 한 방향이 다른 방향보다 `1.5`배 이상 커야 확정한다(대각선 스와이프는 어느 쪽도 아닌 것으로 무시), 수평은 `50px`, 수직은 `70px` 이상 이동해야 한다. 코멘트 시트가 열려 있는 동안은 `.fv-comment-sheet`가 터치 전파를 끊는다.
- **뷰어는 문서 스크롤을 잠근다**(`body`/`html` `overflow: hidden` + `overscroll-behavior: none`, 언마운트 시 복원). 코멘트 입력으로 키보드가 뜨면 브라우저가 문서를 위로 밀어 올리는데, 키보드가 닫힌 뒤에도 그 스크롤이 남아 하단에 검은 띠가 보였다. 시트가 닫히는 시점에 `window.scrollTo(0, 0)`을 한 번, iOS의 접힘 애니메이션을 감안해 `300ms` 뒤 한 번 더 맞춘다.
  - `.fv-mobile`에는 `height`를 주지 않는다 — `fixed inset-0`이 이미 레이아웃 뷰포트에 정확히 맞는데 `100dvh`를 겹치면 over-constrained가 되어 URL 바·키보드 전환마다 높이가 흔들린다.
- 유사컷 아이콘은 갤러리(`SimilarityToggleButton`)와 같은 **lucide `Layers`**를 쓴다(모바일 16px / PC 14px). 이전에는 모바일이 점선 사각형, PC가 `◧` 문자로 서로 달랐다.
- 유사컷 그룹이 있으면 이미지 아래 `40 × 23px` pill에 그룹 장수를 표시한다. 펼치면 하단 두 번째 행이 위치 인디케이터에서 필름스트립으로 바뀌며 해당 그룹 멤버만 원래 순서대로 보여주고, 닫으면 위치 인디케이터로 돌아가며 필터된 전체 탐색 목록 기준으로 복귀한다.
- 평가 영역은 padding이 높이를 늘리지 않도록 `box-sizing: border-box`가 적용된 고정 행(`76px` = 위치 트랙 `20px` + 알약 `56px`)이다. 별은 `22px` glyph/`28 × 42px` control이고, 찜은 `16px` dot + 라벨 알약이다.
- 필름스트립(유사컷 그룹을 펼쳤을 때만 등장)은 기본 썸네일 `42px`, 현재 사진 `48px`, 간격 `6px`로 표시한다. 현재 사진은 `2px` white border로 탐색 위치를 나타내고, 선택된 사진은 갤러리와 동일한 `18px` orange square의 white check로 구분해 현재 위치와 선택 상태가 같은 색으로 혼동되지 않게 한다. 양 끝에 인위적인 중앙 정렬 여백을 두지 않고 좌우 `20px` content padding을 사용해 첫 사진은 왼쪽, 마지막 사진은 오른쪽에 정렬하며 중간 사진만 가능한 범위에서 중앙에 배치한다. 썸네일을 탭하면 같은 상세 화면에서 전환한다.
- 선택 시 체크박스는 즉시 orange fill + white check로 바뀌고, 필름스트립 square check는 `200ms` pop-in, 실제 사진 경계는 `300ms` orange outline flash로 상태 변경을 피드백한다. 해제 시에는 check만 `140ms` fade/scale-out하고 사진 flash는 반복하지 않는다. `prefers-reduced-motion` 환경에서는 flash 애니메이션을 제거하고 상태 색상과 check만 즉시 변경한다.
- (모바일) 코멘트는 컨트롤 행의 아이콘 버튼이며, 내용이 있으면 **흰 점 하나**로 유무만 알린다. 잘린 3글자 미리보기(`태이 거…`)는 110px을 먹으면서 읽히지도 않아 없앴고, 내용은 시트에서 본다.
- (PC) 코멘트는 비어 있을 때 `48px` neutral field(말풍선 아이콘 + "코멘트를 남기세요..." — 검은 화면에서도 눈에 띄도록 테두리/텍스트를 밝은 회색으로 표시), 저장된 내용이 있을 때 높이를 `72px`로 고정한 orange outline 2줄 preview(아이콘 없이 텍스트만)다. 탭하면 키보드 위 white composer와 orange 저장 버튼을 열며, 기존 600ms 자동 저장·blur 저장·오류 상태 계약은 유지한다.
- 위 모바일 상세보기는 Figma `#56109` 원안대로 다크(`#000` 캔버스)를 유지한다 — "사진 집중 다크 워크스페이스" 의도가 있는 화면이라 갤러리(라이트)와 달리 모바일 톤 자체는 바꾸지 않았다.

### PC composition

- 브레이크포인트는 `768px`(갤러리·앱 전역 관례와 동일)이다.
- **PC도 모바일과 같은 다크 사진 워크스페이스 톤을 유지한다.** 갤러리는 라이트로 재스킨했지만, 상세보기는 "사진 집중" 화면이라 `design-system-light.md`가 말하는 Dark Photo Workspace 성격을 PC에서도 그대로 가져간다 — 라이트로 시도했다가 되돌린 이력이 있다(모바일과 톤이 어긋나 보인다는 판단).
- **PC는 사진(가변) + 우측 컨트롤 패널(320px) 2단 구성**이다(`.fs-stage-row` / `.fs-side`). 별점·찜·코멘트·유사컷을 사진 아래가 아니라 옆에 둔다.
  - **근거**: 세로 화면과 달리 PC에서 사진은 **세로에 갇힌다**(1667×927에서 사진이 스테이지 높이의 94%를 채움) — 반면 좌우로 76%가 빈 검정이었다. 즉 하단 챙 1px이 곧 사진 1px 손해인데 옮겨둘 빈 땅이 옆에 있었다. 컨트롤을 옆으로 보내 사진이 **399×532 → 496×661(높이 +24%, 면적 +54%)**로 커졌다.
  - 모바일과 반대 방향의 처방인 점에 주의: 모바일은 가로가 먼저 차서 챙을 줄여도 사진이 안 커졌다(§위 "레터박스와 사진 크기의 관계").
  - 유사컷을 펼치면 그룹 멤버 썸네일도 이 패널에 쌓인다(`.fs-side .fs-mini-strip`은 wrap, 썸네일 80×54) — 예전에는 하단에 썸네일 행이 두 겹으로 쌓여 사진을 그만큼 눌렀다.
  - 좁은 데스크톱(≤1200px)에서는 패널을 288px로 줄여 사진 폭을 보전한다.
- PC 헤더는 **`Y / N장 선택`을 최상위 위계**로 두고 파일명·프로젝트명을 그 아래 보조 텍스트로 내린다. 이전에는 파일명이 화면에서 가장 큰 글씨였고, 선택 수는 `Y >= N`이 되어 확정 푸터가 펼쳐지기 전까지 **어디에도 보이지 않았다** — 고객의 실제 목표가 PC에서만 안 보이는 상태였다(모바일 앱바는 상시 노출).
  - 헤더에는 위치를 표시하지 않는다. 위치는 **하단 필름스트립 윗변의 바**(`.fs-position`, 모바일 `.fv-position`과 같은 개념·같은 계산식)로 보여주고 오른쪽에 `N/M`을 붙인다 — 목록 위에 붙어 있어야 "이 목록 안에서 어디쯤"이 바로 읽힌다. 탭하면 그 지점의 사진으로 이동한다.
  - 유사컷 묶어보기가 켜지면 전체가 아니라 대표컷 수를 세므로 `대표컷` 접두어를 붙여 "41장 → 10장"으로 보이는 이유를 드러낸다.
- **"작가에게 전달" 확인 모달은 셀렉·검토가 같은 컴포넌트(`SelectionConfirmDialog`, 라이트)를 쓴다.** 둘 다 되돌릴 수 없는 마지막 관문이라 성격이 같다 — `title`·`description`·`confirmLabel`·`busyLabel`만 바꿔 끼우고 기본값은 셀렉 확정이다. 예전에는 검토 쪽이 다크 워크스페이스 톤(브래킷 장식 + Space Grotesk + 대문자 모노 버튼)의 별도 모달이라, 라이트 화면에서 전달을 누르면 갑자기 검은 창이 떴다. `/locked`의 확정 취소 모달도 같은 컴포넌트로 합쳤다.
- **잠금 갤러리 PC 구성은 검토 목록(`ReviewGalleryView`)의 뼈대를 따른다.** 같은 프로젝트의 같은 사진을 보여주는 화면이 셋(셀렉 갤러리·검토 목록·잠금 갤러리)인데 이 화면만 카드 언어가 달랐다(썸네일 4:3 vs 1:1, 파일명 11px JetBrains Mono vs 9px Space Mono, 고정 3/4/6/7열 vs `auto-fill`).
  - **머리는 한 줄**이다(`.lk-header`): `A` 마크 + 프로젝트명 / 상태 문구·읽기 전용 칩, 오른쪽에 카운트 + 원본 다운로드. 예전에는 브랜드바와 상태바가 따로 있어 머리가 두 겹이었고, 다운로드 버튼만 `max-w-md` 가운데 정렬이라 격자와 축이 어긋났다.
  - **격자는 `align-items: start`** 다. 기본(stretch)이면 코멘트 없는 확정 카드도 코멘트 있는 재보정 카드 높이에 맞춰 늘어나 아래가 비었다(실측 272px 고정 → 확정 203px / 재보정 266px).
  - **상태 배지에는 `self-start`가 필요하다.** `inline-flex`만으로는 flex column의 stretch에 늘어나 카드 안쪽 폭을 다 먹고(실측 176px = 카드 폭 전체), 읽기 전용 라벨이 누를 수 있는 버튼처럼 보인다(현재 51px).
  - 썸네일은 **1:1**이다(셀렉 갤러리·검토 목록과 같은 값). 예전 `4:3` + `cover`는 세로 인물 사진의 머리가 잘렸다.
  - **섹션이 말하는 것을 카드마다 반복하지 않는다.** `선택된 원본 10장` 묶음 안의 카드 10장에 주황 `선택` 칩을 전부 붙이면 같은 말이 열한 번이고 주황이 화면에 번진다. 카드 배지를 빼는 대신 **섹션 헤더를 sticky로** 만들어(머리 아래 `--lk-header-h`) 31장을 스크롤하는 동안에도 어느 묶음인지 잃지 않게 한다.
    - 함정: 스크롤 조상에 `overflow-y: auto`가 있으면 sticky가 **그 상자**를 기준으로 잡는데 실제로 스크롤되는 것은 window라 영영 달라붙지 않는다. `.lk-body`에서 `overflow`를 뺐다.
    - 비선택 사진은 `opacity .82`(hover 시 1)로만 눌러 구분한다 — "고르지 않은 것"이지 "못 보는 것"이 아니다.
  - **검토 결과 뷰도 같은 방식으로 묶는다: `재보정 요청` → `확정` → `검토 대기` 순.** 재보정이 **위**다 — 작가가 손대야 할 것이 먼저고, 확정 8장을 지나 스크롤해야 재보정 2장이 나오면 정작 할 일이 묻힌다.
  - 카드 배지는 **사진 위 오른쪽 위**에 얹고, 값은 전 페이지(검토 목록 `.rgv-card-pill`)와 똑같다: 흰 배경 + 색 테두리·글자, `999px`, `700 10px/1.5`, `top/right: 8px`. 같은 결과를 두 화면에서 보는데 모양이 다르면 같은 것으로 읽히지 않는다.
    - 셀렉 결과 뷰에서는 섹션이 이미 가르므로 배지를 뺐지만, 검토 결과는 배지 스타일 자체가 전 화면과 이어지는 신호라 섹션과 함께 남긴다.
  - **셀렉 때 남긴 코멘트도 카드에 보여준다.** 모바일 뷰는 보여주고 있었는데 PC 카드는 `comment`를 전달조차 받지 않아 비어 있었다. 재보정 코멘트와 같은 박스를 쓰되 **톤은 가른다**: 재보정은 앰버(작가가 처리해야 할 요청), 셀렉 코멘트는 중립 회색(고객의 메모). 없을 때는 자리를 만들지 않는다 — 격자에 "코멘트 없음" 빈 상자를 10칸 만들면 그게 잡음이다.
  - **풋터는 되돌릴 수 있을 때(`confirmed`)만 둔다.** 예전에는 그 외 상태에서도 남아 머리의 상태 문구를 **글자 그대로 한 번 더** 적었다("작가가 재보정을 진행 중입니다"가 위아래에 동일). 한 줄을 차지하면서 아무것도 더하지 않았다.
- **잠금 갤러리(`/c/[token]/locked`)는 PC도 라이트다.** 모바일 뷰는 원래 라이트였는데 PC 뷰만 다크로 남아, 같은 링크를 노트북에서 열면 갑자기 검은 화면이 나왔다(격자/목록은 라이트라는 규칙과도 어긋났다).
  - 검토 결과 배지는 검토 목록 카드와 **같은 값**을 쓴다: 흰 배경 + 색 테두리·글자, 확정 `#12833f` / 재보정 `#b26a00`. 다크용 반투명 틴트(`emerald-500/10` 등)를 라이트에 그대로 쓰면 거의 보이지 않는다.
  - **파일명은 §파일명 규칙을 따르되, 이 화면은 예외 2가 실제로 걸리는 유일한 곳이다.**
    - `PhotoCard`(검토 결과 — 재보정/확정/검토 대기 섹션)는 `div`라 **애초에 열 수 없다.** 여기서 파일명을 빼면 재보정 요청한 사진을 작가와 이야기할 이름이 앱 어디에도 남지 않는다 — 그래서 이 카드에만 파일명이 남는다.
    - `SimplePhotoCard`/`UnselectedPhotoCard`는 `onOpen`이 있을 때만(= `canViewOriginals`) 파일명을 감춘다. 모바일 격자는 `canOpenDetail`로 같은 판단을 받고, 거기에 더해 **검색 중**이면 항상 보여준다(이 화면에는 모바일 전용 파일명 검색이 있다 — PC에는 없다).
    - 실측: 상세보기가 열리는 프로젝트 → 카드 10장 중 파일명 0개(상세에서 1개), 열리지 않는 검토 결과 → 10장 모두 파일명 표시.
  - `CustomerFooter`에도 `CustomerHeader`와 같은 opt-in `theme="customerLight"`를 추가했다(기본값 다크는 그대로라 다른 호출부는 영향 없음).
  - **원본 다운로드는 머리 아래 sub 헤더 띠**(`OriginalDownloadEntry variant="subheader"`)다 — 모바일 `.locked-mobile-status`와 같은 자리·같은 주황 틴트(`rgba(255,77,0,.06)`). 기한이 있는 안내라 버튼만 두면 "언제까지"를 알 수 없어, **만료일과 남은 일수를 같은 줄**에 둔다(`2026.10.01까지 · 21일 남음`). 3일 이내·당일·만료는 주황으로 표시한다 — 날짜만 보여주면 급한지를 고객이 스스로 계산해야 한다.
    - 밴드는 "설명 + 버튼" 한 줄이라 **줄 전체를 컴포넌트가 그린다**. 만료일은 이 컴포넌트만 아는 값이라(`info.expiresAt`) 바깥에서 조립하려면 상태를 새어 보내야 하고, 아카이브가 없는 프로젝트에서는 컴포넌트가 스스로 아무것도 렌더하지 않아 띠도 함께 사라진다.
    - 함정: `variant="inline"`은 **다크 전용**(글자색 `var(--foreground)` = 흰색)이라 라이트에서 글자가 사라진다.
- **고객 라이트 화면은 `body` 바탕까지 흰색으로 바꾼다**(`useCustomerLightCanvas`). 고객 셸과 전역 `body`는 Dark Photo Workspace 팔레트(`--background` `#0a0b0d`)를 쓰고 라이트 화면은 그 위에 자기 흰 판을 덮는 구조라, **자기 판이 못 덮는 순간마다 검은 바탕이 드러났다**: 모바일에서 스크롤을 끝까지 당길 때의 러버밴드, 주소창이 접혔다 펴지며 `100dvh`가 실제 보이는 높이보다 잠깐 작아질 때. 드러나는 것이 페이지가 아니라 `body`라 페이지 안쪽을 아무리 칠해도 막을 수 없다. 화면을 떠나면 원래 값으로 되돌리므로 다크 화면(셀렉 뷰어·검토 상세)은 그대로 어둡다.
  - 안쪽 스크롤러를 쓰는 화면(검토 목록 `.rgv-scroll`)은 `overscroll-behavior: contain`도 함께 건다 — 러버밴드가 문서로 번지는 것 자체를 막는다.

- **보정본 검토 목록(`/c/[token]/review`)은 모바일·PC가 같은 컴포넌트(`ReviewGalleryView`)를 쓴다.** 예전에는 PC만 첫 사진(`photos[0]`)으로 자동 이동시켰는데, 상세의 닫기·`Esc`가 이 경로로 돌아오는 탓에 **PC에서는 뷰어를 닫을 수 없고 늘 1번 사진으로 튕겼다**(새로고침도 마찬가지). 셀렉이 `목록 → 상세`인 것과도 어긋났고, 제출 직전에 어느 장이 미검토인지 훑어볼 수단이 PC에만 없었다.
  - **머리와 카드는 셀렉 갤러리와 같은 뼈대를 쓴다** — 같은 고객이 같은 링크 안에서 오가는 두 목록인데 파일명 표기도 제목 표기도 서로 달랐다.
    - 머리: `A` 홈 마크 + 이름 + 마감일(`yy.MM.dd` + D-day 배지, 갤러리와 같은 계산·같은 톤) / 오른쪽에 `검토 N / M`(갤러리의 `선택 Y / N` 자리). 제목은 갤러리와 같이 **모바일은 화면 이름(`보정본 검토`), PC는 프로젝트명**이다 — 마크업은 한 벌로 두고 CSS로 가른다.
    - 카드: **파일명을 그리지 않는다** — 셀렉 갤러리와 같은 규칙이다. 훑어보는 목록에서 읽는 것은 사진과 판단 상태(`.rgv-card-pill`)이지 `IMG_8060.jpeg`가 아니고, 이름은 검토 상세에서 말한다. 카드 이름은 `aria-label`에 남아 스크린리더에는 그대로 읽힌다.
      - 카드 아래 그라데이션(`.rgv-card-overlay`)도 함께 걷어냈다 — 그것은 파일명을 읽히게 하려고 깐 스크림이고, 남은 판단 알약은 흰 배경을 가진 우측 상단이라 스크림이 필요 없다.
      - 비율(`106.333 / 103.479`)·격자 여백(20px)은 갤러리 3열(`.gl-density-3`)과 같은 값을 유지한다.
    - 확정/재보정 배지는 갤러리에 짝이 없는 이 화면만의 정보라, 갤러리 체크박스와 같은 위쪽 자리에 둔다.
  - 격자는 모바일 3열 고정, `901px` 이상에서 `repeat(auto-fill, minmax(180px, 1fr))` + 컨테이너 최대 폭 `1280px`(초광폭에서 한 줄이 끝없이 늘어지지 않게).
  - **`확정 N · 재보정 N · 미검토 N`은 읽는 숫자가 아니라 필터다**(`.rgv-tab`, `전체 / 확정 / 재보정 / 미검토`). 숫자만 보여주면 "재보정 1장이 어느 것인지"를 알려면 격자를 눈으로 훑어야 하고, 30장이 넘으면 그게 불가능해진다. 필터는 **보이는 것만 줄이고 풋터의 제출 조건(전체 검토 여부)에는 관여하지 않는다.**
    - 문법(무테 버튼 + 활성 밑줄)은 셀렉 갤러리 데스크톱 헤더의 `전체 사진 / 선택됨`(`.gld-tab`)과 같다 — 같은 고객이 오가는 두 목록이라 "격자를 좁히는 장치"가 서로 다른 모양이면 안 된다.
    - 다만 활성 색은 주황 하나가 아니라 **각 상태의 색**(확정 `#12833f` / 재보정 `#b26a00`)이다. 카드 배지와 같은 색이라야 탭과 결과가 같은 것으로 읽힌다. 상태색이 없는 `전체`·`미검토`만 주황으로 돌아간다.
    - 0장짜리 필터는 **누르지 못하게 한다**(숫자는 그대로 보여준다) — 누르면 빈 화면만 나온다.
    - 마지막 한 장을 판단하면 그 필터가 비어 버린다(`미검토`만 보다가 마지막 장을 확정). 이때는 **렌더 시점에 계산해서 전체로 되돌린다**(`activeFilter`) — effect로 되돌리면 빈 화면이 한 프레임 먼저 그려지고, effect 안의 `setState`는 연쇄 렌더를 부른다(lint가 막는다).
    - 필터를 걸어도 **사진의 대체 이름은 바뀌지 않아야 한다** — 걸러진 목록의 순번으로 이름을 만들면 `#3`이 필터에 따라 다른 사진을 가리킨다(`originalIndexById`).
  - **재보정을 요청할 수 없는 상태에서는 판단 단계를 걷어낸다(수령 모드).** 판별식은 `isReceiptMode` — 남은 재보정(`maxRevisionCount - revisionRound`)이 0인가, 하나뿐이다.
    - **왜**: 답이 `확정` 하나뿐인데 사진마다 확정을 누르게 하면, 정해진 질문을 N번 되풀이시키는 것이다. 선택지가 하나인 선택은 선택이 아니다.
    - ⚠️ **판별식을 `maxRevisionCount === 0`으로 쓰면 안 된다.** 그건 "재보정이 **없는 상품**"이라는 뜻이고, 남은 횟수가 0이 되는 여러 경로 중 하나일 뿐이다. 실제로 마지막 라운드(`reviewing_v2`에서 재보정을 이미 쓴 경우)는 똑같이 재보정이 불가능한데도 판단 화면으로 떨어져, 고객이 매 장 확정을 눌러야만 전달 버튼이 열렸다.
    - 수령 모드에서 바뀌는 것: 상태 필터 → **없는 이유를 적은 안내**(`.rgv-receipt-note`), 머리 `검토 0 / N` → `보정본 N장`(채울 진행이 없는데 0/N을 띄우면 할 일이 남은 것으로 읽힌다), 풋터 → 진행바 없이 **처음부터 열린 `수령 완료`**, 확인 모달 문구도 수령 쪽으로. 제출 페이로드는 전 사진 `approved` + 코멘트 `null`이다.
    - **없는 기능은 회색 버튼이 아니라 문장으로 말한다.** 예전에는 재보정 버튼이 비활성 + `title` 툴팁(`남은 재보정 횟수가 없습니다`)뿐이었는데, **툴팁은 터치 기기에서 뜨지 않아** 모바일 고객은 이유를 볼 방법이 아예 없었다.
    - 상세(`review/[photoId]`)도 같은 판별식을 쓴다: 판단 패널(`.rvx-panel`)을 **렌더하지 않고**(감추기만 하면 빈 상자가 사진을 계속 밀어낸다) 그 폭·높이를 사진에 돌려주며, `Y`/`R` 단축키도 끈다 — 화면에 없는 동작이 키보드로만 일어나면 안 된다. 앱바 요약은 분류 숫자 대신 `이번이 마지막 보정본이에요`.
    - ⚠️ 미결: `재보정 0회 상품`(`maxRevisionCount === 0` + `reviewing_v1`)은 아직 별도 화면 `DeliveryReceiptView`가 맡는다. 같은 상황을 두 화면이 나눠 갖고 있는 셈이라, 수령 모드가 검증되면 그쪽을 흡수해 화면을 하나로 줄일 수 있다.
  - **풋터(`작가에게 전달`)는 셀렉 확정과 같은 컴포넌트·같은 색이다.** 검정(`--customer-control` `#26282c`)은 고객 라이트 화면 CTA의 색이고, 셀렉 갤러리의 `사진 N장 셀렉하기`도 같은 값을 쓴다. 주황은 **진행바**(`#ff4d00`)가 가져간다 — 버튼까지 주황이면 하단 한 줄에 주황이 두 겹이 된다.
  - 진입은 **썸네일을 누르는 것**뿐이다. 한때 상단에 `검토 시작`/`이어서 검토` 버튼을 뒀는데, 격자가 곧 진입점인 화면에서 버튼이 따로 있으면 "어디를 눌러야 하나"를 한 번 더 고르게 만든다(셀렉 갤러리에도 그런 버튼은 없다).
  - 제출 확인 모달은 모바일에서 바텀시트, `901px` 이상에서 화면 중앙이다.
- **판단 패널은 현재 상태 → 판단 → 필요한 사유 순으로 위에서 아래로 읽는다.** 사진 검토 상태를 먼저 보여주고, 재보정을 선택한 경우에만 사유 입력을 펼친다. 단축키 도움말은 패널 바닥에 붙여 판단 흐름과 분리한다.
  - 좁은 화면(≤767px)은 패널을 사진 아래의 짧은 띠로 전환한다. 상태와 판단 버튼은 한눈에 보이고, 설명 문장은 감춰 사진 높이를 보전한다.
- **검토 판단 패널의 위계는 `확정(primary) → 재보정(보조 액션) → 사유 입력 → 단축키` 순이고, 원본 비교는 패널이 아니라 사진 위에 둔다.**
  - **확정과 재보정은 한 줄에 나란히 둔다**(모바일·PC 같은 모양 — 마크업도 CSS도 한 벌). 세로로 쌓으면 104px을 쓰는데 한 줄이면 56px이고, "둘 중 하나"라는 관계가 모양으로 읽힌다.
  - 크기는 실제 사용 비율을 따른다(30장 중 재보정은 두어 장): **확정은 채워진 56px primary로 남는 폭을 다 갖고, 재보정은 40px 무테 보조 액션**(`.rvx-quiet`)으로 글자만큼만 쓴다. 예전에는 둘이 같은 56px 버튼이라 "똑같은 덩어리 두 개"로 읽혔다.
    - 한 줄로 묶을 때의 함정은 **라벨 길이가 위계를 뒤집는 것**이다("재보정 요청"이 "확정"보다 길다). 그래서 보조 버튼은 `max-width: 46%`로 묶고, 키 힌트(`R`)는 넣지 않으며(패널 아래 단축키 줄이 알려 준다), 패널이 288px로 좁아지는 `768~1200px` 구간에서는 라벨에서 "요청"을 덜어 낸다(`.rvx-quiet-more`).
  - **누르기 전에는 색을 입히지 않는다** — 초록은 "확정됨" 결과의 몫이라 미리 쓰면 이미 판단한 것으로 오인된다(누른 뒤에만 초록/앰버).
  - **판단이 끝나면 접는다.** 판단한 사진에 필요한 건 큰 버튼 두 개가 아니라 "무엇으로 정했는지"(상태 칩, 누르면 판단 취소)와 "바꾸는 길"(`재보정으로 바꾸기` / `확정으로 바꾸기`) 하나씩이다. 확정한 사진에서는 재보정 사유 칸도 함께 접는다(`.rvx-comment-block-off`) — 미판단일 때 계속 보여주는 이유는 "재보정을 고르면 사유를 적어야 한다"를 **고르기 전에** 알리기 위해서이지, 확정한 사진에 필요해서가 아니다. PC에서 사진이 `968×646 → 1043×696`으로 커진다.
  - **판단 결과는 사진 위에 겹치지 않는다.** 상시 회차·확정·재보정 pill을 제거하고, 상태는 판단과 같은 우측 패널 첫 행(`.rvx-panel-status`)에 중립 원형 아이콘과 문장으로 표시한다. 사진은 색과 디테일을 판단하는 대상이므로 좌측 상단을 UI가 가리지 않는다. 필름스트립의 작은 원형 아이콘은 전체 진행을 훑는 용도로 유지한다.
  - **앱바 제목 자리는 프로젝트명이 아니라 파일명 + 보정 회차**(`.rvx-fileline`)다. 한 장을 보고 있는 화면에서 "어느 프로젝트인가"는 이미 아는 사실이고, 정작 필요한 "어느 사진·어느 회차인가"를 사진 밖 한 줄에서 확인한다. 원본을 누르는 동안 회차 텍스트만 `원본`으로 바뀐다.
    - 한때 **사진 좌상단 회차 라벨 옆**에 뒀는데, 그 자리는 "지금 보고 있는 것"(원본/V1/V2)과 "판단 결과"(확정/재보정)가 서는 곳이다. 성격이 다른 셋이 좁은 모서리에 나란히 서자 파일명은 잘리고 나머지 둘도 읽기 나빠졌다. **앱바에 자리가 있는데 사진을 덮을 이유가 없다.**
    - 무게는 한 단계 낮춘다(`500 / 14px`, 프로젝트명은 `600 / 15px`였다) — 제목 자리에 있지만 읽는 이름이 아니라 **식별자**다.
    - ⚠️ 여기만 `Space Mono`가 아니라 `Pretendard`다. 이 자리는 14px로 크고 한글 파일명(`다혜태희1781.jpg`)이 흔한데, Space Mono에는 한글 글립이 없어 **한 문자열 안에서 두 서체의 자폭이 섞여 깨져 보인다**. 9~11px로 작게 쓰는 다른 화면에서는 덜 드러난다.
  - 단조로움을 더는 디테일: 확정 버튼에 아주 옅은 위→아래 그라데이션, 아이콘 크기 위계(확정 20px / 재보정 16px), 판단 순간 아이콘 한 번 튀기(`rvx-pop`, 180ms — 색만 바뀌면 바뀐 줄 모른다), PC 한정 `Y`/`R` 키 힌트(`.rvx-key`, 모바일에서는 물리 키가 없어 감춘다).
  - **원본 비교(`꾹 눌러 원본`)는 사진 무대(`.rvx-frame`) 하단 중앙에 얹은 pill**이다. 비교 대상이 사진이니 버튼도 사진에 붙는다 — 패널 맨 아래에 있을 때는 원본을 확인하는 내내 시선이 사진과 패널을 왕복했다.
    - 가로 사진은 레터박스 검은 여백에 얹혀 **사진을 전혀 가리지 않고**(모바일 390px 기준), 세로 사진·PC처럼 사진이 세로로 꽉 찬 경우에만 아래 끝에 걸친다. 누르고 있는 동안은 원본을 보는 중이라 그 영역의 판단이 가려질 일도 적다.
    - `img`의 형제로 두어 이 버튼을 눌러도 사진의 집중 보기(`PhotoFocusOverlay`)가 열리지 않는다.
    - 모바일에서는 별도 비교 버튼을 숨기고 사진 자체를 300ms 누르는 동안 원본을 표시한다. 손가락이 10px 이상 움직이면 비교를 취소해 좌우 스와이프와 충돌하지 않는다. 원본 이미지는 미리 마운트·decode한 뒤 opacity만 140ms로 바꾸므로 전환 중 빈 프레임이 생기지 않는다.
    - 사진을 클릭해 검은 집중 보기로 확대한 뒤에도 같은 300ms 길게 누르기와 원본 레이어를 유지한다. 길게 누른 뒤 손을 떼는 동작은 집중 보기를 닫는 단일 탭으로 처리하지 않는다.
  - 비교가 사진으로 빠지면서 모바일 패널 한 줄은 통째로 판단 버튼 몫이 된다(확정/재보정이 화면 폭을 반씩).
- **"사유를 적어주세요" 경고는 재보정을 고른 즉시가 아니라 빈 칸을 떠났을 때 띄운다.** 고른 시점에는 라벨의 `필수` 칩만 보이고, 빈 채로 blur하면 안내 문장을 보여준다. 끝내 안 적으면 하단 진행 영역이 `재보정 사유 N개 필요`와 `사유 확인` 버튼으로 해당 사진에 안내한다.
- **확정하면 현재 사진에 머문다.** 버튼이 `확정됨` 상태로 바뀌고 앱바 수량과 필름스트립 배지가 갱신된 결과를 사용자가 확인한 뒤, 스와이프·필름스트립·방향키로 다음 사진을 직접 선택한다. 비슷한 컷에서 자동 이동을 알아채지 못하는 문제를 피한다.
- **확정을 누른 티는 버튼뿐 아니라 "결과가 쌓이는 곳"에서도 낸다.** 다음 네 가지 반응을 함께 사용한다:
  - 눌림은 `:active`가 아니라 **`pointerdown`에서 거는 170ms 애니메이션**(`.rvx-pressed`)이다. `:active`는 손가락이 닿아 있는 동안만이라 짧게 톡 치면 60~100ms 만에 끝나 `transition`이 목표값에 닿기도 전에 손이 떨어진다 — 실기기에서 "눌린 느낌이 없다"는 보고의 원인이었다. 탭 길이와 무관하게 끝까지 재생돼야 한다(연속으로 눌러도 매번 처음부터 재생되도록 클래스를 뗐다 붙이며 리플로우를 강제한다).
  - **햅틱은 안드로이드 전용**이다 — iOS Safari에는 Vibration API가 없어 아이폰에서는 아무 일도 일어나지 않는 것이 정상 동작이다(셀렉 뷰어의 찜 햅틱도 마찬가지).
  - 앱바 카운터의 **숫자만** 한 번 커졌다 돌아온다(`rvx-bump`). 숫자 `<b>`에 `key={count}`를 걸어 값이 바뀔 때마다 새로 마운트시켜야 애니메이션이 매번 재생된다.
  - 필름스트립에서 **방금 판단한 한 장의 배지만** 튄다(`.rvx-badge-pop`, `justJudgedId`). 전부 튀게 하면 첫 로드에서 이미 판단된 배지가 한꺼번에 튀어 잡음이 된다.
  - 모바일 햅틱은 셀렉 뷰어와 같은 공통 유틸(`triggerSelectionHaptic("change")`)을 그대로 쓴다.
  - 모든 애니메이션은 `prefers-reduced-motion`에서 꺼진다.
- **하단은 필름스트립과 검토 진행/전달 영역을 같은 124px 행에 둔다.** PC는 오른쪽 292px, 모바일은 152px을 진행 영역으로 예약한다. 검토 중에는 `검토 수 / 전체 · 남은 장수`, 전부 판단했으나 사유가 빠지면 `사유 확인`, 제출 가능하면 `작가에게 전달`로 같은 자리의 내용만 바뀐다. 별도 `SelectionConfirmFooter`가 나타나 사진 높이를 밀지 않는다.
  - 위치 트랙은 `tone="plain"`(흰색)이며 필름스트립 칸 안에서만 그린다. 완료 CTA의 주황색과 경쟁하지 않는다.
  - 모바일도 새 행을 더하지 않고 필름스트립과 같은 높이를 나눠 쓴다. 행동이 필요한 상태에서는 설명을 접고 버튼 폭을 확보한다.
  - 수령 모드는 판단/전달 영역이 없으므로 필름스트립이 전체 폭을 사용한다.
- **확정바 버튼은 노치(clip-path)가 아니라 `border-radius: 10px`다.** 예전 다크 톤 기본값은 오른쪽 아래를 자른 `polygon(...)`이었는데, 같은 화면의 나머지가 전부 라운드(판단 버튼 12px, pill 999px)라 이 버튼만 튀었다. 라이트 톤은 이미 radius였으므로 다크를 거기에 맞춘다(모바일 갤러리 variant는 기존 8px 유지).
- **위치 트랙은 필름스트립이 실제로 넘칠 때만 보여준다.** 썸네일이 한 화면에 다 들어오면 트랙은 같은 정보를 되풀이할 뿐이다. 장수로 어림하지 않고 `ResizeObserver`로 `scrollWidth > clientWidth`를 측정한다 — 임계 장수가 화면 폭과 썸네일 크기(PC 132px / 모바일 84px)에 따라 달라지기 때문이다. 감추면 트랙 자리(위쪽 여백)도 함께 거둔다(`.rvx-strip-flat`).
- **단축키 도움말은 `?`로 연다**(입력 중에는 무시). 패널 바닥의 한 줄 요약을 눌러서도 열린다 — `?`만으로는 아무도 찾지 못한다. 도움말이 열려 있을 때 `Esc`는 목록으로 나가지 않고 도움말부터 닫는다.
- 모바일 검토 화면에서 **재보정 사유 입력칸은 재보정을 고른 동안만 펼친다**(PC는 공간이 있어 상시 노출 — 누르기 전에 "사유를 적어야 한다"를 알리는 값이 있다). 접힌 상태에서 판단 패널은 `277px → 76px`로 줄고 그만큼 사진 무대가 넓어진다.
  - **주의**: 무대가 넓어져도 **가로 사진은 커지지 않는다**(가로가 먼저 꽉 차기 때문 — §위 "레터박스와 사진 크기의 관계"와 같은 성질). 이득을 보는 건 세로·정방형 사진이다(390px 폭 기준 같은 무대에서 세로 3:4는 약 `269px → 493px`).
  - 사진 비율에 따라 무대 높이를 바꾸지 않는다 — 가로/세로 사진을 오가며 훑을 때 컨트롤이 위아래로 튀는 편이 빈 검정보다 나쁘다.
- 필름스트립 썸네일은 PC `132×88`, 모바일 `84×58`이다. 모바일에서 132px은 두 장밖에 안 들어와 훑어보기가 되지 않았다(현재 4장).
- **보정본 검토 초안은 서버(`version_review_drafts`)에 저장하고 기기 간에 공유한다**(`ReviewContext`).
  - 왜 서버인가: PC에서 일부를 확정해 두고 나중에 모바일에서 이어 보는 흐름이 실제로 일어난다. 기기마다 상태가 다르면 **지금 상태를 모른 채 그 위에 덮어쓰게** 되고, 잘못된 상태로 제출될 수 있다. 셀렉이 한 장 고를 때마다 서버에 저장되는 것과 같은 수준으로 맞춘다.
  - 왜 `version_reviews`가 아닌 별도 테이블인가: ① `status='approved'` 행이 있으면 `replace_photo_versions_with_history`가 그 보정본 교체를 거부한다(20260901120000) — 고객이 제출도 하지 않은 초안으로 작가를 잠그면 안 된다. ② 작가 워크플로 화면은 `version_reviews`를 "고객이 낸 최종 결과"로 읽는다. 제출 시에만 옮기고 초안은 비운다.
  - **판단 취소는 행 삭제**다(행 없음 = 미검토). 상태 값으로 남기면 "취소"와 "미검토"가 갈라져 규칙이 둘이 된다.
  - 동기화는 셀렉(`GET /api/c/selections`)과 **같은 5초 폴링·같은 충돌 규칙**이다: GET을 보내기 직전의 사진별 버전·dirty를 스냅샷해 두고, 응답이 왔을 때 **그 사이 내가 건드리지 않은 사진에만** 서버 값을 적용한다. poll 시퀀스로 응답 역전을 막고, `visibilitychange`로 탭 복귀 즉시 당겨온다. 저장은 사진별 350ms 디바운스.
  - **첫 화면은 사진 목록과 서버 초안을 함께 기다렸다가 한 번에 그린다.** 예전처럼 localStorage를 먼저 그리고 서버로 덮으면 그 수백 ms 동안 이 기기의 옛 판단이 보이고, 그 위에 판단을 덮어쓸 수 있다.
  - `localStorage`는 **서버 초안 조회가 실패했을 때만 읽는** 마지막 수단이다(오프라인은 애초에 사진이 로드되지 않아 검토 자체가 불가능하므로 별도로 다루지 않는다).
  - 회차가 넘어가면(`reviewing_v1` → `v2`) 같은 토큰의 지난 회차 로컬 키는 정리하고, 서버 초안은 제출 시 지워진다.
  - **남은 한계**: 링크 단위 공유라 같은 링크를 연 사람끼리 서로의 판단을 덮어쓸 수 있다(셀렉과 같은 모델). 지금 상태가 화면에 보이는 한 덮어쓰는 것 자체는 문제가 아니라는 판단이다.
- 코멘트 저장 표시(`CommentSaveIndicator`)는 저장 중/저장됨/실패에만 렌더한다. 유휴 상태의 `자동 저장` 라벨은 아무 일도 없을 때조차 한 줄을 차지해 제거했다.
- **선(border)은 구조를 나누는 최소한만 남긴다** — 헤더 하단 한 줄뿐이고, 우측 패널·필름스트립은 선이 아니라 **면(배경 밝기 `rgba(255,255,255,.03~.05)`)으로 구분**한다. 이전에는 헤더 세로 구분선 + HUD 박스 테두리 + 유사컷 밴드 상·하선 + 필름스트립 상단선 + 썸네일마다 회색 테두리가 겹쳐, 화면이 격자처럼 읽히며 정작 사진이 묻혔다.
  - 필름스트립 썸네일은 기본 테두리를 없애고 `2px` 투명 테두리 자리만 잡아둔다(현재 위치일 때 흰색으로 채워져 레이아웃이 흔들리지 않는다). 비활성은 grayscale + `opacity .45`로 눌러 구분한다.
  - 썸네일 위 인덱스 번호(`001`, `002`…)는 제거했다 — 파일명과 마찬가지로 고객이 사진을 식별하는 단서가 아니면서 썸네일마다 라벨을 하나씩 더해 시각적 잡음만 키웠다.
- 헤더 우측 순서는 `위치 라벨 → 신원 칩`이며 **신원 칩이 맨 끝**이다(모바일 앱바와 같은 정렬).
- **유사컷 UI는 주황을 쓰지 않는다** — 주황은 "선택"(작가에게 전달되는 결과물) 전용이라, 탐색 보조인 유사컷 밴드/버튼이 같은 색을 쓰면 화면에서 가장 강한 요소가 되어 선택 상태와 경쟁했다. 필름스트립에서도 **현재 위치는 흰 테두리**, 주황은 선택 체크 배지에만 남긴다(모바일 계약과 동일).
- 그 밖의 PC 구성은 기존 데스크톱 HUD의 기능을 그대로 두고, 색·폰트·문구를 모바일(`.fv-*`) 팔레트에 맞춰 정리했다: 헤더 배경을 모바일 앱바와 동일한 `#161a1d`/`#424242` 보더로, Space Grotesk/Space Mono 폰트를 Pretendard로, 미선택 별 색을 모바일과 동일한 `#777B7F`로, 필름스트립 비활성 썸네일 보더를 모바일과 동일한 `#4f545a`로 맞췄다. 선택 액션도 모바일과 동일하게 HUD 패널의 CTA 버튼이 아니라 사진 좌측 하단 체크박스(탭 영역 `44 × 44px`, 시각 박스 `34 × 34px`)로 제공하며 미선택/선택됨 색상도 모바일과 동일하다. 코멘트 입력창도 모바일과 동일하게 말풍선 아이콘 + 밝은 회색(`#a8abae` 테두리/`#d6d6d6` 텍스트)으로 맞췄다. 가짜 EXIF 캡션과 위/경도 장식(실제 데이터가 아닌 순수 장식)은 모바일에 없는 요소라 제거했다.
- 이전/다음 버튼(`PrevNextButton`)과 하단 확정바(`SelectionConfirmFooter`)는 기본값(다크 Photo Workspace 톤)을 그대로 사용한다 — 별도 라이트 variant를 적용하지 않는다.
- 별점·색상 태그·선택 토글·코멘트 자동 저장·유사컷 그룹 펼침·필름스트립 탐색 등 기능 계약은 모바일과 동일하게 유지한다. 키보드 단축키(`?`, `ESC`, 방향키, `1`–`5`, `Q W E R T`)도 PC 전용 기능으로 그대로 둔다.

## 12. Selection confirmation and completed gallery (`#55886`, `#55891`, `#55892`)

25. 미선택 체크박스가 갤러리 카드와 같은 **흰 채움**이라 어두운 사진 위에서도 "빈 체크박스"로 읽히는지 확인한다(이전의 반투명 검정은 로딩 플레이스홀더처럼 보였다).
26. 비율이 다른 사진(가로↔세로)을 빠르게 넘길 때 좌측 상단 체크박스가 화면 위쪽에 잠깐 나타났다 제자리로 이동하지 않는지 확인한다(측정 전에는 아예 보이지 않아야 한다).
27. 챙을 숨기고 다시 켤 때 사진이 `220ms` 동안 부드럽게 확장·축소되는지, 확장 상태에서 핀치 확대·팬이 정상 동작하는지 확인한다.
28. 첫 `찜` 탭에서 "누구세요?" 시트가 뜨고, 이미 쓰인 색이 `사용 중`으로 표시되는지, 색·이니셜 저장 후 그 찜이 이어서 적용되는지 확인한다.
29. 재접속(새로고침) 후에도 내 색·이니셜이 유지되는지, `localStorage`를 비우면 되찾기 시트에서 기존 색을 다시 골라 복구되는지 확인한다.
30. 갤러리 필터(모바일 시트·PC 툴바)에 실제로 쓰인 색만 나오고 내 색이 `내 찜`으로 라벨링되는지, 필터 적용 결과가 뷰어의 이전/다음 탐색 목록과 일치하는지 확인한다.
31. 다른 참가자가 이니셜을 저장한 뒤 내 화면을 새로고침하면 그 사람의 마크 안에 이름 글자가 보이고, 갤러리 필터 라벨도 색 이름 대신 그 이름으로 바뀌는지 확인한다.
32. 찜 알약 왼쪽 구획을 눌러 `내 표시 바꾸기` 시트가 뜨는지, 이름만 고쳐 저장했을 때 **그 사진의 찜 상태가 변하지 않는지**(intent=`edit`), 다른 색을 고르면 이전 색 경고가 뜨는지 확인한다.
33. 색을 2개 이상 고른 상태에서 `모두 찜`으로 바꾸면 결과가 교집합으로 줄고 URL에 `color_mode=all`이 붙는지, 그 URL로 연 뷰어의 이전/다음 목록도 같은 교집합인지 확인한다. 색을 1개로 줄이면 토글이 사라지고 쿼리에서도 빠지는지 함께 본다.
34. 위치 인디케이터를 탭/드래그하면 그 비율에 해당하는 사진으로 바로 이동하는지(`N/M` 텍스트와 thumb 위치가 함께 갱신), 첫 장·마지막 장에서 thumb이 각각 트랙 왼쪽/오른쪽 끝에 닿는지 확인한다.
35. 유사컷 그룹을 펼치면 위치 트랙이 감춰지고 필름스트립 행이 붙으며(컨트롤 행 76px→56px, 스트립 0→68px가 전환 애니메이션과 함께) 그룹 멤버만 보이는지, 접으면 다시 위치 트랙이 컨트롤 행 윗변으로 돌아오는지 확인한다.
38. 별점·코멘트·찜 세 알약이 같은 높이(44px)·반경·테두리로 보이는지, 찜 켜짐 상태에서 알약만 밝게 떠 보이지 않고(inset 틴트) 안쪽 dot이 참가자 색으로 채워져 읽히는지 확인한다.
40. PC에서 사진 오른쪽에 320px 컨트롤 패널이 보이고 사진이 세로로 꽉 차는지, 1200px 이하에서 패널이 288px로 줄어드는지 확인한다.
41. PC 헤더에 `Y / N장 선택`이 상시 보이고(선택을 다 채우기 전에도) 파일명은 보조 텍스트인지, 헤더에 위치 표시가 없는지, 위치는 필름스트립 윗변의 주황 바 + `N/M`으로 보이며 탭하면 이동하는지, 유사컷 묶어보기를 켜면 `대표컷 N/M`으로 바뀌는지 확인한다.
42. 유사컷 밴드·펼침 버튼·필름스트립 현재 위치 표시에 주황이 쓰이지 않는지(주황은 선택 체크·카운트·별점에만), 유사컷을 펼치면 멤버 썸네일이 하단이 아니라 우측 패널에 쌓이는지 확인한다.
45. 모바일 하단 컨트롤에서 **둥근 테두리가 바 하나뿐**인지(별점·유사컷·코멘트·찜은 무테), 찜을 켜면 테두리 대신 내 색 채움으로 바뀌는지, 유사컷 항목이 다른 항목과 같은 44px인지 확인한다.
44. 필름스트립 썸네일에 인덱스 번호가 없고 기본 회색 테두리도 없는지, 현재 위치만 흰 테두리로 구분되는지 확인한다. 헤더 하단 외에 가로 구분선이 겹쳐 보이지 않는지(패널·필름스트립은 배경 밝기로만 구분) 함께 본다.
47. 보정본을 몇 장 판단한 뒤 **탭을 닫았다 다시 열어도** 판단 결과와 재보정 사유가 남아 있는지 확인한다. 헤더에 저장 상태 표시는 없어야 한다.
43. 코멘트를 건드리지 않은 상태에서 `자동 저장` 라벨이 보이지 않고, 입력하면 `저장 중…` → `✓ 저장됨`이 나타났다 사라지는지 확인한다.
39. 앱바(모바일)·헤더(PC) 우측 신원 칩이 `● 이름`으로 보이는지, 이름 미등록이면 점선 테두리 + `이름`으로 보이는지, 탭하면 `내 표시 바꾸기` 시트가 열리는지 확인한다. 아직 색을 안 정한 상태에서는 칩이 아예 없고 찜 버튼이 빈 링 + `찜`으로 보이는지 함께 본다.
36. 사진 영역에서 위로 스와이프하면 코멘트 시트가 열리는지, **아래로 스와이프해도 아무 일이 일어나지 않는지**(갤러리 복귀는 제거됨), 좌우 스와이프(사진 전환)·pinch 확대와 방향이 헷갈리지 않는지 확인한다.
46. 모바일에서 코멘트를 입력·저장해 키보드가 닫힌 뒤 화면이 위로 밀려 하단에 검은 띠가 남지 않는지, 화면 어디서도 세로 스크롤이 되지 않는지 확인한다(실기기 iOS/Android 필요).
37. 이름을 등록하지 않은 참가자의 마크가 빈 원이 아니라 `?` + 점선 테두리로 표시되는지(모바일 사진 위·PC 컨트롤 패널 모두), 내 마크도 이름을 안 넣었을 때 같은 스타일로 보이며 탭하면 `내 표시 바꾸기` 시트가 열리는지 확인한다.
48. PC(1440px)에서 `/c/[token]/review`가 첫 사진으로 자동 이동하지 않고 격자 목록을 보여주는지, 썸네일을 눌러 상세로 들어간 뒤 **닫기(X)·`Esc`로 목록으로 돌아오는지**(1번 사진으로 튕기지 않음) 확인한다.
49. 목록 상단 집계가 `확정·재보정·미검토`로 맞는지, 진입은 썸네일 탭뿐이고 별도 진입 버튼이 없는지 확인한다.
50. 열 수가 모바일 3열, PC는 폭에 따라 늘어나는지(1440px에서 6열), 제출 확인 모달이 모바일은 바텀시트·PC는 중앙에 뜨는지 확인한다.
51. 검토 상세에서 확정 버튼이 재보정보다 시각적으로 무겁게(채워진 면 vs 무테) 보이는지, 누르기 전에는 둘 다 초록/앰버가 아닌지 확인한다.
52. PC 원본 비교 버튼이 사진 하단 중앙에 있는지, 모바일에서는 별도 원본 버튼이 없고 사진을 길게 누르는 안내만 보이는지 확인한다.
53. 재보정을 고른 직후에는 "적어주세요" 경고가 없고 `필수` 칩만 보이는지, 빈 칸을 떠나면 그때 경고가 뜨고 입력을 시작하면 사라지는지, 원본 비교 버튼을 눌러도 경고가 뜨지 않는지 확인한다.
54. 원본 비교 pill이 사진 무대 하단 중앙에 있는지, 가로 사진에서는 검은 여백에 얹혀 사진을 가리지 않는지, 이 버튼을 눌러도 집중 보기가 열리지 않는지 확인한다.
55. 확정 후 현재 사진과 URL이 유지되고, 사진 크기를 바꾸는 안내 줄 없이 버튼·앱바 수량·필름스트립 배지만 갱신되는지 확인한다.
56. 전부 검토해야만 하단 확정바가 나타나는지, 그 모양이 셀렉 뷰어 풋터와 같은지(다크 바 + 주황 안내 문구 + 주황 CTA), 문구가 `N장 모두 검토했어요! 전달 버튼을 눌러주세요`인지, 좁은 화면에서는 문구 없이 버튼이 가로를 다 쓰는지 확인한다.
57. 사진이 적어 필름스트립이 넘치지 않을 때 위치 트랙이 사라지고 그 여백도 함께 줄어드는지, 창을 좁혀 넘치게 만들면 다시 나타나는지 확인한다.
58. `?`로 단축키 도움말이 열리고(사유 입력 중에는 열리지 않음), 패널 하단 한 줄을 눌러도 열리며, `Esc`가 목록으로 나가지 않고 도움말만 닫는지 확인한다.
59. 셀렉 뷰어 하단에 **주황 가로바가 하나도 없는지**(위치 트랙은 흰색, 풋터 진행바는 없음), 주황은 확정바 버튼에만 남았는지 확인한다. 갤러리·검토 목록에는 진행바가 그대로 있어야 한다.
60. 확정바 버튼의 오른쪽 아래가 잘려 있지 않고 라운드인지, 좁은 화면(≤767px)에서 진행바가 없는 화면의 버튼이 가로 전체를 쓰는지 확인한다.
61. 검토를 다 마치기 전에는 검토 상세 하단에 확정바가 없고, 사진 아래 가로 밴드가 `판단 패널 / 필름스트립` 두 겹으로만 읽히는지 확인한다(모바일·PC 모두).
62. 다크 확정바의 상단 구분선이 주황이 아니라 중립 회색인지, 라이트(갤러리·검토 목록) 확정바는 배경·구분선·진행바가 그대로인지 확인한다.
63. 검토 목록과 셀렉 갤러리를 나란히 놓고 머리(홈 마크·제목·마감일·카운트)와 카드(파일명 서체/위치, 그라데이션, 비율, 좌우 여백)가 형제처럼 보이는지 확인한다. 모바일 제목은 `보정본 검토`, PC 제목은 프로젝트명이어야 한다.
64. 긴 파일명이 중간에서 잘리지 않고 ellipsis로 끝나는지 확인한다.
65. 미판단 사진에서 확정(큰 채움 버튼 + `Y` 힌트)과 재보정 요청(무테 보조 버튼 + `R` 힌트)의 무게가 눈에 띄게 다른지, 모바일에서는 키 힌트가 없는지 확인한다.
66. 판단을 내리면 두 버튼이 상태 칩 + `~로 바꾸기` 한 줄로 접히는지, 칩을 누르면 판단이 취소되어 다시 펼쳐지는지, 확정한 사진에서는 재보정 사유 칸도 접혀 사진이 커지는지 확인한다.
67. 판단 결과 배지가 사진 좌상단 회차 라벨 옆에 뜨는지, 판단 순간 아이콘이 한 번 튀는지(reduced-motion에서는 튀지 않음) 확인한다.
68. 실기기 모바일에서 갤러리·검토 목록을 끝까지 당기거나 주소창을 접었다 펴도 하단에 검은 띠가 보이지 않는지 확인한다. 반대로 셀렉 뷰어·검토 상세로 들어가면 다시 어두운 바탕이어야 한다(라이트 화면을 떠날 때 되돌린다).
68. 실기기 모바일에서 갤러리·검토 목록을 끝까지 당기거나 주소창을 접었다 펴도 하단에 검은 띠가 보이지 않는지 확인한다. 반대로 셀렉 뷰어·검토 상세로 들어가면 다시 어두운 바탕이어야 한다(라이트 화면을 떠날 때 되돌린다).
69. 검토 상세 판단 버튼이 모바일·PC 모두 한 줄에 나란히 놓이고, 확정이 재보정보다 눈에 띄게 넓고 높고 채워져 있는지 확인한다. 창을 1200px 이하로 줄이면 보조 라벨이 `재보정`으로 줄고, 767px 이하(모바일)에서는 다시 `재보정 요청`으로 돌아오는지 함께 본다.
70. 확정을 누를 때 버튼이 살짝 눌리고, 앱바의 `확정` 숫자가 한 번 커졌다 돌아오며, 필름스트립에서 **방금 판단한 한 장의 배지만** 튀는지 확인한다(첫 로드에서는 배지가 한꺼번에 튀지 않아야 한다). 모바일 실기기에서는 짧은 진동이 오는지 함께 본다.
71. PC에서 일부를 확정한 뒤 **다른 기기(또는 브라우저 데이터를 비운 상태)에서 같은 링크**를 열었을 때 판단·재보정 사유가 그대로 보이는지, 한쪽에서 취소하면 다른 쪽도 5초 안에(탭 복귀 시 즉시) 따라오는지 확인한다.

74. 판단 배지가 무대 모서리가 아니라 **사진의 실제 모서리**에 붙는지, 창 크기를 바꾸거나 기기를 회전해도 따라오는지 확인한다(가로 사진·세로 사진 모두).
75. 사유를 안 적은 재보정이 남은 상태에서 안내 배너가 **앱바 바로 아래(사진 위)** 에 뜨는지, 누르면 그 사진으로 이동하는지, 사유를 채우면 배너가 사라지고 하단 확정바로 바뀌는지 확인한다.
76. 검토 결과를 전달할 때 뜨는 확인 모달이 셀렉 확정 모달과 같은 흰 카드인지(문구만 다름), 취소/전달 버튼 동작과 전송 중 잠금이 같은지 확인한다.
77. 잠금 갤러리를 PC에서 열었을 때 라이트인지(헤더·상태바·카드·풋터·원본 다운로드 버튼 모두), 확정/재보정 배지가 검토 목록과 같은 색인지, 확정 취소 모달이 같은 흰 카드인지 확인한다.
78. 잠금 갤러리 PC에서 머리가 한 줄인지(브랜드·상태·카운트·다운로드가 같은 줄), 코멘트 없는 카드가 코멘트 있는 카드 높이에 끌려가 빈 공간을 만들지 않는지, 상태 배지가 카드 폭을 다 먹지 않는지 확인한다. 확정 취소가 불가능한 상태에서는 하단 풋터가 아예 없어야 한다.
79. 잠금 갤러리 셀렉 결과 뷰에서 카드마다 `선택`/`미선택` 배지가 붙지 않는지, 대신 섹션 헤더가 머리 아래에 달라붙어 따라오는지, 썸네일 1:1에서 인물 머리가 잘리지 않는지 확인한다. 검토 결과 뷰에서는 확정/재보정 배지가 카드에 그대로 남아야 한다.
80. 잠금 갤러리 검토 결과 뷰가 `재보정 요청`(위) → `확정`(아래)으로 묶이는지, 배지가 사진 위 오른쪽 위에 검토 목록과 같은 모양으로 뜨는지, 두 섹션 헤더가 스크롤에서 머리 아래에 달라붙는지 확인한다.
81. 잠금 갤러리에서 `확정 취소` 모달을 열고 닫아도 배경의 카드 높이와 1:1 썸네일 비율이 바뀌지 않는지 확인한다. 모달 제목·본문·버튼 스타일은 모달 내부에만 적용되어야 한다.
82. 셀렉 진행 중 모바일 갤러리의 2열 카드에서 코멘트가 있는 사진만 하단 우측 주황색 말풍선 아이콘을 표시하는지 확인한다. 3·4열에서는 아이콘을 숨기고 코멘트 본문은 상세 뷰어에서 확인한다.
81. 잠금 갤러리 PC 머리 아래에 원본 다운로드 띠가 있고 `날짜까지 · N일 남음`이 함께 보이는지, 3일 이내면 주황으로 바뀌는지, 아카이브가 없는 프로젝트에서는 띠 자체가 없는지 확인한다.
82. 셀렉 결과 카드에 셀렉 때 남긴 코멘트가 보이는지(중립 회색 박스), 코멘트가 없는 카드에는 빈 상자가 생기지 않는지 확인한다.
83. 셀렉 갤러리에서 2·3·4열을 오가며 카드 구조가 같은지 확인한다(사진 1:1, 흰 카드, 파일명은 사진 위). 세로 사진이 가로로 잘리지 않는지, 3열에서도 빈 별이 보이고 눌리는지, 4열에서만 파일명·별점이 감춰지는지 함께 본다.
84. 2열에서 파일명을 길게 눌러 **텍스트로 선택**되는지(링크 메뉴가 아니라), 파일명 줄을 눌러도 상세로 들어가지 않는지, 별점·코멘트·색은 사진 안에 남아 있는지 확인한다.
85. 코멘트를 남긴 사진에 말풍선 표시가 **PC·2열·3열 모두**에서 보이는지 확인한다(4열은 오버레이가 없어 제외).

- 보정본 상세의 원본 비교 레이어는 기본 사진 무대와 같은 배경색을 사용하며 즉시 전환해 보정본 잔상과 배경색 변화를 방지한다. 전체 화면 확대는 기존 검정 배경을 유지한다.
- PC 하단 전달 영역은 우측 판단 패널과 동일한 폭과 표면으로 정렬하고, 완료 문구 아래에 전체 폭 전달 버튼을 배치한다.

- 최종 보정본 상세의 수령 모드에서도 하단 `수령 완료` 버튼을 제공한다. 확인 모달에서 전체 보정본 수령을 확인한 뒤 갤러리와 동일한 제출 API로 전체 사진을 approved 처리하며, delivered 응답 시 납품 완료 화면으로 이동한다. 재보정 0회 프로젝트도 상세보기를 유지한다.

- 고객 셀렉 상세뷰어는 PC 필름스트립 옆과 모바일 하단에 선택 수 및 `셀렉 확정하기`를 상시 표시한다. 필요한 장수를 정확히 채웠을 때 활성화하며 기존 확정 확인창과 API를 사용한다. 완료 시 별도 바가 솟아오르지 않는다.

- 유사컷 뱃지는 작가 원본업로드·원본탭·고객 갤러리에서 전체 장수와 펼침 방향으로 통일한다. 펼친 묶음은 중립색으로 표시하고 주황 테두리는 실제 선택에만 사용한다. 펼친 멤버마다 접기 버튼을 제공하며 작가 목록에서도 같은 버튼이 동작한다. 고객은 선택 수를 별도 보조 표시로 제공하고 펼친 동안 선택 변경에 따라 그룹 위치가 이동하지 않는다.
