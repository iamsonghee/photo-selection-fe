# 신규 랜딩 성능 QA — 2026-10-17

대상: 로컬 `http://localhost:3001/`, `/select`, `/studio`. `feat/landing-entry-flow` 작업 폴더에서 확인했다. 운영 배포와 운영 데이터 변경은 하지 않았다.

## 재현과 원인

Aside 브라우저의 데스크톱 1440×900에서 첫 진입, 정지, 전체 스크롤, 하단 정지, 재방문을 조사했다. 표본은 2.2초이며 개발서버·브라우저 자동화 환경의 측정이므로 운영 FPS로 해석하지 않는다.

| 문제 | 심각도 | 수정 전 증거 | 수정 |
|---|---|---|---|
| 셀렉 첫 화면에서 정지해도 계속 갱신 | HIGH | 2회 표본에서 childList 변경 212·44회, 최대 long task 1,303ms | 사진 더미의 상시 움직임과 RAF 루프 제거. 스크롤 이벤트를 프레임당 한 번으로 합침 |
| 셀렉 화면 밖에서도 불필요한 처리 | MEDIUM | 하단 표본에서 childList 102회 | 화면 밖·숨겨진 탭의 스크롤 시연 갱신 중단 |
| 스튜디오 정지 중 같은 장수 DOM 재생성 | MEDIUM | 2회 표본에서 childList 변경 123·110회 | 상태·장수 변경 시에만 내용 갱신하고 두 상시 RAF 루프를 스크롤 기반으로 전환 |

통합 홈의 찜 숫자 강조도 `offsetWidth`를 읽어 CSS 애니메이션을 재시작하던 방식에서 Web Animations로 바꿔 강제 동기 레이아웃을 제거했다.

추가로 셀렉의 폰트 로딩·같은 화면 구간 resize에서 사진 DOM을 재사용한다. 스튜디오도 갤러리 열 수가 바뀌지 않으면 사진을 다시 만들지 않는다. 움직임 축소에서는 셀렉 완료 장면을 정적으로 표시한다. 기존 로그인 목적지와 시연의 선택·필터 동작은 유지한다.

## 수정 후 독립 재검증

- Aside 안정화 후 셀렉 정지 표본 2회: childList **0·0회**, long task 0건.
- Aside 안정화 후 스튜디오 상단 및 하단 정지 표본: childList **0·0회**, long task 0건.
- 반복 스크롤 표본: 셀렉 long task 52ms 1건, 스튜디오 51·54ms. 첫 전체 스크롤에서는 최대 348ms의 긴 프레임이 남았지만, Long Animation Frame 기록에 앱 스크립트 원인이 잡히지 않았다. 이미지 준비·렌더링 등의 영향일 가능성은 있으나 확정하지 않는다.
- 셀렉 하단에 처음 들어간 직후의 DOM 변경은 업로드 숫자 시연 종료 후 0회로 안정화됐다. 이것은 상시 히어로 갱신과 구분한다.
- 깨끗한 브라우저의 모바일 세 페이지에서 가로 넘침, 깨진 이미지, 페이지 오류, 실패 요청은 관찰되지 않았다.

## 최종 대조 측정과 판정

**qa-verifier: CONDITIONAL PASS.** 재현된 상시 DOM 병목은 해결됐고 기능 회귀는 발견하지 않았다. 실제 저사양 휴대폰·저속망과 Aside 냉간 첫 진입의 렌더링 지연은 검증 한계로 남는다.

초기 통합 홈의 짧은 표본에서는 165~201ms 프레임 간격이 있었지만, 이후 정적 `/terms`에서도 비슷한 지연이 관찰돼 이 절대값만으로 랜딩 고유 결함으로 단정하지 않았다.

- 안정화한 Aside 통합 홈의 한 주기 14초: long task **0건**, RAF 간격 중앙값 17ms, p95 50ms, 최대 85ms. 정적 `/terms`는 중앙값 30ms, p95 49ms, 최대 66ms로 느린 프레임 분포가 비슷했다. 통합 홈의 DOM 변경 17회는 찜·선택 연출에 따른 정상 변경이었다.
- 별도의 깨끗한 Chromium에서 `/terms`, 통합 홈 움직임 축소, 통합 홈 일반 상태를 각각 4초 대조: 모두 프레임 간격 중앙값·p95·최대 약 17ms, long task·Long Animation Frame **0건**. 일반 상태의 찜 연출 변경 외 불필요한 반복 DOM 생성은 관찰하지 않았다.

따라서 앞선 짧은 표본의 낮은 RAF 수를 그대로 앱의 지속적인 성능 결함으로 해석하지 않는다. 첫 진입의 모든 지연이 없어졌다는 의미도 아니다.

## 검증과 범위

자동 회귀 테스트: `tests/e2e/landing-performance.spec.ts`. PC·모바일의 정지 중 내용 유지, 움직임 축소 완료 장면, 통합 홈의 자바스크립트 없는 초기 배경 표시를 확인한다. 기존 `entry-flow.spec.ts`의 세 랜딩·로그인 목적지·모바일 표시도 함께 실행했다.

- 자동 테스트 5개 통과.
- `npx tsc --noEmit` 통과.
- 변경 파일 ESLint와 `git diff --check` 통과.
- `npm run build -- --webpack` 통과(Next.js의 기존 middleware 명칭 변경 안내는 남음).
- `scripts/landing-preview-css.mjs`에도 통합 홈의 초기 열 구성·제목 수정사항을 반영했고, 재생성 결과가 현재 CSS와 동일한 것을 확인했다.
- 독립 기능 검증: 셀렉 품질 필터·그룹 펼치기·가족 탭, 스튜디오 유사컷·품질·가족 탭, 양쪽 로그인 CTA와 뒤로가기, 일반·움직임 축소 모바일의 새로고침·resize 정상. JavaScript 오류·실패 요청·깨진 이미지·가로 넘침 없음.

통합 홈은 앞선 작업의 서버 HTML 배경과 이미지 우선순위를 유지한다. 이번 조사에서 통합 홈의 순간적인 RAF 간격이 관찰됐지만 앱 long task 원인은 확정하지 않았다. 실제 저사양 휴대폰·모바일망·운영 빌드의 성능 측정은 별도 범위다. Aside는 viewport 변경을 지원하지 않아 모바일 확인은 독립 Playwright 컨텍스트로 보완한다.

기존 미커밋 작업은 보존했다. 알림톡 작업 폴더와 백엔드 소스는 수정하지 않았으며, `docs/landing-studio-handoff.md`도 그대로 두었다.

## 추가: 저사양·저속망 이미지 모드

세 랜딩의 서버 첫 화면을 PC·모바일용 WebP 시연 이미지로 제공한다. 저사양·저속망 힌트가 있으면 이 상태를 유지하고 연출 코드를 불러오지 않는다. 단순히 애니메이션을 멈추는 방식과 달리 16~50장의 사진 격자 DOM도 생성하지 않는다. 일반 환경은 필요한 연출 모듈을 받아 기존 시연으로 전환한다.

판별 기준: 데이터 절약 요청, slow-2g/2g/3g, 0 초과 1.5Mbps 이하 downlink, 0 초과 4GiB 이하 메모리, 0 초과 CPU 4개 이하. 이는 브라우저 힌트를 활용한 휴리스틱으로 실제 벤치마크 판정이 아니다. 힌트가 없으면 일반 환경으로 처리한다.

정적 모드에서도 제목·설명·로그인·시작 버튼·FAQ는 HTML로 유지한다. 스튜디오 기능 예시는 가벼운 이미지 교체로 전환하고 원본·보정본 비교도 유지한다. 다른 시연은 실제 캡처 이미지로 표시한다. 히어로 이미지는 먼저, 아래 시연 이미지는 지연 로딩한다. 연출 파일 로딩 실패 시 정적 이미지를 유지한다.

- PC·모바일 데이터 절약/3g 모의 환경에서 세 페이지 모두 이미지 모드, 연출 chunk 요청 0회, 애니메이션 사진 격자 0개, 가로 넘침·페이지 오류 없음.
- `tests/static-landing.test.mjs`는 저사양·저속망과 미지원·정상 힌트를 검사한다.
- 기존 일반·움직임 축소·로그인 회귀와 정적 모드 검증을 함께 실행한다.
- 이미지 갱신: 로컬 개발 서버 실행 후 `node scripts/render-landing-posters.mjs`. 실제 랜딩 화면을 캡처하며 `public/landing/posters`와 `src/components/landing/posters.json`을 갱신한다. 문구·화면 시안을 바꿨다면 함께 다시 생성한다.

추가 검증 결과: 관련 회귀 테스트 7개, 판별 단위 검사, 타입 검사, 린트, 프로덕션 빌드 통과. 3g 정보만 제공한 환경에서도 세 랜딩 모두 정적 모드를 유지했고, 모바일 히어로는 PC 이미지 중복 없이 모바일 이미지 하나만 요청했다. Aside에서도 망 정보를 모의한 페이지 이동으로 이미지 모드를 확인했으며 테스트용 브라우저 속성은 복원했다.


## 배포 전 진입·푸터 확인

- 작가 랜딩의 첫 화면·이용 안내·하단에서 베타 신청 진입을 복구했다.
- 세 랜딩의 로그인 모달은 현재 화면 위에 열리고 닫으면 위치를 유지한다. 로그인 성공 목적지(일반·작가·개인·베타)를 검사했다.
- 메뉴로 랜딩을 왕복하면 히어로부터 표시하며 해시 링크는 기존 동작을 유지한다. PC·모바일 회귀 검사를 통과했다.
- 개인 랜딩 마지막 하객 앨범 링크는 시작 버튼 아래에 표시한다.
- 푸터의 사업자 정보 버튼은 약관·개인정보처리방침과 같은 줄에 배치한다. 상세 정보는 기본 접힘이며 PC·모바일 세 랜딩에서 펼침·닫기를 확인했다. Aside의 실제 작가 랜딩에서도 같은 줄 좌표와 스크린샷을 확인했다.
- 최종 webpack 프로덕션 빌드 및 경로 이전·로그인 목적지·워크스페이스·정적 모드 단위 검사를 통과했다.
- 배포 전 운영 랜딩의 이미지·폰트·영상을 내장한 단일 HTML을 저장하고 오프라인 표시를 확인했다. 보관 파일은 앱 배포에 포함하지 않는다.

## 모바일 이미지 대체 과잉 판정 수정

운영 모바일 피드백에 따라 4GB/4코어 또는 3G/1.5Mbps 단독 조건을 제거했다. 데이터 절약·slow-2g/2g·2GB 이하 및 2코어 이하 동시 확인만 정적 모드로 판정한다. 기존 본문의 초기 기준과 3G 검증 결과는 수정 전 기록이다. 일반 모바일 힌트의 세 랜딩 연출 진입과 저사양·데이터 절약 유지에 대한 회귀 검사를 추가했다.
