# 랜딩 진입·공통 로그인·공간 전환 작업 계획

상태: 1차 구현 및 로컬 검증 완료 — 2026-10-11. 아래 업무 항목은 계획이며, 구현 결과와 검증 범위는 마지막 절에 구분해 기록한다.
브랜치: `feat/landing-entry-flow`. 시작점: 로컬에 확인된 `origin/main` (`0103210b`).

## 목표와 범위

랜딩 디자인에 앞서 통합·스튜디오·내 사진 셀렉의 입구를 만들고, 같은 계정으로 두 작업 공간을 이용하는 동선을 로컬에서 검증한다.
표시 명칭은 로고 `A-CUT`, 공간 `작가·스튜디오` / `내 사진 셀렉`으로 한다.
회원 유형을 작가/고객으로 고정하지 않는다. 프로젝트별 소유권·참여 권한 및 기존 인증을 유지한다.

## 공간별 요금을 고려한 설계 원칙

스튜디오와 내 사진 셀렉은 서로 다른 요금 체계를 적용할 예정이다. 구체적인 가격·과금 단위·결제 시점은 미정이며, 월 구독/프로젝트별 결제 등 특정 모델을 이번 구현의 전제로 삼지 않는다.

- 계정과 인증은 공유하지만 공간별 상품 이용 자격과 사용량은 구분한다. 스튜디오 이용권이 있다는 이유만으로 내 사진 셀렉의 유료 기능을 허용하거나 반대 공간의 한도를 차감하지 않는다.
- 공간에 들어가고 전환하는 행동과 유료 기능 실행을 분리한다. 공간 이동으로 구매·구독 시작/변경/해지·이용권 발급이 발생하지 않는다.
- 로그인 목적지와 마지막 사용 공간은 이용권 보유 여부로 바꾸지 않는다. 이용권이 없더라도 해당 공간에 진입하여 안내를 볼 수 있다.
- 유료 기능의 허용 판단은 해당 공간·프로젝트와 인증된 사용자를 기준으로 서버에서 수행해야 한다. 마지막 공간 쿠키, 화면 메뉴, 클라이언트 상태를 권한 근거로 사용하지 않는다.
- 초대받은 참여와 자기 프로젝트 생성은 별개다. 공간 전환 기능을 추가하면서 기존 PIN·공유·하객 링크 참여에 새로운 구매 조건을 붙이지 않는다. 프로젝트 비용 부담자와 향후 참여 과금 정책은 별도로 결정한다.
- 기존 베타 제한·사용량·서버 권한 검사는 유지한다. 요금 미정이라는 이유로 현재 제한을 해제하거나, 모든 기능을 무료라고 표시하지 않는다.
- 상품 안내와 사용량을 표시할 때는 어느 공간의 정보인지 명시한다. 공통 계정 플랜 하나로 양쪽 혜택을 보장하는 문구를 사용하지 않는다.

이번에 구현할 것은 공간 식별과 이동, 기존 이용 제한을 올바른 공간에 연결하는 데 필요한 최소 변경이다. 범용 결제 엔진, 신규 구독/이용권 테이블, 결제 모듈, 가격표와 임의의 무료 한도는 만들지 않는다. 요금 확정 뒤 기존 구조를 기준으로 필요한 변경을 결정한다.

미정 항목: 공간별 과금 단위·가격·무료 범위, 결제를 요청하는 행동, 이용권 적용 범위와 유효기간, 만료·해지 후 조회/다운로드/편집 범위, 통합 상품 제공 여부. 이 항목들은 결제 구현 전에 확정하며 공통 로그인·공간 전환 구현을 막지는 않는다.

## 이동 계약

1. 유효한 초대·공유 링크 또는 보호된 작업 화면의 복귀 목적지가 있으면 해당 화면을 우선한다.
2. 스튜디오 시작 버튼은 작가 대시보드, 내 사진 셀렉 시작 버튼은 개인 프로젝트 목록으로 이동한다.
3. 일반 로그인은 계정의 마지막 사용 공간으로 이동한다.
4. 마지막 공간을 판단할 기록이 없으면 이용할 공간을 선택한다. 선택만으로 프로젝트를 생성하지 않는다.
5. 로그인 상태라면 재인증을 생략한다. 계정 전환·로그아웃 시 다른 계정의 이동 기록을 적용하지 않는다.
6. 양 공간에서 로그인 상태를 유지한 채 전환할 수 있다. 소개 페이지 방문만으로 마지막 작업 공간을 덮어쓰지 않는다.
7. 작가 초대 링크의 PIN, 셀렉 참여자·하객 링크의 인증은 기존 정책을 따른다. 모든 초대에 소셜 로그인을 강제하지 않는다.
8. 내 사진 셀렉을 처음 이용하면 기존 빈 목록 안내와 프로젝트 시작 동선으로 연결한다.
9. 이용권 유무와 무관하게 위 이동 우선순위를 유지한다. 공간 전환은 상품 구매나 계정 유형 변경으로 처리하지 않는다.

## 1. 기준 조사와 주소 설계

- 기존 로그인 모달·OAuth 훅·콜백·로그인 후 복귀 경로의 모든 호출부를 조사한다.
- 계정 프로필 및 FE/BE 인증 경계를 확인하고 마지막 공간 저장 위치를 결정한다.
- 기존 플랜·베타 한도·사용량 표시·프로젝트 생성/업로드 제한의 FE/BE 호출부를 조사한다. 공통 계정 정보와 공간별 이용 조건이 섞인 지점을 기록하고 이번 전환으로 잘못된 혜택·한도 공유가 발생하지 않도록 범위를 정한다.
- 마지막 공간은 사용자별로 구분한다. 기기 간 유지 여부, 기존 사용자에게 기록이 없는 경우, 저장 실패 시 선택 화면으로 복구하는 규칙을 구현 전 명시한다.
- 사용자 메타데이터/기존 설정 저장소를 우선 검토하고, 단순 공간 기억을 위해 불필요한 새 테이블은 추가하지 않는다.
- 소개 주소는 `/`, `/studio`, `/select`로 준비한다.
- 1차 작업 공간 주소는 `/photographer/dashboard`, `/customer-select`를 유지한다.
- 최종 작업 공간 주소는 소개 주소와 충돌하지 않는 안으로 정리하고 기존 링크·OAuth·API·SEO 영향표를 만든다. 주소 이전은 별도 후속 단계다.
- 로컬 환경의 DB·백엔드 대상, OAuth 콜백, 테스트 계정, 실행 포트를 확인한다. 실제 사용자 프로젝트를 테스트 데이터로 수정하지 않는다.

완료 기준: 이동 우선순위, 마지막 공간 저장 정책, 주소 표, 공간별 기존 이용 제한과 테스트 환경이 명시되어 있다. 요금 미정 항목과 현재 제한을 구분한다.

## 2. 최소 랜딩과 공통 진입점

- 세 랜딩에 공통 로고·공간 메뉴·로그인 진입점을 제공한다.
- 제목·설명·서비스 시작 버튼만 기존 디자인 시스템으로 구성한다.
- 로그인 상태에서는 `내 작업으로 이동`을 제공하고 동일한 이동 판단을 재사용한다.
- 프로젝트·이용 기록이 없는 계정을 위한 공간 선택 화면을 만든다.
- 기존 `/landing` 및 `/customer-select/login` 진입의 호환 방식을 정하고 연결을 보존한다.
- 공간 선택 안내는 서비스 목적만 설명한다. 미정인 가격·무료 혜택·양쪽 이용권 공유를 약속하지 않는다.

완료 기준: PC·모바일에서 세 입구를 오가며 로그인 또는 실제 작업 화면으로 이동할 수 있다.

## 3. 인증과 복귀 목적지

- 기존 `post-login-redirect`와 OAuth 콜백을 재사용하여 이동 계약을 구현한다.
- 명시적 목적지는 마지막 공간보다 우선한다. 취소한 로그인 목적지가 다음 시도에 남지 않도록 한다.
- 외부 URL·잘못된 경로를 통한 열린 리다이렉트를 막고, 인증 실패/취소 시 다시 시작할 수 있게 한다.
- 기존 작가 가입·첫 로그인 지표가 일반 로그인이나 내 사진 셀렉 진입으로 잘못 기록되지 않는지 확인한다.
- 베타 신청 등 랜딩 외 로그인 호출부의 복귀 경로를 보존한다.

완료 기준: 사용자 상태와 진입 버튼에 따라 정확한 목적지로 이동하며 인증 루프와 불필요한 대시보드 경유가 없다.

## 4. 공간 전환

- 작가 PC 사이드바·모바일 메뉴, 개인 프로젝트 목록의 적절한 메뉴에 공간 전환을 제공한다.
- 계정의 인증된 공간 진입 시 마지막 사용 공간을 갱신한다.
- 두 공간의 프로젝트 목록과 권한은 기존대로 분리한다.
- 메뉴는 `작가·스튜디오로 이동` / `내 사진 셀렉으로 이동`으로 표현한다. `플랜 전환`이나 `계정 변경`으로 표현하지 않는다.
- 기존 이용 조건·사용량 표시는 해당 공간 기준을 유지한다. 이용 제한에 걸린 경우에는 현재 정책대로 안내하고 다른 공간의 이용권으로 우회하지 않는다.
- 업로드·미저장 작업 화면에서 전환 동작이 기존 이탈 보호를 우회하지 않도록 확인한다.

완료 기준: 같은 계정으로 양쪽 공간을 이용하고 새로고침·재로그인·계정 변경 시 계약대로 복귀한다.

## 5. 로컬 검증과 문서 동기화

| 시나리오 | 기대 결과 |
|---|---|
| 기록 없는 계정의 일반 로그인 | 공간 선택 → 선택한 작업 공간 |
| 기존 계정 일반 로그인 | 저장된 마지막 공간 |
| 마지막 공간이 스튜디오인 계정의 개인용 시작 | 내 사진 셀렉으로 직접 진입 |
| 마지막 공간이 개인용인 계정의 스튜디오 시작 | 작가 대시보드로 직접 진입 |
| 로그인 상태에서 각 시작 버튼 | 인증 화면 없이 해당 작업 공간 |
| 공간 전환 후 새로고침·재로그인 | 전환한 공간으로 복귀 |
| 로그아웃 후 다른 계정 로그인 | 이전 계정 기록 미적용 |
| 작가 초대·개인 셀렉 공유·하객 링크 | 기존 인증과 해당 프로젝트 목적지 유지 |
| 보호된 상세 주소 직접 방문 | 필요한 인증 후 원래 상세 주소로 복귀 |
| 로그인 취소·실패·만료된 목적지 | 안전한 재시도, 오래된 목적지 오적용 없음 |
| 저장 실패·잘못된 마지막 공간 | 서비스 선택으로 안전하게 복구 |
| 외부 URL을 복귀 주소로 전달 | 외부 이동 거절 |
| 베타 신청 등 기존 로그인 호출부 | 기존 목적지 보존 |
| 공간 전환·일반 로그인 | 구매·구독 변경·이용권 발급·사용량 차감 없음 |
| 한쪽 공간에만 이용 자격이 있는 테스트 상태 | 다른 공간에도 진입 가능, 유료 기능 자격 자동 공유 없음 |
| 양쪽 공간의 서로 다른 사용량·한도 | 해당 공간의 정보만 표시·적용 |
| 기존 한도에 도달한 계정의 공간 전환 | 기존 제한 우회 불가, 반대 공간 한도 오차감 없음 |
| 이용권 없는 초대 참여자의 기존 링크 접속 | 기존 프로젝트 인증 유지, 새 구매 요구 없음 |
| 마지막 공간 쿠키·클라이언트 상태 조작 | 서버의 프로젝트 권한·이용 제한 변경 불가 |

- 기존 리다이렉트/콜백 테스트를 확장하여 우선순위·계정 구분·경로 검증을 확인한다.
- ESLint·TypeScript 및 관련 테스트를 실행한다.
- 실제 로컬 브라우저에서 PC·모바일 동선과 로그인 왕복을 검증한다. 테스트용 인증과 실제 OAuth 검증 결과를 구분한다.
- 이용권 유무 시나리오는 기존 모델로 표현 가능한 범위에서 테스트한다. 아직 없는 결제 상태는 테스트 전용 fixture/mock으로 이동과 권한의 분리를 검토하고 미구현으로 기록한다. 실제 결제 검증으로 보고하거나 운영 계정에 가짜 이용권을 저장하지 않는다.
- 구현이 완료된 내용만 `user-flow.md`, `architecture.md` 및 필요한 용어 규칙에 반영한다.

완료 기준: 테스트 결과와 미검증 항목이 기록되고 사용자가 로컬에서 같은 동선을 재현할 수 있다.

## 후속 단계

동선 검증 후 최종 주소로 이전하고 기존 링크의 호환 리다이렉트를 검증한다. 그다음 랜딩 디자인·마케팅 콘텐츠를 적용한다.
최초 1차 범위에서 보류했던 작업 주소 이전은 2026-10-11 후속 요청으로 로컬에 반영했다. 랜딩 비주얼 제작, 요금제 변경, 업로드/셀렉/보정 기능 개편, 운영 배포는 계속 제외한다.
요금 확정 후 공간별 구매 안내, 서버 이용 자격 확인, 사용량 차감, 결제·만료·해지 흐름을 별도 범위로 구현·검증한다. 지금의 이동 검증 완료를 결제 준비 완료로 간주하지 않는다.
