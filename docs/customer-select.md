# 셀프 고객 서비스 — 제품·구현 기준

> 고객이 A-CUT을 사용하는 작가 없이 직접 촬영본을 업로드하고, 함께 사진을 고른 뒤 외부
> 작가에게 파일명과 보정 요청을 전달하는 서비스다. 경로는 `/customer-select/**`이며 문서와
> 대화에서는 반드시 **셀프 고객 서비스**라고 부른다. 기존 `/c/[token]/**`는 **작가 고객 페이지**다.

## 1. 이 문서의 역할

이 문서는 제품 결정과 현재 구현을 함께 기록한다. **합의된 정책은 구현 완료를 뜻하지 않는다.**
현재 동작은 코드로 확인하고, 제품 방향은 사용자와 합의한 목적·정책을 기준으로 결정한다.
초기 목업이나 기존 화면의 단계·정보량을 정답으로 취급하지 않는다. 제품 설계 우선순위는 다음과 같다.

1. 일반 고객의 목적과 사용자와 합의한 정책
2. 목적을 끝까지 달성할 수 있는 사용자 흐름
3. 기존 ACUT 디자인 시스템과 같은 목적의 공통 컴포넌트
4. 실제 구현·인증·데이터 구조와의 차이
5. 초기 목업·스크래치 문서

목업은 사용자 흐름과 필요한 정보의 참고 자료일 뿐, 레이아웃·카드·모달·헤더·푸터를 새로
만드는 근거가 아니다. 같은 목적의 ACUT 화면이 있으면 그 화면과 컴포넌트를 먼저 재사용하고,
API 계약이나 권한 모델이 달라 재사용할 수 없는 부분만 셀프 고객용으로 분리한다.

## 2. 제품 정의

셀프 고객 서비스의 사용자는 사진을 맡긴 고객이면서 프로젝트 소유자다. 고객은 촬영본을 직접
보유하고 있으므로 A-CUT은 셀렉과 의사소통에 필요한 썸네일·프리뷰만 관리한다.

### 2.1 확정된 출시 정책 (2026-09-22)

1. 로그인하고 프로젝트를 만든다.
2. 한 계정의 모든 프로젝트를 합해 최대 2,000장의 셀렉용 사진을 저장한다. 사진이나 프로젝트를
   삭제하면 삭제한 사진만큼 업로드 한도가 복구된다.
3. 소유자는 직접 고르고, 공유 참가자는 개인 찜·별점을 남긴다. 작가 전달 메모는 모두 함께 수정하며 최종 선택은 소유자가 결정한다.
   함께 고르는 인원은 소유자를 포함해 색상 슬롯 수와 같은 최대 5명이다.
4. 목표 장수는 참고용이다. 목표 미달·초과를 이유로 확정·전달을 막지 않는다.
5. 소유자는 현재 선택 결과를 읽기 전용 링크나 파일로 외부 작가와 공유한다. 링크 복사는 완료 상태를
   만들거나 선택을 잠그지 않으며 같은 링크에는 항상 최신 결과가 반영된다.
6. 보정본 검토는 선택적으로 연결하는 후속 기능이다.

프로젝트 생성 시 촬영 종류는 필수이며, 촬영일·스튜디오/업체·담당 작가·촬영 지역·장소는
선택 입력으로 시작한다. `target_count`는 일반적인 참고 목표가 아니라 외부 작가와 약속한
보정 장수이며, 실제 선택 장수가 달라도 전달을 막지 않는다. 입력 원문은 향후 통계·사업 분석의
기초 데이터로 보존하고 업체/장소 표준화는 별도 정책이 정해질 때 추가한다.

기존 공통 찜·의견 갈림 필터는 유지한다. 추가 후보 정리 기능은 마지막 위치 이어보기만 첫 출시
범위로 두고, 별도 고민 중 상태와 두 장 비교는 구현하지 않는다. 임시 대화와 가입 없이 보는
작가용 읽기 전용 결과 링크는 첫 출시 범위로 둔다.
한 번 눌러 같은 사진을 여는 기능은 구현됐으며, 화면을 계속 따라가는 기능은 실제 사용 필요를
확인할 때까지 후속으로 보류한다.

정확한 요금·상품 구성은 미정이다. 현행 상한은 BE `MAX_PHOTOS_PER_CUSTOMER_ACCOUNT = 2000`이며,
업로드 한도와 선택 목표는 별개로 안내한다. 신규 흐름의 작업 순서·검토안은
[출시 작업 계획](customer-select-release-plan.md)을 따른다.

지인 초대 링크(`/customer-select/[projectId]/select?share_token=...`)는 공유 토큰을 쿠키로 교환하고 `?invite=1`로 진입한다. 이때 `GET /api/customer-select/projects/[id]/invite-cover`가 대표 사진 URL만 먼저 조회해 전체 프로젝트 상태 조회와 병렬로 이미지를 받는다. 서버는 같은 공유 쿠키/소유자 인증을 검사하며, 첫 AI 장면 가운데 컷(없으면 첫 사진)을 사용한다. 초대 화면은 전체 상태가 준비된 뒤 표시하고, 대표 사진이 로드될 때까지 플레이스홀더를 유지한다.

### 2.1.1 AI 장면 정리 흐름 (2026-10-01 합의, FE 시안 구현)

AI 장면 정리는 이 서비스의 핵심 차별점이다. 분석에는 시간이 걸리므로 그동안에도 셀렉은 멈추지 않는다.

- AI 정리는 **사용자가 시작할 때만** 돈다. 원본 그대로 보고 싶거나, 사진을 더 올린 뒤 정리하고 싶은 경우를 위해서다.
  업로드가 끝나면 `원본 그대로 고르기` / `✨ AI로 정리하고 고르기` 두 갈래를 제안하고("사진을 다 올렸다면"), 고르기 화면에서는
  정리 전 원본 시간순 보기에 소유자만 보는 `AI로 장면 정리` 버튼을 둔다. 참여자에게는 시작 버튼이 없다.
- 시작하기로 한 뒤에만 `AI로 사진 정리` 시트에서 세부 항목을 보여준다. 장면별로 나누기(항상 켬), 비슷한 사진 묶기·흔들림·눈 감음 확인(기본 켬, 끌 수 있음 — 켜고 시작하면 고르기 화면이 `흔들림 사진 빼기`를 켠 채 시작, 기기별 기억). 대부분은 `정리 시작` 한 번이면 된다. 요청한 작업 중 하나라도 시작하지 못하면(2xx·409 외) 시트에 그 항목 이름을 보여준다(`…을(를) 시작하지 못했어요. 나머지는 진행 중이에요.`) — 다시 누르면 진행 중인 작업은 409로 넘어가고 실패한 작업만 다시 시작된다(`startAiTidy`). 방금 시작한 작업은 첫 상태 조회 전에 끝나도 프로젝트를 다시 읽는다.
  2026-10-03부터 항목마다 따로 실행한다(`customer_ai_runs.kind` = `scene` | `similarity` | `quality`, 마이그레이션 `20261003010000_customer_scene_run_kind.sql`) — 장면은 전체 사진 임베딩을 기다리지 않고, 끈 항목은 돌지 않는다(유사컷을 끄면 임베딩도 안 함). 프로젝트·종류별 진행 중 실행은 하나만(부분 UNIQUE 인덱스, 겹치면 409 + 현재 `run_id` — FE는 "이미 정리 중"으로 이어 보여줌). 장면 실행 요청에 촬영 종류의 장면 이름 목록(`customerSceneCatalog`)과 경계 공백(`customerSceneGapSeconds` → `scene_gap_seconds`, 30~1800초, 없으면 3분 — 2026-10-05부터 홈스냅만 75초: 방을 옮길 때 1~2분만 쉼. 장면 상한은 사진 40장당 1개(최소 8·최대 30, 규칙 `gap-v3`) — 고정 8개는 1,572장 홈스냅에서 막혔다)을 함께 보내면 clip-service `run_scene`이 촬영 시각 공백으로 장면을 나누고(FE `splitScenes`와 같은 규칙, `clip-service/app/scenes.py`) 장면마다 대표 사진 3장(`pick_samples` — 이미 판정된 흔들림·초점·눈 감음 likely 사진은 빼고, 같은 유사컷 묶음은 한 장만, 앞·중간·뒤 고르게)을 Gemini Flash-Lite에 보내 목록 중 이름과 확신 여부(`confident`)를 받는다(맞는 게 없거나 확신이 없으면 `기타 장면`, 바로 붙은 장면의 이름이 같고 사이 공백이 10분 미만이면 한 장면으로 합친다 — 시간 공백이 한 장면을 잘못 나눈 경우. 그 전에 장소를 알 수 없는 작은 장면(`기타 장면`·`클로즈업·디테일`, 20장 미만)은 공백이 더 짧은 이웃 장면(10분 미만)에 붙여 그 이름을 따른다 — `absorb_placeless`, 배경 없는 디테일 컷은 같은 사진에도 Gemini 답이 흔들림). 이름 붙이기를 다 끝낸 뒤에 기존 장면을 교체해 도중에 재시작돼도 기존 장면은 남는다. 실행마다 쓴 설정(기준값·이름 목록·모델·프롬프트 버전 `SCENE_NAME_PROMPT_VERSION`·규칙 버전 `SCENE_ALGORITHM_VERSION`)을 `customer_ai_runs.settings`에 남긴다. 결과는 `customer_scenes`와 `customer_photos.scene_id`(마이그레이션 `20261001010000_add_customer_scenes.sql`)에 저장하고 프로젝트 조회가 `aiScenes`로 내려준다 — 장면 테이블을 읽지 못하면 장면 없이 내려줘 조회는 깨지지 않는다. 사진 내용으로 경계를 보정하지는 않는다(같은 홀의 다른 장면을 잘못 합칠 수 있고, 실제 촬영 데이터로 기준값을 정해야 함). `비슷한 사진 묶기`는 고르기 화면의 묶어 보기 기본값으로 쓴다.
- 다시 정리: 정리한 프로젝트에서 소유자는 `보기 옵션` 패널의 `AI 다시 정리`로 시트를 다시 연다(정리 뒤 새로 올린 사진 수를 함께 보인다). 정리 뒤 새로 올린 사진은 다시 정리하기 전까지 마지막 `새로 올린 사진` 장면에 모인다. clip-service는 이미 저장된 임베딩·품질 판정을 재사용해 새 사진만 Gemini를 부르고, 유사컷·장면은 전체를 다시 계산한다(장면 이름 호출은 장면 수만큼). 각 작업이 끝날 때마다 프로젝트를 다시 읽어 장면은 유사컷·흔들림을 기다리지 않고 먼저 보인다. 고른 사진·찜·메모는 사진에 붙어 있어 그대로다. 이 화면에서 정리가 끝나면 프로젝트를 다시 읽어 새 결과를 보인다.
- 장면 정리 중에는 장면 없이 **촬영 시간순 전체 사진**으로 고른다(1차 훑어보기). 상단에 진행 상태와 "그동안 ♡를 눌러 두세요" 안내를 둔다. 진행 수는 clip-service가 실행 중 `customer_ai_runs`에 기록하고(장면은 이름 붙인 장면 수, 유사컷·흔들림은 사진 수 — 5장마다, 기록할 때 `updated_at`도 갱신), 화면은 진행 중인 작업을 한 줄씩(`장면 이름 붙이는 중 · 3 / 6`, `비슷한 사진 묶는 중 · 840 / 2,000장`, `흔들림·눈 감음 확인 중 · …장`) 보이고 막대는 장면 진행만 따른다(`taskProgressText`, `useSceneAnalysis.ts`). 장면이 끝난 뒤 남은 작업은 장면 목록 아래 한 줄로 보이고, 실패하거나 일부(`failed_count > 0`) 처리하지 못하면 `… 실패 · 다시 시도`/`… N장 못 함 · 다시 시도`로 알린다. 살아 있는 실행은 60초마다(`HEARTBEAT_SECONDS`) `updated_at`을 갱신하고(Gemini 응답이 느리거나 동시 실행 자리를 기다리는 동안에도), 마지막 갱신 뒤 10분(`STALE_RUN_SECONDS`) 넘게 멈춘 실행(서비스 재시작 등)은 실패로 닫는다. 모든 실행은 Gemini를 부르기 전·결과를 쓰기 직전에 아직 현재 실행인지 확인해(`_ensure_running`), 닫혀 대체된 실행은 비용을 더 쓰지 않고 멈춘다. 사진을 내려받는 실행(유사컷·품질)은 40장씩(`BATCH_PHOTOS`) 내려받기 → 판정 → 저장하고, 프로세스당 2개(`CUSTOMER_AI_HEAVY_RUNS`, env)까지만 동시에 돌며 나머지는 기다린다(메모리 상한 ≈ 2 × 40장). 품질 판정을 마치면 현재 모델·프롬프트가 아닌 판정을 지워 사진마다 한 행만 남긴다.
- 분석이 끝나면 보던 화면을 바꾸지 않고 `장면별로 보기`를 제안한다. 들어오기 전에 끝났으면 바로 장면 보기로 시작한다.
- 장면은 항상 **시간 순서대로 이어진 구간**이다. AI는 경계와 이름만 정하고 순서는 바꾸지 않는다. 내용 기준 묶음(신부 단독 등)은 장면이 아니라 후속 보기 조건으로 다룬다.
- 사진 상세의 좌우 이동은 장면 끝에서도 이어진다. 다음/이전 장면에 현재 보기 조건과 맞는 사진이 있으면 상세를 닫지 않고 첫/마지막 사진으로 넘어가며, 빈 장면은 건너뛴다. 장면 이름을 잠깐 표시하고 주소 `?scene=N`과 마지막 장면 기록도 갱신한다. 전체 목록 모드와 마지막 장면 끝에서는 기존처럼 멈춘다.
- `/review`의 선택 사진 상세도 화면에 표시된 장면 순서대로 이어진다. 상세를 열 때 선택 사진 목록을 고정하고 장면 경계를 넘으면 다음/이전 장면 이름을 잠깐 표시한다. 선택 사진이 없는 장면은 목록에서 빠진다.
- 장면 이름은 촬영 종류별 목록(`src/lib/customer-shoot-scenes.ts`) 안에서만 고르고, 없으면 `기타 장면`. 홈스냅(`home_snap`)은 인물 구성이 아니라 집 안 장소(거실·침실·아기방·야외 등)로 이름을 붙인다. 시간대는 보조 정보로 함께 표시한다.
- 분석 실패·미사용이면 촬영 시각 공백으로 나눈 시간 장면(이름 없음)으로 대체하고, 소유자에게 `AI 정리 다시 시도`를 보여준다.
- 사진이 100장 미만(`MIN_PHOTOS_FOR_SCENES`, FE·BE 같은 값)이면 장면을 나누지 않고 촬영 시간순 전체 보기로 둔다(2026-10-05, 20장→100장 — 골라낸 사진만 올리면 사진 간격이 몇 분씩이라 시간 공백으로 장소 경계를 못 찾음). AI 정리 시트의 `장면별로 나누기`는 꺼진 채 `사진이 100장 이상일 때 장면으로 나눠요`를 보인다. 장면 실행 요청은 그대로 보내 정리 상태 흐름은 같고, clip-service가 장면 없이 바로 끝낸다(Gemini 호출 없음).
- 찜·선택은 사진에 붙어 있어 화면 구조가 바뀌어도 유지된다. 장면 목록에는 `N장 골랐어요`만 보여준다(분수·추천 장수 없음 — '추천 사진 중 N장'으로 오해)(찜 수는 카드의 ♥에서 본다).
- **한 번에 한 장면**을 본다(장면 개요 화면은 없음). 진입하면 주소 `?scene=N` → 이 탭에서 마지막으로 본 장면 → 아직 덜 고른 첫
  장면 순서로 시작한다. 장면 끝에서는 브라우저 스크롤이 스스로 멈추고, 끝에 다음 장면 이름만 얇게 보인다("↓ 다음 예식").
- 장면 끝에서 **쭉 당기면 다음 장면**으로 넘어간다(`SceneGrid`). 당기는 만큼 화면이 고무줄처럼 위로 끌리며(점점 덜 늘어남)
  아래에서 다음 장면 이름과 진행 원이 드러나고, 원이 다 차면(62%) 다음 장면이 아래에서 올라오듯 바뀐다(휠은 다 차는
  순간 바로, 터치는 손을 뗄 때). 덜 당기고 놓으면(휠은 0.35초 멈춤) 제자리로 돌아간다. 휠은 바닥에 0.25초 머문 뒤, 잠깐
  쉬었거나 느려지지 않는(10px 이상) 휠만 당김으로 인정한다 — 관성 스크롤은 계속 느려지기만 해서 넘어가지 않고, 이어서 굴리는
  트랙패드·마우스는 쉬지 않아도 잡힌다. 한 칸이 작은 마우스 휠도 한 번에 최소 20px씩 당긴다. 새 장면으로 넘어온
  뒤에는 휠이 한 번 쉬어야(0.14초) 다음 당김이 시작돼 한 번의 스크롤로 여러 장면을 건너뛰지 않는다. 터치는 장면 끝에 멈춘 뒤
  새로 댄 손가락으로만 당긴다. 위로도 같은 고무줄이다(2026-10-02): 장면 맨 위에서 더 올리면 위쪽이 늘어나며 이전 장면 이름(↑)이
  드러나고, 충분히 당기면 이전 장면의 끝으로 넘어가 위에서 내려오듯 들어온다(덜 당기면 제자리, 장면이 바뀐 직후 0.12초는 위 당김을 시작하지 않음). 갤러리는 `overscroll-behavior: contain`이라 모바일 당겨서 새로고침과 겹치지 않는다. 마지막 장면 끝에는
  소유자 `선택 완료 →`(검토 화면으로 이동), 참여자 `다 골랐어요`. 조정값: `PULL_MAX`, `PULL_RESISTANCE`, `PULL_TO_PASS`.
- 장면 목차: PC는 왼쪽 **장면 사이드바**(장면 이름·장면별 고른 수, 지금 장면 강조, 전체 고른 수, 대화)이고, 접기 버튼으로 접으면
  왼쪽 가운데 **점 메뉴**로 바뀐다(장면마다 점: 지금 장면 강조 링, 다 고른 장면 초록, 일부 고른 장면 진한 점). 마우스를 올리거나
  키보드로 들어가면 장면 이름·고른 수가 펼쳐지고, 점을 누르면 그 장면으로 간다. 맨 위 아이콘으로 사이드바를 되돌리고 맨 아래에
  대화가 있다(접힘 상태는 기기에 기억). 모바일은 처음부터 하단 위에
  떠 있는 퀵메뉴(● 장면 이름 · N/전체 ▲, 대화) → 장면 시트. 대화 버튼은 퀵메뉴 안으로 옮겼다
  (`EphemeralChat`의 `open`/`onOpenChange`). AI 정리 실패 시 장면 목록에 `AI 정리 실패 · 다시 시도`가 보인다.
- 사진 로딩·위치는 작가 고객 갤러리와 같은 규칙을 따른다: 같은 `GalleryPhotoCard`·`createThumbLoadQueue(12)`, 화면 2.5개 분량
  미리 렌더(overscan), 상세 보기를 닫으면 마지막으로 본 사진(접힌 유사컷이면 그 표지)이 화면 밖일 때 가운데로 스크롤,
  새로고침 시 마지막 사진 행 복원.

현재 구현: 분석 상태는 `useSceneAnalysis`(select/useSceneAnalysis.ts)가 기존 유사컷 분석 상태 API(`ai/similarity`)를 5초마다
조회해 판단한다. **AI 장면 경계·이름을 만드는 BE/clip-service는 아직 없다**(엔진은 FE 확정 후 결정). 개발 환경에서는
`?mockAnalysis=none|analyzing|ready|failed|off`로 상태를 확인할 수 있고(같은 탭 세션에 기억), ready는 시간 장면에 목록 이름을
순서대로 붙인 시안이다. 테스트 사진이 한 번에 찍혀 시간 장면이 2개 미만이면 시안 모드에서만 12장 안팎씩(최대 6개) 순서대로
잘라 장면을 만든다. 시안 완료 상태(ready)에서는 유사컷·품질 화면 확인용으로 8장마다 앞 3장을 유사컷으로 묶고, 11장마다 흔들림, 13장마다
눈 감음 의심을 붙인다(실제 고객 분석은 clip-service `/analyze/customer/{kind}`가 BE `feature/customer-select` 브랜치에만 있어 배포 서비스에서는 404).

촬영 종류(2026-10-01): 웨딩 본식 · 웨딩 촬영 · 돌·백일잔치 · 가족·베이비 · 커플·스냅 · 졸업·기념 · 프로필·증명 · 기타.
작가 프로젝트의 촬영 종류와 별개이며, 이전 셀프 고객 값 중 새 목록에 없는 `wedding`은 호환용으로 계속 허용한다(장면 목록 없음).

고르기 화면 좌우 여백(2026-10-02): 사진 그리드 최대 너비 제한(1392px)을 두지 않고 남는 폭을 열로 채운다. 툴바·장면 제목·인물 칩·안내의 왼쪽 시작선은 사진과 같게 — 장면 목록을 펼치면 24px, 접으면 76px(왼쪽 가운데 점 메뉴 자리, PC만).

하단 바 버튼 기준(2026-10-02): 셀프 고객 화면의 하단 바(고르기 `bottomBar`, 업로드·완료·보정본 업로드·비교·내보내기·프로젝트 만들기·설정의 `PhotographerPageActionBar`/`PhotographerFormActionBar`) 버튼은 모두 `PhotographerLightButton size="work-panel"`(높이 48px, 14px 굵게)로 통일한다.

사진 칸 기준(2026-10-02, `src/app/customer-select/_lib/photo-grid.ts`): 사진을 훑어보는 갤러리(업로드·고르기·결과 보기)는 정사각형·모서리 8px(고르기는 공용 카드 4px를 셀렉 화면 안에서만 8px로), PC 최소 180px·간격 12px, 모바일 3열·간격 8px. 예외 — 고르기는 모바일 2·4열을 보기 옵션으로 고를 수 있고(2열은 4:3), 결과 보기는 파일명·작가 전달 메모를 읽도록 모바일 2열. 검토 화면의 고른 사진 목록은 요약 썸네일(정사각형 112px·간격 8px). 업로드는 작가 공용 갤러리(`OriginalPhotoGallery`)에 `squareMedia`·`minCellWidth`를 넘겨 맞추며, 작가 화면은 기존 크기(3:2, 218px) 그대로다.

### 2.2 현재 구현과의 차이

- 현재 전달은 텍스트 복사, CSV(파일명·참여자 의견), TXT(파일명 목록) 다운로드와
  완료·다시 선택 상태를 지원한다.
- 현재 참여자 식별은 색 슬롯에 연결되어 있다. 선택 상태 동기화에는 그대로 사용하되, 접속 상태·
  따라가기처럼 한 참여자의 여러 세션을 구분해야 하는 기능 전에 세션 식별자를 추가한다.

### 명시적 비범위

- 납품용 원본 업로드·원본 아카이브·원본 복구
- 작가 계정, 작가 등급, 작가별 업로드 쿼터
- 작가 추천 사진과 작가 초대 생애주기
- 기존 `projects`/`photos` 상태 머신에 셀프 고객 프로젝트를 편입하는 것

셀프 고객의 사진은 언제나 **셀렉용 사진**이다. UI·API·문서에서 이를 작가 화면의 “납품용
원본”과 혼용하지 않는다.

## 3. 화면 설계 원칙

### 3.1 디자인은 공유하고 흐름은 일반 고객에 맞춘다

기존 컴포넌트 재사용은 시각·조작의 일관성을 위한 것이다. 작가용 폼의 항목 수나 페이지 순서를
그대로 복제할 의무는 없다. 한 화면의 주요 행동을 명확히 하고, 고급 기능·선택 입력은 점진적으로
노출한다. 큰 화면 변경은 간단한 와이어프레임 검토 후 구현한다.

- 로그인·프로젝트 목록·프로젝트 생성: Photographer Light의 셸, 폼, 버튼, 액션바를 따른다.
- 사진 업로드·관리: 작가 원본 업로드의 작업면, 가상화 갤러리, 선택·삭제, 정렬, 뷰어,
  헤더 축소, 하단 고정 액션바를 따른다.
- 사진 셀렉: 작가 고객 페이지의 셀렉 갤러리 카드, 필터, 상세 뷰어, 확정 풋터를 따른다.
- 보정본 검토: 작가 고객 페이지의 보정본 검토 카드·상세 비교·판정 UI를 따른다.
- 확인 모달·버튼·배지·빈 화면은 기존 공통 컴포넌트를 사용한다.

셀프 고객 전용 컴포넌트는 인증 문구, 참가자 상태, 외부 작가 전달 등 도메인 차이가 있는 경우에만
허용한다. 기존 컴포넌트를 복사해 이름만 바꾸지 않는다.

### 3.2 페이지 폭과 좌우 여백

- 모바일 바깥 여백은 `20px`, PC는 `32px`를 기본으로 한다.
- 셀프고객 전역 헤더는 최대 폭을 두지 않고 로고와 계정 영역을 각각 화면 좌우의 기본 여백에 고정한다.
- 사진 작업 화면은 전역 헤더 안에 브랜드·프로젝트명·전체 이용량을 한 줄로 합치고 별도 프로젝트 행을 두지 않는다. 모바일은 진입할 때부터 `48px`의 `A` 마크·프로젝트명만 표시하며, PC는 스크롤할 때 같은 높이로 줄인다.
- 프로젝트 현황·검토·전달·완료 같은 일반 화면은 최대 `1120px`를 사용한다.
- 생성·설정 폼의 입력 영역은 최대 `840px`를 사용한다.
- 프로젝트 목록·결과처럼 정보량이 많은 일반 화면은 최대 `1504px`를 사용한다. 업로드·셀렉 갤러리는 2,000장 탐색 효율을 위해 최대 폭 제한을 두지 않는다. 셀렉 격자는 작가 고객 갤러리와 같은 PC `24px`, 모바일 `20px` 여백과 고객 라이트 토큰을 사용한다.
- 로그인 카드·오류 안내처럼 내용 자체가 짧은 화면은 더 좁을 수 있지만 바깥 여백 기준은 유지한다.

### 3.3 대량 사진 작업면

- 계정의 모든 셀프 고객 프로젝트 합산 상한은 **2,000장**이다. 관리자(`ADMIN_EMAILS`) 계정은 무제한이다
  (FE 이용량 `limit: null`, BE 검사·DB 트리거 모두 건너뜀 — 트리거는 마이그레이션 `20261005000000_customer_photo_limit_admin_bypass.sql`, 2026-10-05 운영 DB 적용. 관리자 목록이 바뀌면 이 함수도 다시 만든다).
- PC에서는 사진 작업면이 가용 폭을 사용하며 모바일 폭 카드로 제한하지 않는다.
- 상단 헤더·도구와 하단 주요 행동은 고정하고 갤러리만 독립 스크롤한다.
- 모바일 업로드 도구는 사진 수·AI·검색/정렬·선택을 한 줄에 두고, 파일명 검색과 정렬 옵션은 공통 바텀시트에서 필요할 때만 연다.
- 갤러리는 가상화하고, 화면 근처 이미지만 제한된 동시성으로 로드한다.
- 모바일 사진 추가 셀은 작가 업로드와 같은 공통 `PhotoUploadTile`을 사용해 대기·진행·서버 처리 상태를 동일하게 표시한다.
- 업로드는 20장씩 `압축 → 전송`해 전체 압축 결과를 메모리에 쌓지 않는다.
- 파일명은 검색·정렬 또는 상세 식별에 필요한 곳에서만 표시한다.
- 업로드 전에 현재 장수 기준 남은 한도를 확인하고, 실패·제외된 파일은 이름을 보존해 해당
  파일만 다시 시도할 수 있게 한다.

AI 장면이면 장면 이름을, 시간 장면이면 시간대를 제목으로 쓴다. 목표 장수는 장면 사진 수 비율로 나눠 `N / M장 정도`로만 안내하며 막지 않는다. 카드의 자리는 역할과 상관없이 같다 — 왼쪽 위 ✓는 최종 선택(소유자만 누르고, 참여자는 소유자가 고른 사진에 ✓ 표시만 본다), 왼쪽 아래 `♥ N`은 찜(누르면 내 찜을 켜고 끈다, 내가 찜했으면 주황으로 채움, 숫자는 찜한 사람 수·나 포함, 마우스를 올리면 이름). 찜이 있으면 `♥ N`이 늘 보이고 없으면 PC에서 마우스를 올렸을 때만 빈 ♡가 보인다. 터치 기기에서 참여자(찜이 메인 동작)는 빈 ♡도 늘 보이고 누를 수 있고, 소유자는 표시만 하며 찜은 상세에서 한다. 찜한 사람 색 점은 카드에 쓰지 않는다(누가 찜했는지는 이름 툴팁·상세). 카드 체크로 선택하는 순간에만 체크가 톡 튀고 주황 테두리가 안쪽으로 번졌다 사라진다(0.24~0.36초, 해제·동기화·다시 그려질 때는 없음, 모션 줄이기 설정이면 생략). 유사컷 묶기가 켜져 있으면 묶음은 표지 한 장(고른 사진이 있으면 그 사진)으로 접히고, 표지는 뒤에 카드가 겹친 모양에 오른쪽 아래에 `⧉ N ▾` 펼치기 배지가 있고, 묶음 안에 고른 사진이 있으면 ✓ 자리(왼쪽 위)에 주황 `✓ M`을 둔다. 카드 아래쪽 그라데이션은 사진 위·배지 아래에 깔아 배지·글자가 어둡게 덮이지 않는다. 묶음 표지는 왼쪽 아래에 표지 사진의 찜(`♥ N`, ✓처럼 표지 한 장 — 바로 찜할 수 있음, 2026-10-02), 오른쪽 아래에 `⧉ N ▾`를 두고 표지 한 장의 메모 표시는 숨긴다. 카드 위에는 ## 5. 데이터 모델

작가 프로젝트와 소유권·인증·보관 정책이 다르므로 데이터는 분리한다.

- `customer_projects`: 소유자, 프로젝트 정보, 목표 장수, 사진 수, 공유 토큰, 보정 완료 플래그
- `customer_projects.sharing_enabled`: 현재 공유 토큰의 활성 여부. 중지하면 기존 쿠키도 거부
- `customer_projects.lifetime_uploaded_count`: 삭제와 무관한 프로젝트 누적 성공 업로드 장수. 계정별
  합계는 현재 저장 한도와 별개로 유료 정책·반복 사용 분석에만 사용
- `customer_projects.exported`, `delivery_count`, `last_delivered_at`: 이전 전달 완료 흐름의 호환 필드이며
  현재 셀프고객 UI·링크 복사·프로젝트 상태에는 사용하지 않는다.
- `customer_projects` 촬영 분석 필드: `shoot_type`(필수 입력), `shoot_date`, `studio_name`,
  `photographer_name`, `shoot_region`, `shoot_location`(선택 입력)
- `customer_photos`: 셀렉용 썸네일·프리뷰, 원본 파일명, 표시 순서, 유사컷 그룹, 원본 촬영 시각(`taken_at`, 장면 구분용)
- `customer_selections`: 소유자 최종 선택, 참가자별 찜 색상, 사진당 하나의 공용 작가 전달 메모
- `customer_participant_opinions`: 사진별 참가자 개인 별점. `comment`는 공용 메모 전환 전 호환용 레거시 필드
- `customer_project_participants`: 비로그인 참가자의 색 슬롯·닉네임·완료 여부
- `customer_participant_presence`: 참여자별 최근 heartbeat 시각. 30초 이내 갱신된 참여자를
  온라인으로 표시하며 프로젝트·참여자 삭제 시 함께 정리
- `customer_photo_versions`: 사진별 보정본 회차와 확정·재보정 결정
- `customer_ai_runs`, `customer_ai_embeddings`, `customer_photo_groups`,
  `customer_quality_assessments`: 셀프 고객 사진의 장면·유사컷·품질 분석(`customer_ai_runs.kind` = scene·similarity·quality,
  `settings` = 그 실행의 AI 설정, `updated_at` = 마지막 진행 기록, `usage` = 장면 이름·품질 판정의 Gemini 토큰 합계
  `{calls, prompt_tokens, output_tokens, thinking_tokens, total_tokens}` — 마이그레이션 `20261003020000_customer_ai_run_usage.sql`)

모든 테이블은 RLS를 켜고 브라우저에서 직접 쓰지 않는다. Next.js API 또는 BE가 service role로
처리한다. 참가자별 찜 변경은 `toggle_customer_selection_color` RPC로 원자 처리한다.

## 6. 인증·권한

- 소유자는 Supabase Auth의 Google/Kakao 로그인을 사용한다.
- 대시보드 계정 표시는 Supabase Auth의 `user_metadata` 이름·프로필 이미지와 이메일·provider를
  읽어 사용한다. 현재는 셀프 고객 전용 프로필 테이블이나 추가 개인정보를 만들지 않는다.
- 참가자는 계정 없이 공유 링크로 접근한다. `share_token`은 최초 진입 요청에서만 사용하고,
  미들웨어가 프로젝트와 토큰을 검증한 뒤 프로젝트별 `HttpOnly`, `SameSite=Lax` 쿠키로 교환한다.
- 토큰 교환 직후 같은 화면의 `share_token` 없는 URL로 리다이렉트하며, 이후 화면 이동과 API
  요청에는 토큰을 쿼리나 요청 본문으로 전달하지 않는다.
- 공유 링크 복사와 원문 토큰 조회는 프로젝트 소유자에게만 제공한다.
- 공유 중지는 현재 토큰을 비활성화하고, 재발급은 새 토큰으로 교체한다. 두 작업 모두 기존 링크와
  발급된 참여자 쿠키를 즉시 무효화하지만 참가자의 찜·별점·의견 기록은 삭제하지 않는다.
- 참가자 색 슬롯은 브라우저의 `acut:customer-select:identity:{projectId}`에 저장한다.
- 최초 참가자는 닉네임과 아직 사용하지 않은 색을 직접 고른다. 색 선점은 DB의
  `(project_id, color)` 고유 키로 동시에 요청해도 한 명만 성공하며, 5개가 모두 사용 중이면 입장을 막는다.
- 새 기기에서는 초대 화면의 `이어서 참여하기`에서 기존 닉네임·색을 선택해 같은 참여자로
  복원한다. 별도 인증번호 없이 공유 링크를 가진 가까운 참여자끼리 사용한다는 현재 인증 강도를 따른다.
- Next.js API는 소유자 세션 또는 프로젝트별 공유 쿠키의 유효한 토큰을 검사한다.
- 공유 참가자는 본인 색 슬롯의 찜·별점·완료 상태와 사진별 공용 작가 전달 메모를 변경한다.
  최종 선택·최종 검토·전달 상태 변경은 소유자만 가능하다.
- 사진 업로드·삭제·보정본 관리는 소유자 JWT만 허용한다. 공유 토큰은 셀렉 협업 권한으로만 사용한다.
- 작가용 결과 링크는 협업 토큰과 분리된 HMAC 서명 토큰을 최초 접속에서만 사용한다. 검증 뒤
  프로젝트별 HttpOnly 쿠키로 교환하고 토큰 없는 결과 URL로 이동한다. 결과 권한은 읽기 전용이며
  `exported=true`인 최신 결과에만 유효하다.
- 협업 상태 동기화도 소유자 세션 또는 공유 쿠키를 검사하는 전용 API를 통한다. 브라우저에
  service role이나 공개 DB 읽기 권한을 주지 않는다.

공유 토큰은 참여 링크이지 강한 본인 인증 수단이 아니다. 유출이 의심되면 설정에서 공유를
중지하거나 링크를 재발급한다.

## 7. 업로드·삭제·AI

- 셀렉용 이미지는 브라우저에서 1600px/0.82 JPEG 수준으로 축소한 뒤 20장 단위로 전송한다.
- BE는 썸네일과 프리뷰만 R2에 저장하고 `customer_photos`를 만든다.
- 파일 드롭, 개별 체크, 빈 영역 드래그 선택, `Cmd/Ctrl+A`, `Delete/Backspace`, `Esc`를 지원한다.
- 모바일은 항상 보이는 체크박스로 사진을 선택·삭제한다. PC·모바일 모두 파일명 검색을 제공하고,
  기본 격자에서는 파일명을 숨겨 사진 밀도를 확보한다.
- FE는 계정 전체 2,000장 상한을 업로드 전에 확인한다. 전송은 20장(`BATCH_SIZE=20`)씩 처리하며 중단 시
  현재 배치 이후 파일, 서버가 거절한 파일은 다시 시도 목록으로 유지한다. 같은 파일을 다시
  선택할 수 있도록 파일 입력값은 선택 직후 초기화한다.
- 첫 배치 완료 후 최근 3개 배치의 `압축+전송` 시간과 장수를 가중 평균해 예상 남은 시간을
  계산한다. 첫 배치 전에는 `예상 시간 계산 중`, 이후에는 분 단위의 완화된 시간을 표시한다.
- FE는 파일 선택·드롭·재시도 직전에 계정 전체 사진 수를 갱신한다. 선택 파일 전체가 남은 한도를
  초과하면 전송하지 않고 선택/가능 장수와 `파일 다시 선택`을 표시한다.
- BE `POST /api/customer-upload/photos`도 요청 파일 수가 남은 한도를 초과하면 요청 전체를
  `limit_exceeded`로 거절한다. 일부 파일을 자동으로 잘라 업로드하지 않는다.
  DB 트리거는 같은 소유자의 동시 업로드를 직렬화하고 실제 사진 행 합계가 2,000장을 넘는 배치를
  롤백해 여러 프로젝트에서 동시에 올려도 한도를 넘지 않게 한다.
  형식 오류와 이미지 처리 실패 파일은 배치 내 위치 `rejected_indices`(와 표시용 `rejected` 파일명)로 돌려준다.
  FE는 위치로 원본 파일을 찾고 `uploaded`와 함께 확인하며 실패가 있으면 AI 제안보다 재시도를 먼저 표시한다.
- FE는 압축 전 원본 파일명(`original_filenames`)과 사진마다 고정된 `client_upload_ids`(UUID)를 함께 보낸다.
  BE는 이 UUID를 `customer_photos.id`로 그대로 쓰고, 이미 저장된 ID는 처리 없이 성공으로 세며 동시 재시도는
  `ON CONFLICT DO NOTHING`으로 건너뛴다 — 프록시 시간 초과·응답 유실 후 재시도해도 중복 사진이 생기지 않는다.
  `photo_count`는 업로드·삭제 모두 실제 사진 행 수로 다시 센다.
- 삭제 전 최종 선택·찜·별점·의견·AI 분석·보정본의 연쇄 삭제 건수를 확인창에 표시한다.
  확정하면 사진 행의 cascade 데이터와 썸네일·프리뷰·보정본 R2 객체를 정리한다.
- 한 번이라도 전달한 프로젝트(`delivery_count > 0`)는 다시 선택 중이어도 사진 추가·삭제를
  잠근다. 프로젝트 자체 삭제와 선택 기능인 보정본 업로드는 이 잠금 대상이 아니다.
- 성공 업로드 장수는 현재 보유 사진 수와 별도로 누적한다. 삭제 후 재업로드해도 누적값은
  줄지 않지만, 실제 유료화 전에는 프로젝트 삭제·재생성을 포함하는 계정 단위 사용량 원장이 필요하다.
- 업로드 완료 후 `AiAnalysisPromptModal`에서 유사컷 또는 눈 감음·흐림 분석을 선택한다.
- 완료 모달을 닫은 뒤에도 업로드 헤더의 `AI 분석` 버튼으로 다시 열 수 있다.
- AI 모델 호출과 그룹핑 알고리즘은 clip-service의 기존 구현을 재사용하지만 결과 테이블은 작가
  프로젝트와 분리한다.

### 7.1 공동 선택 동기화

- 활성 화면은 `/api/customer-select/projects/[id]/sync`를 2초마다 조회한다. 탭이 다시 보이면
  즉시 한 번 갱신하며 숨겨진 탭에서는 요청하지 않는다.
- 사진 URL·기본정보는 반복 전송하지 않고 최종 선택, 찜, 참가자별 별점·의견, 닉네임·완료 상태,
  현재 선택 상태만 내려준다. 호환 필드는 기존 응답 형태 유지를 위해 포함할 수 있다.
- 로컬 저장 요청이 진행 중이면 동기화 결과 적용을 미뤄 사용자가 방금 바꾼 값을 덮어쓰지 않는다.
- 두 번 연속 실패하면 연결 경고를 표시하고 자동 재시도한다. 최종 검토는 최신 상태가 연결된
  동안만 진행할 수 있다. 결과 링크 복사는 프로젝트 상태와 협업 쓰기를 변경하지 않는다.
- 온라인 표시와 현재 사진 공유는 기존 presence API, 일회성 대화는 Supabase Realtime Broadcast를
  사용한다. 연속 화면 따라가기는 후속 검토로 보류한다.

### 7.2 접속 상태

- 선택 화면이 보이는 동안 참여자 색 단위로 10초마다 heartbeat를 저장한다. 숨겨진 탭은 갱신하지
  않고 다시 보이면 즉시 갱신한다.
- 최근 30초 안에 heartbeat가 있는 참여자는 PC·모바일 참여자 칩에 `온라인`으로 표시한다.
- 현재 단계는 누가 접속 중인지에만 집중해 여러 탭·기기를 개별 세션으로 구분하지 않는다.
  화면 따라가기에서 세션 구분이 필요해질 때 별도 세션 ID를 추가한다.

### 7.3 현재 사진 공유

- 상세보기를 열거나 사진을 넘기면 참여자 presence에 현재 사진을 저장하고, 닫으면 갤러리 상태로
  되돌린다. 같은 색으로 여러 기기가 접속하면 마지막 화면 조작이 기준이다.
- 온라인 참여자가 상세 사진을 보고 있으면 참여자 칩에 파일명과 `보는 중`을 표시한다. 칩을
  누르면 상대 화면을 바꾸지 않고 내 상세보기만 같은 사진으로 한 번 이동한다.
- 현재 단계는 연속 따라가기가 아니다. 상대가 이후 다른 사진으로 이동해도 내 화면은 자동으로
  움직이지 않는다. 연속 따라가기는 고빈도 양방향 연결과 명시적인 시작·종료 UX를 함께 구현한다.

### 7.4 일회성 대화

- **2026-10-02부터 숨김**: 고르기 화면 `CHAT_ENABLED = false`로 대화 버튼·패널을 모두 감췄다(코드·Realtime 채널은 그대로, 값만 바꾸면 다시 켜짐). 아래는 켰을 때의 동작이다.
- 참여자가 두 명 이상이면 갤러리와 사진 상세보기에 `대화` 버튼을 표시한다.
- 지금 온라인인 다른 참여자가 있을 때만 120자 이하 메시지를 보낼 수 있다. 메시지는 Realtime
  Broadcast로 현재 접속자에게만 전달되고 각 화면에서 8초 뒤 사라진다.
- 대화 기록은 DB·서버·브라우저 저장소에 남기지 않으며 늦게 접속한 참여자, 전달 결과,
  CSV/TXT에는 포함하지 않는다.
- 공유 토큰의 SHA-256 해시를 채널 키로 사용해 프로젝트 ID만으로 채널에 들어올 수 없게 한다.

테스트 기간에는 셀렉을 시작한 뒤에도 사진을 추가 업로드할 수 있다. 운영 전 정책은 다음이
기본안이다.

- 셀렉 진행 중 추가 업로드 허용
- 선택 기록이 있는 사진 삭제 시 영향 범위를 명시한 강한 확인

## AI 정리 개요와 조정 지점 (2026-10-02 기준)

셀프 고객의 "AI 정리"가 무엇을 어떻게 판단하는지, 값을 바꾸려면 어디를 고치는지 한곳에 모은다. 값은 실제 촬영(돌잔치 528장)으로 확인하며 정했고, 앞으로 장면 검수(아래)로 계속 조정한다.

### 흐름

1. **업로드(FE)**: 압축 전에 원본 EXIF 촬영 시각(`DateTimeOriginal` → `DateTime` → 파일 수정 시각)을 읽어 `customer_photos.taken_at`에, 출처(`exif`/`file`)를 `taken_at_source`에 저장한다(`src/lib/exif-taken-at.ts`, `docs/upload-flow.md`). 파일 수정 시각은 장면 경계에 쓰지 않는다. 작가 쪽 사진에는 촬영 시각이 없다(보류 과제).
2. **AI 정리 시작**: `scene` 실행이 장면을, `similarity` 실행이 유사컷을, `quality` 실행이 흔들림·눈 감음·인물 구성을 각각 따로 판정한다(clip-service `customer_ai.py`, 끈 항목은 실행 안 함). 장면 실행에는 FE가 촬영 종류의 장면 이름 목록을 함께 보낸다.
3. **유사컷**: Gemini 임베딩(이미 계산한 사진은 재사용) → 촬영 순서로 늘어놓고 이웃끼리 유사도로 묶는다.
4. **장면**: 촬영 시각 공백으로 나눔 → 장면마다 대표 3장(흔들림·유사컷 중복 제외)을 Gemini Flash에 보여 이름 목록 중 하나와 확신 여부를 고르게 함(확신 없으면 `기타 장면`) → 바로 이어지고 공백 10분 미만인 같은 이름은 합침.
5. **품질·인물**: 사진마다 Gemini Flash 1회. 흔들림·초점·눈 감음·얼굴 가림·주 피사체 + 셀프 고객 전용 인물 구성(`people`).
6. **화면 해석(FE)**: 판정 값을 어떻게 보여줄지는 FE가 정한다(아래 표의 "화면 해석").

지인 베타의 실제 촬영으로 장면 분석을 다듬기 위해, 운영자가 셀프 고객 프로젝트의 AI 장면을 보고 정답을 남긴다(`/admin/scenes`, 관리자 이메일만). 참여자 동의는 오프라인으로 받는다.

- 목록: 사진이 있는 셀프 고객 프로젝트별 촬영 종류·사진 수·AI 장면 수·검수 여부·점수, 촬영 종류별 평균 점수.
- 검수 화면: 사진 전체를 촬영 시간순 썸네일로, 장면별 색 띠·이름·시간대·AI 이름(가장 많은 것)과 함께 보인다. 사진을 누르면 그 사진부터 새 장면, `앞 장면과 합치기`, 이름은 촬영 종류의 이름 목록에서 고르거나 직접 입력. AI가 장면을 나눈 자리는 주황 왼쪽 선. 편집하는 동안 지금 정답 기준 AI 점수를 바로 보여준다.
- 저장(`POST /api/admin/scene-labels`): `customer_scene_labels`(마이그레이션 `20261002000000_add_customer_scene_labels.sql`, 2026-10-02 운영 DB 적용)에 프로젝트당 한 건(덮어쓰기) — 정답 장면(이름·사진 ID 목록), 그때의 AI 장면, AI 설정(그 장면을 만든 최근 완료 `scene` 실행의 `customer_ai_runs.settings` — 규칙 버전·기준값 전부·이름 목록·이름 모델·프롬프트 버전. 장면 실행 분리 전 장면이면 `LEGACY_AI_SETTINGS`(`gap-v1`)), 메모, 검수자. 프로젝트 사진 전체를 빠짐없이·겹치지 않게 나눈 것만 받는다(사진이 바뀌었으면 409). **서비스 화면의 장면(`customer_scenes`)은 바꾸지 않는다.**
- 점수(`src/lib/scene-label-score.ts`): 경계 정밀도(AI 경계 중 정답 ±3장 안), 재현율(정답 경계 중 AI가 찾은 비율), 이름 정확도(사진마다 AI 장면 이름 = 정답 이름). 기준값·이름 목록·프롬프트를 바꾼 뒤 다시 정리하고 같은 프로젝트를 검수하면 비교할 수 있다.
