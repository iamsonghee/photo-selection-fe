# 셀프 고객 서비스 — 제품·구현 기준

> 고객이 A-CUT을 사용하는 작가 없이 직접 촬영본을 업로드하고, 함께 사진을 고른 뒤 외부
> 작가에게 파일명과 보정 요청을 전달하는 서비스다. 경로는 `/customer-select/**`이며 문서와
> 대화에서는 반드시 **셀프 고객 서비스**라고 부른다. 기존 `/c/[token]/**`는 **작가 고객 페이지**다.

## 1. 이 문서의 역할

이 문서는 제품 결정과 현재 구현을 함께 기록한다. **합의된 정책은 구현 완료를 뜻하지 않는다.**
현재 동작은 코드로 확인하고, 제품 방향은 사용자와 합의한 목적·정책을 기준으로 결정한다.
초기 목업이나 기존 화면의 단계·정보량을 정답으로 취급하지 않는다. 제품 설계 우선순위는 다음과 같다.

1. 일반 고객의 목적과 사용자와 합의한 정책
2. 목적을 끝까지 달성할 수 있는 사용자 흐름
3. 기존 ACUT 디자인 시스템과 같은 목적의 공통 컴포넌트
4. 실제 구현·인증·데이터 구조와의 차이
5. 초기 목업·스크래치 문서

목업은 사용자 흐름과 필요한 정보의 참고 자료일 뿐, 레이아웃·카드·모달·헤더·푸터를 새로
만드는 근거가 아니다. 같은 목적의 ACUT 화면이 있으면 그 화면과 컴포넌트를 먼저 재사용하고,
API 계약이나 권한 모델이 달라 재사용할 수 없는 부분만 셀프 고객용으로 분리한다.

## 2. 제품 정의

셀프 고객 서비스의 사용자는 사진을 맡긴 고객이면서 프로젝트 소유자다. 고객은 촬영본을 직접
보유하고 있으므로 A-CUT은 셀렉과 의사소통에 필요한 썸네일·프리뷰만 관리한다.

### 2.1 확정된 출시 정책 (2026-09-22)

1. 로그인하고 프로젝트를 만든다.
2. 한 계정의 모든 프로젝트를 합해 최대 2,000장의 셀렉용 사진을 저장한다. 사진이나 프로젝트를
   삭제하면 삭제한 사진만큼 업로드 한도가 복구된다.
3. 소유자는 직접 고르고, 공유 참가자는 개인 찜·의견을 남긴다. 최종 선택은 소유자가 결정한다.
   함께 고르는 인원은 소유자를 포함해 색상 슬롯 수와 같은 최대 5명이다.
4. 목표 장수는 참고용이다. 목표 미달·초과를 이유로 확정·전달을 막지 않는다.
5. 소유자가 최종 결과를 확정하고 파일명·요청사항을 외부 작가에게 전달하면 기본 흐름은 완료된다.
6. 최종 전달 결과는 하나만 유지한다. `다시 선택하기`로 완료 상태를 해제하고 수정한 뒤 재전달하면
   최신 결과로 교체하며, 전달 횟수와 최근 전달 시각만 기록한다.
7. 보정본 검토는 기본 흐름 완료 후 선택적으로 연결하는 후속 기능이다.

프로젝트 생성 시 촬영 종류는 필수이며, 촬영일·스튜디오/업체·담당 작가·촬영 지역·장소는
선택 입력으로 시작한다. `target_count`는 일반적인 참고 목표가 아니라 외부 작가와 약속한
보정 장수이며, 실제 선택 장수가 달라도 전달을 막지 않는다. 입력 원문은 향후 통계·사업 분석의
기초 데이터로 보존하고 업체/장소 표준화는 별도 정책이 정해질 때 추가한다.

기존 공통 찜·의견 갈림 필터는 유지한다. 추가 후보 정리 기능은 마지막 위치 이어보기만 첫 출시
범위로 두고, 별도 고민 중 상태와 두 장 비교는 구현하지 않는다. 임시 대화와 가입 없이 보는
작가용 읽기 전용 결과 링크는 첫 출시 범위로 둔다.
한 번 눌러 같은 사진을 여는 기능은 구현됐으며, 화면을 계속 따라가는 기능은 실제 사용 필요를
확인할 때까지 후속으로 보류한다.

정확한 요금·상품 구성은 미정이다. 현행 상한은 BE `MAX_PHOTOS_PER_CUSTOMER_ACCOUNT = 2000`이며,
업로드 한도와 선택 목표는 별개로 안내한다. 신규 흐름의 작업 순서·검토안은
[출시 작업 계획](customer-select-release-plan.md)을 따른다.

### 2.2 현재 구현과의 차이

- 현재 전달은 텍스트 복사, CSV(파일명·참여자 의견), TXT(파일명 목록) 다운로드와
  완료·다시 선택 상태를 지원한다.
- 현재 참여자 식별은 색 슬롯에 연결되어 있다. 선택 상태 동기화에는 그대로 사용하되, 접속 상태·
  따라가기처럼 한 참여자의 여러 세션을 구분해야 하는 기능 전에 세션 식별자를 추가한다.

### 명시적 비범위

- 납품용 원본 업로드·원본 아카이브·원본 복구
- 작가 계정, 작가 등급, 작가별 업로드 쿼터
- 작가 추천 사진과 작가 초대 생애주기
- 기존 `projects`/`photos` 상태 머신에 셀프 고객 프로젝트를 편입하는 것

셀프 고객의 사진은 언제나 **셀렉용 사진**이다. UI·API·문서에서 이를 작가 화면의 “납품용
원본”과 혼용하지 않는다.

## 3. 화면 설계 원칙

### 3.1 디자인은 공유하고 흐름은 일반 고객에 맞춘다

기존 컴포넌트 재사용은 시각·조작의 일관성을 위한 것이다. 작가용 폼의 항목 수나 페이지 순서를
그대로 복제할 의무는 없다. 한 화면의 주요 행동을 명확히 하고, 고급 기능·선택 입력은 점진적으로
노출한다. 큰 화면 변경은 간단한 와이어프레임 검토 후 구현한다.

- 로그인·프로젝트 목록·프로젝트 생성: Photographer Light의 셸, 폼, 버튼, 액션바를 따른다.
- 사진 업로드·관리: 작가 원본 업로드의 작업면, 가상화 갤러리, 선택·삭제, 정렬, 뷰어,
  헤더 축소, 하단 고정 액션바를 따른다.
- 사진 셀렉: 작가 고객 페이지의 셀렉 갤러리 카드, 필터, 상세 뷰어, 확정 풋터를 따른다.
- 보정본 검토: 작가 고객 페이지의 보정본 검토 카드·상세 비교·판정 UI를 따른다.
- 확인 모달·버튼·배지·빈 화면은 기존 공통 컴포넌트를 사용한다.

셀프 고객 전용 컴포넌트는 인증 문구, 참가자 상태, 외부 작가 전달 등 도메인 차이가 있는 경우에만
허용한다. 기존 컴포넌트를 복사해 이름만 바꾸지 않는다.

### 3.2 대량 사진 작업면

- 계정의 모든 셀프 고객 프로젝트 합산 상한은 **2,000장**이다.
- PC에서는 사진 작업면이 가용 폭을 사용하며 모바일 폭 카드로 제한하지 않는다.
- 상단 헤더·도구와 하단 주요 행동은 고정하고 갤러리만 독립 스크롤한다.
- 갤러리는 가상화하고, 화면 근처 이미지만 제한된 동시성으로 로드한다.
- 업로드는 20장씩 `압축 → 전송`해 전체 압축 결과를 메모리에 쌓지 않는다.
- 파일명은 검색·정렬 또는 상세 식별에 필요한 곳에서만 표시한다.
- 업로드 전에 현재 장수 기준 남은 한도를 확인하고, 실패·제외된 파일은 이름을 보존해 해당
  파일만 다시 시도할 수 있게 한다.

다시 만들지 않는다.

## 4. 화면별 목표와 현재 상태

`구현됨`은 기능이 존재한다는 뜻이며, `정렬 필요`는 초기 목업 기반 UI가 남아 공통 화면으로
교체해야 한다는 뜻이다.

| 화면 | 경로 | 기준 화면 | 현재 상태 |
|---|---|---|---|
| 로그인 | `/customer-select/login` | Photographer Light 인증 | 구현됨 |
| 프로젝트 목록 | `/customer-select` | 작가 대시보드/목록 | 구현됨. 헤더 계정 메뉴에 소셜 프로필 이름·이미지, 이메일, 로그인 제공자, 전체 사진 이용량과 로그아웃을 표시하며 별도 고객 프로필 테이블은 사용하지 않음. 새 프로젝트는 목록에서만 우측 하단 `+` 플로팅 버튼으로 제공하고 빈 화면에서는 중앙 시작 버튼을 사용. 계정 전체 `현재 / 2,000장`과 잔여량을 상단 공통 영역에 한 번 표시. 업로드 전 ACUT 마크, 업로드 후 첫 사진의 프리뷰(없으면 썸네일)를 카드 대표 이미지로 사용. 각 카드는 해당 프로젝트 사진 수·선택 수·보정 목표와 실제 진행 상태에 맞는 다음 행동만 표시하며, 8개 이상이면 이름·업체·작가 검색과 상태 필터를 제공. 설정은 현황 화면에서 진입 |

| 사진 업로드·관리 | `/customer-select/[projectId]/upload` | 작가 원본 업로드 | 공통 갤러리·뷰어·액션바 적용됨 |

| 보정본 비교 | `/customer-select/[projectId]/retouch/compare` | 고객 보정본 상세 검토 | 공통 셸·집중 뷰어 적용됨. 원본 비교, 판정 저장 실패 재시도, 미도착 보정본 완료 차단 지원 |
| 재보정 전달 | `/customer-select/[projectId]/retouch/export` | 고객 재보정 결과 | 공통 셸·하단 액션바와 복사·CSV/TXT 실제 다운로드 적용됨 |
| 완료 | `/customer-select/[projectId]/done` | 고객 완료 화면 | 공통 셸·하단 액션바 적용됨. 완료 저장 실패를 표시하고 재시도 가능 |
| 프로젝트 설정·삭제 | `/customer-select/[projectId]/settings` | 작가 프로젝트 설정 | 목록 카드 설정 버튼에서 진입. 기본정보·목표 수정을 지원하고, 소유자만 DB 파생 데이터와 R2 이미지를 함께 삭제 가능 |
| 공유 링크 관리 | `/customer-select/[projectId]/settings#sharing` | 작가 고객 링크 관리 | 소유자 전용. 링크 복사·즉시 중지·재발급을 지원하며 중지/재발급 시 기존 링크와 참여자 쿠키를 거부한다. 기존 셀렉·의견 기록은 보존한다. |

### 작업 순서

시작·업로드·현황 → 참여자와 선택 권한 → 확정·전달 → 실시간 협업 → 후보 비교·의견 정리.
각 묶음을 PC·모바일에서 검증하고 사용자 검토 후 다음 묶음으로 진행한다.
보정본 검토는 후속 선택 기능으로 분리한다. 상세 완료 기준은 출시 작업 계획에 기록한다.

## 5. 데이터 모델

작가 프로젝트와 소유권·인증·보관 정책이 다르므로 데이터는 분리한다.

- `customer_projects`: 소유자, 프로젝트 정보, 목표 장수, 사진 수, 공유 토큰, 전달·보정 완료 플래그
- `customer_projects.sharing_enabled`: 현재 공유 토큰의 활성 여부. 중지하면 기존 쿠키도 거부
- `customer_projects.lifetime_uploaded_count`: 삭제와 무관한 프로젝트 누적 성공 업로드 장수. 계정별
  합계는 현재 저장 한도와 별개로 유료 정책·반복 사용 분석에만 사용
- `customer_projects.delivery_count`, `last_delivered_at`: 전달 완료 누적 횟수와 최근 전달 시각.
  과거 전달본 자체는 보존하지 않는다.
- `customer_projects` 촬영 분석 필드: `shoot_type`(필수 입력), `shoot_date`, `studio_name`,
  `photographer_name`, `shoot_region`, `shoot_location`(선택 입력)
- `customer_photos`: 셀렉용 썸네일·프리뷰, 원본 파일명, 표시 순서, 유사컷 그룹
- `customer_selections`: 소유자 최종 선택과 참가자별 찜 색상
- `customer_participant_opinions`: 사진별 참가자 개인 별점·공개 의견
- `customer_project_participants`: 비로그인 참가자의 색 슬롯·닉네임·완료 여부
- `customer_participant_presence`: 참여자별 최근 heartbeat 시각. 30초 이내 갱신된 참여자를
  온라인으로 표시하며 프로젝트·참여자 삭제 시 함께 정리
- `customer_photo_versions`: 사진별 보정본 회차와 확정·재보정 결정
- `customer_ai_runs`, `customer_ai_embeddings`, `customer_photo_groups`,
  `customer_quality_assessments`: 셀프 고객 사진의 유사컷·품질 분석

모든 테이블은 RLS를 켜고 브라우저에서 직접 쓰지 않는다. Next.js API 또는 BE가 service role로
처리한다. 참가자별 찜 변경은 `toggle_customer_selection_color` RPC로 원자 처리한다.

## 6. 인증·권한

- 소유자는 Supabase Auth의 Google/Kakao 로그인을 사용한다.
- 대시보드 계정 표시는 Supabase Auth의 `user_metadata` 이름·프로필 이미지와 이메일·provider를
  읽어 사용한다. 현재는 셀프 고객 전용 프로필 테이블이나 추가 개인정보를 만들지 않는다.
- 참가자는 계정 없이 공유 링크로 접근한다. `share_token`은 최초 진입 요청에서만 사용하고,
  미들웨어가 프로젝트와 토큰을 검증한 뒤 프로젝트별 `HttpOnly`, `SameSite=Lax` 쿠키로 교환한다.
- 토큰 교환 직후 같은 화면의 `share_token` 없는 URL로 리다이렉트하며, 이후 화면 이동과 API
  요청에는 토큰을 쿼리나 요청 본문으로 전달하지 않는다.
- 공유 링크 복사와 원문 토큰 조회는 프로젝트 소유자에게만 제공한다.
- 공유 중지는 현재 토큰을 비활성화하고, 재발급은 새 토큰으로 교체한다. 두 작업 모두 기존 링크와
  발급된 참여자 쿠키를 즉시 무효화하지만 참가자의 찜·별점·의견 기록은 삭제하지 않는다.
- 참가자 색 슬롯은 브라우저의 `acut:customer-select:identity:{projectId}`에 저장한다.
- 최초 참가자는 닉네임과 아직 사용하지 않은 색을 직접 고른다. 색 선점은 DB의
  `(project_id, color)` 고유 키로 동시에 요청해도 한 명만 성공하며, 5개가 모두 사용 중이면 입장을 막는다.
- 새 기기에서는 초대 화면의 `이어서 참여하기`에서 기존 닉네임·색을 선택해 같은 참여자로
  복원한다. 별도 인증번호 없이 공유 링크를 가진 가까운 참여자끼리 사용한다는 현재 인증 강도를 따른다.
- Next.js API는 소유자 세션 또는 프로젝트별 공유 쿠키의 유효한 토큰을 검사한다.
- 공유 참가자는 본인 색 슬롯의 찜·별점·의견·완료 상태만 UI에서 변경한다. 의견은 같은 프로젝트
  참여자에게 공개된다. 최종 선택·최종 검토·전달 상태 변경은 소유자만 가능하다.
- 사진 업로드·삭제·보정본 관리는 소유자 JWT만 허용한다. 공유 토큰은 셀렉 협업 권한으로만 사용한다.
- 작가용 결과 링크는 협업 토큰과 분리된 HMAC 서명 토큰을 최초 접속에서만 사용한다. 검증 뒤
  프로젝트별 HttpOnly 쿠키로 교환하고 토큰 없는 결과 URL로 이동한다. 결과 권한은 읽기 전용이며
  `exported=true`인 최신 결과에만 유효하다.
- 협업 상태 동기화도 소유자 세션 또는 공유 쿠키를 검사하는 전용 API를 통한다. 브라우저에
  service role이나 공개 DB 읽기 권한을 주지 않는다.

공유 토큰은 참여 링크이지 강한 본인 인증 수단이 아니다. 유출이 의심되면 설정에서 공유를
중지하거나 링크를 재발급한다.

## 7. 업로드·삭제·AI

- 셀렉용 이미지는 브라우저에서 1600px/0.82 JPEG 수준으로 축소한 뒤 20장 단위로 전송한다.
- BE는 썸네일과 프리뷰만 R2에 저장하고 `customer_photos`를 만든다.
- 파일 드롭, 개별 체크, 빈 영역 드래그 선택, `Cmd/Ctrl+A`, `Delete/Backspace`, `Esc`를 지원한다.
- 모바일은 항상 보이는 체크박스로 사진을 선택·삭제한다. PC·모바일 모두 파일명 검색을 제공하고,
  기본 격자에서는 파일명을 숨겨 사진 밀도를 확보한다.
- FE는 계정 전체 2,000장 상한을 업로드 전에 확인한다. 전송은 20장(`BATCH_SIZE=20`)씩 처리하며 중단 시
  현재 배치 이후 파일, 서버가 거절한 파일은 다시 시도 목록으로 유지한다. 같은 파일을 다시
  선택할 수 있도록 파일 입력값은 선택 직후 초기화한다.
- 첫 배치 완료 후 최근 3개 배치의 `압축+전송` 시간과 장수를 가중 평균해 예상 남은 시간을
  계산한다. 첫 배치 전에는 `예상 시간 계산 중`, 이후에는 분 단위의 완화된 시간을 표시한다.
- FE는 파일 선택·드롭·재시도 직전에 계정 전체 사진 수를 갱신한다. 선택 파일 전체가 남은 한도를
  초과하면 전송하지 않고 선택/가능 장수와 `파일 다시 선택`을 표시한다.
- BE `POST /api/customer-upload/photos`도 요청 파일 수가 남은 한도를 초과하면 요청 전체를
  `limit_exceeded`로 거절한다. 일부 파일을 자동으로 잘라 업로드하지 않는다.
  DB 트리거는 같은 소유자의 동시 업로드를 직렬화하고 실제 사진 행 합계가 2,000장을 넘는 배치를
  롤백해 여러 프로젝트에서 동시에 올려도 한도를 넘지 않게 한다.
  형식 오류와 이미지 처리 실패 파일은 `rejected` 파일명 배열에 포함한다. FE는 `uploaded`와 `rejected`를 함께
  확인하며 실패가 있으면 AI 제안보다 재시도를 먼저 표시한다.
- 삭제 전 최종 선택·찜·별점·의견·AI 분석·보정본의 연쇄 삭제 건수를 확인창에 표시한다.
  확정하면 사진 행의 cascade 데이터와 썸네일·프리뷰·보정본 R2 객체를 정리한다.
- 한 번이라도 전달한 프로젝트(`delivery_count > 0`)는 다시 선택 중이어도 사진 추가·삭제를
  잠근다. 프로젝트 자체 삭제와 선택 기능인 보정본 업로드는 이 잠금 대상이 아니다.
- 성공 업로드 장수는 현재 보유 사진 수와 별도로 누적한다. 삭제 후 재업로드해도 누적값은
  줄지 않지만, 실제 유료화 전에는 프로젝트 삭제·재생성을 포함하는 계정 단위 사용량 원장이 필요하다.
- 업로드 완료 후 `AiAnalysisPromptModal`에서 유사컷 또는 눈 감음·흐림 분석을 선택한다.
- 완료 모달을 닫은 뒤에도 업로드 헤더의 `AI 분석` 버튼으로 다시 열 수 있다.
- AI 모델 호출과 그룹핑 알고리즘은 clip-service의 기존 구현을 재사용하지만 결과 테이블은 작가
  프로젝트와 분리한다.

### 7.1 공동 선택 동기화

- 활성 화면은 `/api/customer-select/projects/[id]/sync`를 2초마다 조회한다. 탭이 다시 보이면
  즉시 한 번 갱신하며 숨겨진 탭에서는 요청하지 않는다.
- 사진 URL·기본정보는 반복 전송하지 않고 최종 선택, 찜, 참가자별 별점·의견, 닉네임·완료 상태,
  전달 상태만 내려준다.
- 로컬 저장 요청이 진행 중이면 동기화 결과 적용을 미뤄 사용자가 방금 바꾼 값을 덮어쓰지 않는다.
- 두 번 연속 실패하면 연결 경고를 표시하고 자동 재시도한다. 최종 검토·전달은 최신 상태가
  연결된 동안만 진행할 수 있다.
- `작가에게 전달했어요`를 누르면 정기 주기를 기다리지 않고 즉시 다시 동기화한다. 미완료
  참여자가 있으면 최신 명단으로 재확인하며, 확인창에서 확정할 때도 다시 조회한 뒤 전달한다.
- 전달 완료 상태에서는 최종 선택뿐 아니라 참가자의 찜·별점·의견·완료 상태 변경과 새 참여도
  잠근다. 소유자가 `다시 선택하기`를 눌러 전달 완료를 해제한 뒤에만 협업 쓰기가 다시 열린다.
- 온라인 표시와 현재 사진 공유는 기존 presence API, 일회성 대화는 Supabase Realtime Broadcast를
  사용한다. 연속 화면 따라가기는 후속 검토로 보류한다.

### 7.2 접속 상태

- 선택 화면이 보이는 동안 참여자 색 단위로 10초마다 heartbeat를 저장한다. 숨겨진 탭은 갱신하지
  않고 다시 보이면 즉시 갱신한다.
- 최근 30초 안에 heartbeat가 있는 참여자는 PC·모바일 참여자 칩에 `온라인`으로 표시한다.
- 현재 단계는 누가 접속 중인지에만 집중해 여러 탭·기기를 개별 세션으로 구분하지 않는다.
  화면 따라가기에서 세션 구분이 필요해질 때 별도 세션 ID를 추가한다.

### 7.3 현재 사진 공유

- 상세보기를 열거나 사진을 넘기면 참여자 presence에 현재 사진을 저장하고, 닫으면 갤러리 상태로
  되돌린다. 같은 색으로 여러 기기가 접속하면 마지막 화면 조작이 기준이다.
- 온라인 참여자가 상세 사진을 보고 있으면 참여자 칩에 파일명과 `보는 중`을 표시한다. 칩을
  누르면 상대 화면을 바꾸지 않고 내 상세보기만 같은 사진으로 한 번 이동한다.
- 현재 단계는 연속 따라가기가 아니다. 상대가 이후 다른 사진으로 이동해도 내 화면은 자동으로
  움직이지 않는다. 연속 따라가기는 고빈도 양방향 연결과 명시적인 시작·종료 UX를 함께 구현한다.

### 7.4 일회성 대화

- 참여자가 두 명 이상이면 갤러리와 사진 상세보기에 `대화` 버튼을 표시한다.
- 지금 온라인인 다른 참여자가 있을 때만 120자 이하 메시지를 보낼 수 있다. 메시지는 Realtime
  Broadcast로 현재 접속자에게만 전달되고 각 화면에서 8초 뒤 사라진다.
- 대화 기록은 DB·서버·브라우저 저장소에 남기지 않으며 늦게 접속한 참여자, 전달 결과,
  CSV/TXT에는 포함하지 않는다.
- 공유 토큰의 SHA-256 해시를 채널 키로 사용해 프로젝트 ID만으로 채널에 들어올 수 없게 한다.

테스트 기간에는 셀렉을 시작한 뒤에도 사진을 추가 업로드할 수 있다. 운영 전 정책은 다음이
기본안이다.

- 셀렉 진행 중 추가 업로드 허용
- 선택 기록이 있는 사진 삭제 시 영향 범위를 명시한 강한 확인
- 전달 완료 후 업로드·삭제 잠금

## 8. 프로젝트 상태

현재 별도 status 컬럼 없이 플래그와 사진 수로 목록의 다음 위치를 계산한다.

| 조건 | 표시 상태 | 기본 이동 |
|---|---|---|
| `photo_count = 0` | 사진 업로드 전 | 업로드 |
| `photo_count > 0`, `exported = false`, `delivery_count = 0` | 셀렉 진행 | 셀렉 갤러리 |
| `exported = false`, `delivery_count > 0` | 재선택 중 | 셀렉 갤러리 |
| `exported = true`, `retouch_done = false` | 전달 완료 | 현재 전달 내용 |
| `retouch_done = true` | 완료 | 완료 화면 |

이 구조는 간단하지만 검토 중·재보정 요청 중 같은 세부 상태를 표현하지 못한다. 실제 목록 UX에서
구분이 필요해질 때만 명시적 status 도입을 검토한다.
